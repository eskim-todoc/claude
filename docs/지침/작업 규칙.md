# 작업 규칙 체크리스트

**TL;DR**: 존댓말 사용, 문서는 GFM(.md), **모든 작업은 4단계(요구사항→분석→계획→구현) + 산출물·자체검토·이력 의무**, 코드는 단계 ④ 진입 전 사용자 승인, `claude_` 브랜치 + `--no-ff`, 작업 스코프(루트/프로젝트)별 repo 분리, **서브에이전트 적극 활용 (병렬·효율)**, AI 표시 금지.

> [!IMPORTANT]
> 모든 작업을 시작하기 전에 아래 규칙을 확인할 것.

---

## 1. 커뮤니케이션

- [ ] 사용자 대상 메시지는 **존댓말**로 작성 (반말 금지)
- [ ] 사용자 명령에 **조금이라도 모호함**이 있으면 작업 착수 전 무조건 질문 (이분→yes/no, 다항→선택지)

> [!NOTE]
> 상세: [`일반/커뮤니케이션 규칙.md`](일반/커뮤니케이션%20규칙.md) · [`일반/명령 해석 규칙.md`](일반/명령%20해석%20규칙.md)

---

## 2. 문서 작성

- [ ] 문서는 사용자가 다른 포멧을 명시하지 않는 한 **GFM Markdown(`.md`)** 으로 작성
- [ ] 문서는 유형별 폴더(`지침/`, `사용방법/`, `tasks/` 등) 아래 배치 (상세: [`일반/문서 작성 규칙.md`](일반/문서%20작성%20규칙.md))
- [ ] 다이어그램은 **Mermaid**로 작성 (ASCII art 지양)
- [ ] 강조·경고는 **GitHub Alert 블록** (`> [!NOTE]`, `> [!WARNING]` 등) 활용
- [ ] 항목 식별자는 **알파벳 약어(`Q1`/`H1`/`R1`/`P1`) 금지** — 의미 한글 라벨 + `_번호` (`질문_1`/`가설_1`/`위험_1`/`요구사항_1`)
- [ ] '~하고 정리해' 요청 시, 작업 위치의 `docs/`에 `.md`로 정리

> [!NOTE]
> 상세: [`일반/문서 작성 규칙.md`](일반/문서%20작성%20규칙.md)

---

## 3. 작업 진행 — 4단계 프로세스 (모든 작업)

- [ ] 작업 지시 수신 시 `tasks/list.md` 조회 → 기존 폴더 이어가기 또는 신규 생성 (사용자 확인)
- [ ] 4단계 산출물 작성: **① `요구사항.md` → ② `분석.md` → ③ `계획.md` → ④ 구현·처리**
- [ ] 각 단계 산출 직후 **자체 검토 2축** 수행: ① 지침 준수, ② 논리적 정합성
- [ ] `진행상황.md`를 단계 ① 시작과 동시에 생성하고 단계 전이·결정·이슈마다 갱신
- [ ] 단계 ③ 완료 후 단계 ④ 진입 전 **사용자 승인** 필수
- [ ] 작업 종료 시 `이력.md` 작성 + `_archive/` 이동 + `list.md` 갱신
- [ ] 단순 수정(오타·설정값·자명한 한 줄)은 4단계 면제
- [ ] **서브에이전트로 병렬·효율 가능한 부분은 적극 활용** (광범위 탐색·다중 가설·독립 작업 동시 실행)
- [ ] 신규 프로젝트 폴더 트리거(예: "기본 세팅 해줘") 수신 시 [`일반/프로젝트 초기 세팅.md`](일반/프로젝트%20초기%20세팅.md) 정형 절차 적용 (4단계 면제)

> [!NOTE]
> 상세: [`일반/작업 진행 규칙.md`](일반/작업%20진행%20규칙.md) · [`일반/서브에이전트 활용.md`](일반/서브에이전트%20활용.md) · [`일반/프로젝트 초기 세팅.md`](일반/프로젝트%20초기%20세팅.md)

## 4. 프로그래밍 작업 (단계 ④ 코드 작성 시 추가)

- [ ] 일반 작업 진행 규칙(§3)을 따른다 — 코드 작성은 단계 ④. 단계 ①~③ 산출물·승인 없이 코드 작성 금지
- [ ] 신규 심볼·모듈 분리 시 **`tdc_` 접두어 무조건 적용**, 기존 파일 리팩토링 시에도 손댄 심볼은 적용 우선
- [ ] 필요 시 `시험방법/`, `사용방법/` 폴더에 영속 문서 추가 작성

> [!NOTE]
> 상세: [`코딩/작업 규칙.md`](코딩/작업%20규칙.md) · [`코딩/네이밍 컨벤션.md`](코딩/네이밍%20컨벤션.md)

## 5. 코드 분석·디버깅 (회귀 fix 시 필수)

- [ ] 함수 호출 경로 / 변수 사용처는 **추정 금지** — 반드시 `Grep` 으로 전수 확인
- [ ] root cause 가설은 **최소 3 개 수립 후 cross-check** (1 개로 만족 금지)
- [ ] **사용자가 직접 수정한 변경 (system-reminder)** 은 그 자체가 단서 — 의도 깊이 분석
- [ ] IRQ / 전원 / 클럭 / GPIO 등 **시스템 상태 변화 시점** 을 명시 추적
- [ ] fix 적용 전 self-check Q1~Q5 답변 (root cause 인가, 다른 가설 배제됐나, 회귀 위험은, 부작용은, 진단 요청이 우선 아닌가)
- [ ] 사용자가 "철저히" / "확실히" 표현 쓰면 검증 단계 강화

> [!NOTE]
> 상세: [`코딩/분석·디버깅 규칙.md`](코딩/분석·디버깅%20규칙.md) — 실제 회귀 사례 (Sound1 LED 잔상색 2026-04-23) 포함

## 6. Git

- [ ] 작업이 속한 **스코프(루트/프로젝트)의 repo**에 커밋 — 작업이 일어난 디렉토리가 아닌 **변경 파일 경로 기준**
- [ ] `claude_` 접두사 브랜치에서만 작업 (`main` 직접 커밋 금지)
- [ ] 파일 수정 전 feature 브랜치 생성 후 체크아웃
- [ ] 모든 병합은 `--no-ff`로 수행
- [ ] 커밋 완료 후, 병합 전 **사용자 확인** 필수
- [ ] Author / Committer: `김은수 <eunsu.kim@to-doc.com>` — AI 표시 절대 금지
- [ ] 커밋 메시지에 `Co-Authored-By` 등 AI 관련 라인 금지
- [ ] 머지·푸시 완료 후 `claude_develop` 복귀 — 모든 repo (루트 + 프로젝트) 동일, `claude_main` 체류 금지

> [!CAUTION]
> `main` 직접 커밋·푸시는 **절대 금지.** 릴리즈는 사용자 고유 권한.

> [!NOTE]
> 상세: [`Git/브랜치, 병합 규칙.md`](Git/브랜치,%20병합%20규칙.md) · [`Git/워크플로우.md`](Git/워크플로우.md)

## 7. 응답·컨텍스트 효율

- [ ] 파일 내용·툴 출력을 응답에 그대로 인용 금지 (Edit diff·1줄 요약)
- [ ] 인사·사전 설명("이제 ~하겠습니다")·사후 부연 금지 → 결과만
- [ ] 작업 종료 보고는 `변경/검증/다음` 3줄 (회고 명사구 한 줄 요약은 그 다음에 추가)
- [ ] `Read`는 `offset`/`limit` 활용 (큰 파일 전체 읽기 금지)
- [ ] 대량 탐색·로그 분석은 서브에이전트(Agent 도구) 위임
