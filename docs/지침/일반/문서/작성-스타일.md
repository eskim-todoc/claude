# 마크다운 작성 스타일

**TL;DR**: 모든 문서는 GFM(.md). 강조는 GitHub Alert(`[!NOTE]`·`[!IMPORTANT]` 등). 다이어그램은 ASCII 대신 Mermaid. 항목 식별자는 알파벳 약어(Q1·H1) 금지 — 의미 한글 라벨 + _번호(질문_1·가설_1) 형식. 외부 도메인 약어(HTTP·I2C 등)는 예외.

## 1. 기본 포멧

- 사용자가 명시적으로 다른 포멧(`.docx` / `.xlsx` / `.pdf` / `.pptx` / `.html`)을 지정하지 않는 한, **모든 문서는 GFM(GitHub Flavored Markdown, `.md`)으로 작성**한다.
- 예외 없음. 사용자가 특정 포멧을 요청한 경우에만 해당 포멧으로 작성.
- GitHub.com 또는 VSCode의 **GitHub Markdown Preview** 확장(`bierner.markdown-preview-github-styles`)에서 렌더링된 결과를 기준으로 삼는다.

## 2. 기본 GFM 문법 활용

- **표** (pipe table) — 구조화된 정보는 표로. 정렬 필요 시 `:---`, `:---:`, `---:`
- **체크리스트** — `- [ ]` / `- [x]` 형식. 절차·할 일 목록에 사용
- **코드 블록** — 언어 명시 필수 (` ```bash `, ` ```powershell `, ` ```c `, ` ```json ` 등)
- **취소선** — `~~deleted~~`로 변경 이력 표시
- **링크** — 파일 간 링크는 상대경로. 공백은 `%20`으로 인코딩. 한글은 raw 유지

## 3. GitHub Alert Blocks

강조·경고·주의사항은 **GitHub Alert 구문**을 사용한다. (일반 인용(`>`)보다 시각적으로 구분됨)

```markdown
> [!NOTE]
> 알아두면 좋은 일반 정보.

> [!TIP]
> 더 나은 방법에 대한 조언.

> [!IMPORTANT]
> 반드시 알아야 할 중요 정보.

> [!WARNING]
> 즉시 주의가 필요한 긴급 정보.

> [!CAUTION]
> 위험·부정적 결과에 대한 경고.
```

| 유형 | 용도 |
|---|---|
| `[!NOTE]` | 참고 정보, 부가 설명 |
| `[!TIP]` | 권장 방법, 팁 |
| `[!IMPORTANT]` | 반드시 인지할 핵심 사항 |
| `[!WARNING]` | 실행 전 주의할 점 (되돌리기 어려운 작업 등) |
| `[!CAUTION]` | 실수 시 데이터 손실·보안 위험 등 치명적 경고 |

## 4. 다이어그램은 Mermaid

ASCII art 다이어그램 대신 **Mermaid**를 사용한다. GitHub과 GitHub Markdown Preview 모두 네이티브 렌더링 지원.

> [!IMPORTANT]
> 모든 Mermaid 작성 시 **§4.5 노드 라벨 안전 규칙을 먼저 준수**한다 — 라벨 큰따옴표 감쌈·`~`(물결표) 금지·`<br/>` 줄바꿈은 파싱 깨짐(`Parse error ... got 'PS'` / `Unsupported markdown: del`)과 글자 잘림을 일으키는 최빈 원인이다. 작성 후 검증기로 `valid` 확인 필수.

### 4.1 자주 쓰는 Mermaid 유형

| 유형 | 용도 | 코드 블록 헤더 |
|---|---|---|
| `flowchart` | 절차·의사결정 흐름 | ```` ```mermaid ```` + `flowchart LR` (또는 TD) |
| `sequenceDiagram` | 시스템·서비스 간 상호작용 순서 | `sequenceDiagram` |
| `gitGraph` | Git 브랜치·병합 흐름 | `gitGraph` |
| `stateDiagram-v2` | 상태 머신 | `stateDiagram-v2` |
| `classDiagram` | 클래스·타입 구조 | `classDiagram` |
| `erDiagram` | 엔티티 관계 | `erDiagram` |
| `pie` | 비율 차트 | `pie` |
| `gantt` | 일정·타임라인 | `gantt` |

### 4.2 기본 예시

```mermaid
flowchart LR
    A[시작] --> B{조건?}
    B -->|Yes| C[처리 A]
    B -->|No| D[처리 B]
    C --> E[종료]
    D --> E
```

```mermaid
sequenceDiagram
    actor User
    participant Hook as Stop Hook
    participant Slack
    User->>Hook: 응답 종료
    Hook->>Slack: Webhook POST
    Slack-->>User: DM 알림
```

```mermaid
gitGraph
   commit id: "init"
   branch claude_develop
   commit id: "c1"
   branch claude_feature_x
   commit id: "c2"
   checkout claude_develop
   merge claude_feature_x
```

> [!TIP]
> Mermaid 다이어그램은 화살표 방향(`LR`/`TD`)과 스타일 클래스를 활용하면 가독성이 더 올라간다. 불필요한 분기는 과감히 생략하고 핵심 흐름만 남길 것.

### 4.3 표준 스타일 정책 (flowchart)

`flowchart` 다이어그램에는 환경 무관 일관 외형·테마 비종속·노드 다양성을 보장하기 위한 표준 스타일 정책을 적용한다. 본 정책은 *신규·갱신 다이어그램부터* 적용. 옵션 카탈로그·튜토리얼은 [`projects/mermaid-study`](../../../../projects/mermaid-study/CLAUDE.md) 노트 참조.

#### 4.3.1 정책 8요소

| # | 요소 | 명세 |
|---|---|---|
| 1 | YAML frontmatter `config` | 코드 블록 최상단 `--- title:... config: ... ---`. `theme:base` + `themeVariables` + `flowchart` 블록 |
| 2 | 폰트 12px | `themeVariables.fontSize: "12px"` |
| 3 | 굵은 선 기본 | 모든 노드 `stroke-width:3px` (classDef 명시), 엣지 `==>` 굵은 화살표, `linkStyle default stroke-width:3px` |
| 4 | 점선은 한정 사용 | 보조 관계·비동기 갭만 `-. "label" .->`. 본 흐름은 실선 |
| 5 | 배경 환경 무관 고정 | `themeVariables.darkMode:false` + `themeVariables.background:"#fafafa"` + 다이어그램 전체를 이름 없는 서브그래프 `subgraph canvas [" "] ~ end`로 감싸고 `style canvas fill:#fafafa,stroke:#cfd8dc,stroke-width:1px` |
| 6 | v11 신 노드 절제 사용 | 의미 명확한 1~2종만 (예: 코드 실행 산출은 `@{ shape: doc, label: "..." }`) |
| 7 | 시작·끝 고전 외형 | 시작 = stadium `([...])`, 끝 = double-circle `(((...)))` |
| 8 | 사각형 0개 + 외형 다양성 | rect `[텍스트]` 금지. stadium·rounded·cylinder·subroutine·평행사변형·hexagon·v11 노드·double-circle 등 6~8종 활용 |

#### 4.3.2 색상 팔레트 (5종 muted)

| 클래스 | fill | stroke | color | 용도 |
|---|---|---|---|---|
| `terminal` | `#ede4d3` | `#9a8567` | `#4a3d29` | 시작·끝 (sand) |
| `step` | `#eceff3` | `#7a8896` | `#374151` | 일반 단계 (slate-light) |
| `io` | `#dde6ee` | `#6c849c` | `#2a3f55` | 메모리·I/O (blue-gray) |
| `trigger` | `#ecdcbb` | `#a07b3a` | `#5a3e1b` | 트리거·이벤트 (mustard-muted) |
| `core` | `#dee6d4` | `#7a8f5e` | `#3d4c2b` | 실행·산출 (sage) |

모든 클래스 `stroke-width:3px` 포함. 5종 muted 톤으로 채도 일관.

#### 4.3.3 풀스타일 예시 (8요소 모두 적용)

```mermaid
---
title: "예시: 배포 파이프라인 — 표준 정책 풀스타일"
config:
  theme: base
  themeVariables:
    darkMode: false
    background: "#fafafa"
    primaryColor: "#eef0f3"
    primaryTextColor: "#374151"
    primaryBorderColor: "#7a8896"
    lineColor: "#475569"
    fontFamily: "Pretendard, Apple SD Gothic Neo, sans-serif"
    fontSize: "12px"
    clusterBkg: "#fafafa"
    clusterBorder: "#cfd8dc"
    edgeLabelBackground: "#ffffff"
  flowchart:
    curve: monotoneY
    nodeSpacing: 30
    rankSpacing: 30
    padding: 12
    htmlLabels: true
---
flowchart TD
    subgraph canvas [" "]
        direction TB

        Start([커밋 푸시])
        Build("CI 빌드<br/>npm ci · build")
        Test{{단위·통합 테스트}}
        Pkg[[패키징<br/>Docker image]]
        Stage[/스테이징 배포<br/>blue-green/]
        Smoke@{ shape: doc, label: "Smoke 테스트<br/>health-check · e2e" }
        Approve[(승인 기록<br/>change ticket)]
        Prod(((프로덕션 배포 완료)))

        Start ==> Build ==> Test ==> Pkg ==> Stage ==> Smoke
        Smoke ==> Approve ==> Prod
        Test -. "실패 시 재시도" .-> Build

        classDef terminal fill:#ede4d3,stroke:#9a8567,stroke-width:3px,color:#4a3d29
        classDef step     fill:#eceff3,stroke:#7a8896,stroke-width:3px,color:#374151
        classDef io       fill:#dde6ee,stroke:#6c849c,stroke-width:3px,color:#2a3f55
        classDef trigger  fill:#ecdcbb,stroke:#a07b3a,stroke-width:3px,color:#5a3e1b
        classDef core     fill:#dee6d4,stroke:#7a8f5e,stroke-width:3px,color:#3d4c2b

        class Start,Prod terminal
        class Build,Pkg step
        class Stage,Approve io
        class Test trigger
        class Smoke core

        linkStyle default stroke-width:3px
        linkStyle 7 stroke:#7a6e8c,stroke-width:2px,stroke-dasharray:6 4
    end

    style canvas fill:#fafafa,stroke:#cfd8dc,stroke-width:1px
```

→ 8 노드 외형(stadium·rounded·hexagon·subroutine·평행사변형·doc·cylinder·double-circle) 모두 활용. 사각형 0개.

#### 4.3.4 호환·한계 NOTE

> [!NOTE]
> **v11 신 노드 fallback**: `@{ shape: doc, label: "..." }` 등은 Mermaid v11+ 필요. 미만 환경은 평행사변형 `[/.../]`으로 대체 가능.

> [!NOTE]
> **옵시디언 다크 테마**: 옵시디언 다크 모드는 mermaid 컨테이너 div(SVG **바깥**)에 다크 배경을 적용하므로, 본 정책의 배경 고정은 SVG **내부** 영역만 흰색 유지된다. 옵시디언 SVG 외부 다크 띠는 mermaid 표준 옵션으로 해결 불가능 (GFM 호환 유지 시). 옵시디언 사용 시 별도 CSS snippet 추가 권장 (mermaid 외부 처리, GFM 영향 0).

#### 4.3.5 적용 범위

- 본 §4.3은 **flowchart 풀 적용**. **sequenceDiagram·stateDiagram-v2** 적용은 §4.4 참조 (mermaid 기능 차이로 정책 일부만 적용)
- classDiagram·erDiagram·gantt·gitGraph 등은 향후 정책 확장 시 검토
- **신규·갱신 다이어그램부터 적용**. 기존 다이어그램은 자연적 손댐 시점에 점진 변환 (일괄 소급 금지)
- 정책 풀 적용 1차 레퍼런스: [`projects/mermaid-study/docs/노트/04-스타일과 테마.md §13~§14`](../../../../projects/mermaid-study/docs/노트/04-스타일과%20테마.md)

### 4.4 표준 정책 확장 (sequenceDiagram · stateDiagram-v2)

sequenceDiagram·stateDiagram-v2는 mermaid 기능 차이로 §4.3 정책을 **부분 적용** — `linkStyle` 미지원·노드 모양 개념 다름·`subgraph canvas` wrap 불가. 공통 요소(①·②·④·⑤ 일부)만 적용하고, 다이어그램별 `themeVariables` 매핑으로 §4.3.2 5종 muted 팔레트와 시각 일관성을 유지한다.

#### 4.4.1 공통 요소 적용 매트릭스

| §4.3 요소 | sequenceDiagram | stateDiagram-v2 |
|---|---|---|
| ① YAML frontmatter `config` | 적용 (theme:base + themeVariables) | 적용 (theme:base + themeVariables) |
| ② 폰트 12px | 적용 (`fontSize:"12px"`) | 적용 |
| ③ 굵은 선 기본 | 부분 — `themeVariables.signalColor`로 색만 일관 (stroke-width 직접 제어 X) | 적용 — `classDef ... stroke-width:3px` 지원 |
| ④ 점선 한정 | 적용 — `-->>` 응답·`-)` async 한정 | **미적용** — state-v2는 점선 전이 미지원 (`-.->` parser INVALID). 모든 전이 `-->` 실선만 사용 |
| ⑤ 배경 환경 무관 고정 | `darkMode:false` + `themeVariables.background` (canvas wrap 불가) | `darkMode:false` + `themeVariables.background` (canvas wrap 불가) |
| ⑥ v11 신 노드 | 미적용 (개념 부재) | 미적용 (개념 부재) |
| ⑦ 시작·끝 고전 외형 | 미적용 (액터 개념) | 적용 — `[*]` 종료 마커 표준 |
| ⑧ 사각형 0개 | 미적용 | 부분 — 단순 state는 mainBkg, 복합 state는 compositeBackground로 시각 구분 |

#### 4.4.2 sequenceDiagram themeVariables 매핑 (5 muted 톤)

| 키 | 값 | 클래스 매핑 |
|---|---|---|
| `actorBkg` / `actorBorder` / `actorTextColor` / `actorLineColor` | `#eceff3` / `#7a8896` / `#374151` / `#475569` | step (액터) |
| `signalColor` / `signalTextColor` | `#475569` / `#374151` | line |
| `noteBkgColor` / `noteBorderColor` / `noteTextColor` | `#ecdcbb` / `#a07b3a` / `#5a3e1b` | trigger (노트) |
| `activationBkgColor` / `activationBorderColor` | `#dee6d4` / `#7a8f5e` | core (활성화) |
| `labelBoxBkgColor` / `labelBoxBorderColor` / `labelTextColor` | `#dde6ee` / `#6c849c` / `#2a3f55` | io (loop·alt·opt 라벨) |
| `loopTextColor` / `sequenceNumberColor` | `#374151` | step |

> [!NOTE]
> sequenceDiagram은 `classDef`·`linkStyle` 미지원. 시각 다양성은 액터/노트/활성화/라벨 박스 4 영역의 themeVariables 톤 구분으로 표현.

#### 4.4.3 stateDiagram-v2 themeVariables 매핑 + classDef

| 키 | 값 | 클래스 매핑 |
|---|---|---|
| `mainBkg` / `nodeBorder` / `labelColor` / `lineColor` | `#eceff3` / `#7a8896` / `#374151` / `#475569` | step (단순 state) |
| `compositeBackground` / `compositeBorder` / `compositeTitleBackground` | `#dde6ee` / `#6c849c` / `#dde6ee` | io (composite state) |
| `altBackground` | `#ecdcbb` | trigger (concurrent 영역) |
| `labelBackgroundColor` | `#fafafa` | (배경과 동일) |

특수 강조 state는 §4.3.2 `classDef` 5종(terminal·step·io·trigger·core) 그대로 활용 (`stroke-width:3px` 포함).

- classDiagram·erDiagram·gantt·gitGraph 등은 향후 별도 확장 검토 (mermaid 옵션 카탈로그는 [`mermaid-study 04 노트`](../../../../projects/mermaid-study/docs/노트/04-스타일과%20테마.md) 참조)
- §4.3과 마찬가지로 **신규·갱신 다이어그램부터 적용**. 기존 일괄 소급 금지

### 4.5 노드 라벨 안전 규칙 (파싱 깨짐·글자 잘림 방지)

Mermaid 다이어그램이 깨지는 최빈 원인은 **노드 라벨 안의 특수문자 처리**다. 아래 4규칙은 모든 Mermaid 다이어그램(flowchart·stateDiagram 등)에 **필수 적용**한다. 모양 종류(stadium·diamond 등)와 무관하다.

#### 4.5.1 규칙 4종 (필수)

| # | 규칙 | 이유 | 잘못 → 올바름 |
|---|---|---|---|
| 1 | **모든 노드 라벨을 큰따옴표 `"..."`로 감싼다** (모양 괄호 안쪽). 다이아몬드 `{"..."}`, 스타디움 `(["..."])`, 라운드 `("...")`, subgraph 제목 `["..."]` 전부 | 라벨에 `(` `)` `&` `[` `]` `<` `>` `=` 가 따옴표 없이 들어가면 `Parse error ... got 'PS'` 발생 | `B{tdc_get(&s) 성공?}` → `B{"tdc_get(&s) 성공?"}` |
| 2 | **라벨 안에 `~`(물결표) 금지** | `~`가 한 다이어그램에 2개 이상이면 Mermaid가 그 사이를 취소선(`<del>`)으로 오인 → `Unsupported markdown: del` 에러 | `[main.c:386~393]` → `[main.c:386-393]` (범위는 하이픈) |
| 3 | **줄바꿈은 `<br/>`만 사용** | `\n`은 렌더 안 됨, `</br>`는 비표준(닫는 태그 단독)이라 환경에 따라 깨짐 | `1줄\n2줄` / `1줄</br>2줄` → `1줄<br/>2줄` |
| 4 | **라벨 텍스트는 간결하게** — 긴 부연은 `<br/>`로 줄 분할하거나 본문 표로 분리 | 과길이 라벨은 노드 박스 밖으로 넘쳐 인접 노드·subgraph 제목과 겹쳐 가려짐 | 한 라벨 3~4줄 이내 권장 |

#### 4.5.2 작성 후 검증 (필수)

- Mermaid 작성·수정 후 **검증기로 `valid` 확인 후 커밋**한다. 검증 없이 커밋 금지.
- 도구: MCP `validate_and_render_mermaid_diagram` (Mermaid Chart) 또는 [Mermaid Live Editor](https://mermaid.live).
- `valid: true`면 렌더 SVG가 커서 도구 출력이 토큰 한도를 넘을 수 있다 — 이때는 저장된 결과 파일에서 `valid` 필드만 추출해 확인한다(파싱 성공의 정상 신호).

#### 4.5.3 적용 범위

- **모든 Mermaid 다이어그램에 필수 적용** (flowchart·sequenceDiagram·stateDiagram-v2 등 전부)
- §4.3 표준 스타일 정책과 **독립** — 스타일 적용 여부와 무관하게 본 §4.5는 항상 우선
- 신규·갱신 다이어그램 작성 시 의무. 기존 깨진 다이어그램은 손대는 시점에 같이 교정

## 5. 문서 구조

- 최상위 제목은 `#` 하나. 파일당 하나.
- 섹션 구분은 `##`, `###` 순서대로. 건너뛰지 말 것.
- 긴 문서는 맨 위에 간단한 목차 또는 개요 섹션을 둘 것.
- 긴 섹션 사이 구분이 필요하면 `---` 수평선 사용.

## 6. 라벨링 — 알파벳 약어 금지

문서 내 항목 식별자(질문·가설·위험 등) 는 알파벳 약어 (`Q1`, `H1`, `R1`, `P1`) 대신 **의미가 드러나는 한글 라벨 + `_<번호>`** 형식으로 표기한다.

> [!IMPORTANT]
> 약어는 본인조차 며칠 후 보면 "이게 뭐였지?" 가 된다. 이름 자체가 의미를 전달해야 한다.

### 6.1 형식

`<한글 라벨>_<번호>` (예: `질문_1`, `가설_2`, `위험_3`, `요구사항_1`)

### 6.2 권장 라벨 (참고용 — 작성자 재량 가능)

| 알파벳 약어 | 권장 한글 라벨 | 사용 맥락 |
|---|---|---|
| Q (Question) | 질문 | 사용자에게 묻거나 미해결 의문 |
| A (Analysis) | 분석 | 분석 항목·서브토픽 |
| H (Hypothesis) | 가설 | 디버깅·root cause 추정 |
| R (Risk) | 위험 | 회귀·부작용 위험 |
| R (Requirement) | 요구사항 | 기능·비기능 요구 |
| G (Goal) | 목적 / 목표 | 작업 목표 |
| P (Problem) | 문제 | 식별된 문제 |
| P (Plan) | 계획 | 구현 단계·작업 항목 |
| D (Decision) | 결정 | 설계 결정 |
| C (Constraint) | 제약 | 환경·시스템 제약 |
| O (Option) | 선택지 | 다중 옵션 비교 |
| T (Test) | 시험 | 시험 케이스·항목 |

표는 권장일 뿐. 새 카테고리가 필요하면 작성자가 의미 명확한 한글 라벨을 신규 도입할 수 있다 (단어 중복 회피, 같은 문서 내 일관성 유지).

### 6.3 적용 범위

- **모든 영속 `.md` 문서** 에 적용 (지침/사용방법/tasks 산출물 등 전부)
- **소급 처리**: 기존 문서 손댈 때 같이 변경 (점진적). 일괄 소급 변경은 사용자 명시 요청 시에만

### 6.4 예외

- 외부 표준·도메인 약어 (`HTTP/2`, `IEEE 802.11`, `I2C`, `SPI` 등) 은 그대로 유지 — 본 규칙 대상 아님
- 단순 번호 매기기 (`1.`, `2.`, `(a)`, `(b)`) 는 영향 없음 — 본 규칙은 *식별자 라벨* 에만 적용
- 표 컬럼 헤더 약어 (예: `ID`, `No.`) 는 자유

## 7. 학습 노트 — 문서 스타일 (2026-05-18 회고 흡수)

> [!NOTE]
> 2026-05-18 Package C 이전에는 `docs/회고/문서 스타일.md`에 별도 누적. 이제는 본 파일에 흡수.

### 7.1 GFM + Mermaid + Alert Blocks 문서 스타일 (2026-04-21) *(maturity: core)*

모든 `.md` 문서는 GitHub.com 또는 VSCode **GitHub Markdown Preview** 확장(`bierner.markdown-preview-github-styles`)에서 렌더링된 결과를 기준으로 작성한다.

**Why:** 사용자가 VSCode에 GitHub Markdown Preview 확장을 설치해 GitHub 렌더링 기준으로 문서를 읽음. 일관된 시각적 품질을 위해 GitHub이 네이티브 지원하는 GFM 확장 문법(Alert blocks, Mermaid 등)을 적극 활용한다.

(상세 적용 방법은 §3 Alert Blocks·§4 Mermaid·§2 GFM 문법 참조)

### 7.2 지침 모호 표현(`선택`/`권장`) 금지 — 단호한 `필수`/`금지`로 (2026-05-06) *(maturity: core)*

지침에 "선택 적용", "권장", "가능하면" 같은 모호한 표현을 쓰면 LLM은 결국 일관 적용에 실패한다. 같은 폴더 안에서도 어떤 파일은 적용되고 어떤 파일은 누락되어 사용자가 일관성 깨진 상태를 발견한 후에야 지적이 들어옴.

**How to apply:**

- 지침 작성 시 적용 범위는 **`필수 적용` / `미적용` / `금지 상태`**의 단호한 3분법으로 표기. `선택 적용`·`권장`·`가능하면`은 사용 금지
- 정말 조건부 선택이 필요하면 그 **선택 기준**(언제 적용·언제 미적용)을 if-then 형태로 명시. 판단을 LLM에 떠넘기지 않는다
- 지침에 **금지 상태**(예: "같은 폴더 내 일부 파일에만 적용된 부분 적용")를 명시 — LLM이 일관성 검증을 self-trigger 하게
- 템플릿은 지침 본문의 규칙과 **동기화 검증**: 템플릿이 빠뜨린 항목은 LLM이 그대로 빠뜨림. 신규 규칙 추가 시 관련 템플릿도 동시 갱신
- 기존 모호 지침을 발견하면 손댈 때 같이 단호화 (점진적 개선)

### 7.3 외부 인계 명세서는 도구 측 형식 명세와 분리 (2026-05-08) *(maturity: stable)*

같은 형식 정보라도 **청자가 다르면 별도 문서로 분리**하고 양쪽을 상호 링크한다. 도구 측 사용자(이 도구를 어떻게 쓸지) 관점의 형식 명세와 외부 작업자(이 형식을 어떻게 *생산*할지) 관점의 인계 명세는 같은 마커·정규식 정보를 담더라도 우선순위·강조점·검증 절차가 다르다.

**How to apply:**

- 하나의 인터페이스·형식이 둘 이상의 *역할*에서 참조되면 (예: 도구 사용자 + 외부 생산자, API 호출자 + API 제공자) 역할별 별도 문서 작성
- 각 문서 frontmatter `applies_to`와 본문 TL;DR에 **청자 명시**
- 동일 정보는 양쪽에 약간씩 중복 OK — 단일 진실의 출처는 코드(정규식 상수 등)
- 양쪽 문서 TL;DR 직후에 `> [!NOTE]` 한 줄로 상호 참조
- 외부 인계용은 추가로 명시:
  - `## 변경 이력` 섹션 (v1.0 등 버전 부여) — 외부에 *전달*되는 명세는 명시 버전 관리 필수
  - `## 검증 방법` 섹션 — 외부 작업자가 자체 점검 가능한 절차

### 7.4 frontmatter `name` 필드는 헤더에 YAML 특수문자 포함 시 큰따옴표 (2026-05-07) *(maturity: experimental)*

frontmatter `name` 필드 값을 본문 첫 `#` 헤더 텍스트와 동기화할 때, 헤더에 `[`/`]`/`:`/`#`/`|`/`&`/`*`/`!`/`%`/`@`/`` ` ``/`>` 같은 **YAML reserved 문자**가 포함되어 있으면 **항상 큰따옴표로 감싸 안전 처리**한다.

**How to apply:**

- frontmatter 작성 시 `name` 값이 다음 중 하나로 **시작**하면 큰따옴표 감쌈 의무:
  - `[` `]` `{` `}` (flow indicators)
  - `&` `*` `!` `|` `>` `'` `"` `%` `@` `` ` `` (YAML special)
  - `#` (comment starter)
  - `?` (mapping key)
  - `-` 다음 공백 (sequence)
- 값 **중간**에 `:` + 공백 또는 ` #`(공백+해시)이 들어가도 감쌈 의무
- 안전 디폴트 — 의심스러우면 큰따옴표. 한글·영문 조합 평범한 텍스트는 감쌈 불필요
