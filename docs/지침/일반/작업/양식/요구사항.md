# 양식 — 요구사항.md

**TL;DR**: 4단계 ① 요구사항 산출물 표준 양식. 사용자 요청 원문·목표·수용 기준·작업 범위 외·위임 범위·관련 산출물·자체 검토 7개 섹션. 양식 본문을 작업 폴더의 `요구사항.md`로 복사한 뒤 `<...>` placeholder를 채워 사용. frontmatter의 `maturity`는 신규 작업이라 기본 `experimental`로 시작.

## 사용법

1. 새 작업 폴더(`docs/tasks/<모듈>/YYYYMMDD_<slug>/`) 생성
2. 본 파일의 §양식 본문을 복사해서 작업 폴더의 `요구사항.md`로 저장
3. `<...>` placeholder를 실제 내용으로 채움
4. 채울 내용이 없는 섹션은 "해당 없음" 또는 섹션 삭제
5. 작성 직후 셀프 체크: frontmatter·TL;DR·의미 한글 라벨 ([`../../문서/메타-frontmatter.md`](../../문서/메타-frontmatter.md))

# 요구사항: <작업명>

**TL;DR**: <80~250자 — 무엇을·왜·검증 기준 핵심을 한 단락으로>

## 1. 사용자 요청

사용자가 제시한 원문 또는 정리된 의도.

> "<사용자 원문 인용>"

모호 포인트가 있었다면 어떻게 질문·해소했는지 명시.

## 2. 목표

본 작업으로 달성할 목표:

- 목표_1: <구체적 목표>
- 목표_2: <...>

## 3. 수용 기준 (Definition of Done)

본 작업 완료 판정 기준:

### 3.1 기능·산출물
- [ ] 수용기준_1: <검증 가능한 항목>
- [ ] 수용기준_2: <...>

### 3.2 정합성·검증
- [ ] git diff로 모든 변경 검토 가능
- [ ] cross-link 살아있음 (broken link 0)
- [ ] `이력 및 결과.md` 시계열 로그 + 완료 요약 작성

### 3.3 회귀 방지
- [ ] 본 작업은 `claude_feature_<설명>` 브랜치 격리
- [ ] 각 commit이 atomic — 단계별 revert 가능

## 4. 작업 범위 외 (Out of Scope)

본 작업에서 다루지 않을 항목:

- 범위외_1: <사유>
- 범위외_2: <사유>

## 5. 위임 범위 (Claude 자율 결정)

사용자가 위임한 결정 영역:

- 위임_1: <어떤 결정>

위임 범위 밖 (사용자 결정 영역):

- 사용자결정_1: <merge·push 등>

## 6. 관련 산출물

본 작업 폴더의 다른 산출물:

- [분석.md](분석.md) — 현 상태·영향 범위·결정
- [계획.md](계획.md) — 실행 단계·검증
- [이력 및 결과.md](이력%20및%20결과.md) — 시계열 로그·완료 요약
- 첨부: `첨부_요구사항_<제목>.<ext>` (있다면)
