# 컨텍스트 절약 규칙

**TL;DR**: 응답·툴 결과를 처음부터 압축. **파일 내용 출력 금지** — 경로·라인만 제공, 사용자가 직접 열람. 변경 보고는 diff 형태로 간략히. 툴 출력 1줄 요약, 인사·사전 설명·사후 부연 금지, 작업 종료는 `변경/검증/다음` 3줄. `/compact` 의존 X — 생성 시점부터 절약.

## 1. 핵심 원칙

응답이 컨텍스트의 가장 큰 비중을 차지하지 않도록, 처음부터 메시지를 압축해서 전달한다. 요약(`/compact`)에 의존하지 않고, **생성 시점부터 절약**하는 것을 우선한다.

## 2. 응답 작성 규칙 (필수)

### 2.1 파일 내용 출력 금지 (경로·diff 만)

- Read 한 파일 내용을 응답에 인용·발췌하지 말 것 — 사용자가 직접 파일을 연다
- 파일 위치는 `[경로](경로)` 또는 `<파일>:<라인>` 마크다운 링크 형태로만 제공
- 변경 보고는 **간략한 diff** 형태 우선 (변경된 라인만, 미변경 컨텍스트 최소화)
- 변경 규모가 크면 `<파일>:<라인범위> 수정 완료` 1줄로 대체
- 변경 후 전체 파일을 다시 보여주지 말 것
- 사용자가 명시적으로 "보여줘"라고 할 때만 발췌 출력

### 2.2 툴 결과 즉시 요약·폐기

- Bash / grep / glob 출력을 그대로 인용하지 말 것
- `X개 일치, 핵심: Y` 1줄로 요약
- 긴 빌드 / 테스트 로그는 에러 라인만 추출해 보고
- 디렉토리 트리는 관련 항목만 발췌

### 2.3 응답 형식 압축

- 사전 설명("이제 ~하겠습니다") 금지 → 바로 실행
- 사후 부연("이로써 ~됩니다") 금지 → 결과만
- 코드 블록은 변경분(diff)만, 미변경 부분 생략
- 불릿 3개 이내, 각 라인 1줄 이내
- 인사말·맺음말 생략

### 2.4 다중 질문 통합

- 확인이 필요하면 여러 질문을 한 턴에 묶을 것
- "A는 어떻게 할까요? 그리고 B는요?" 형태로 1회 응답에 통합

### 2.5 보고 형식 (작업 단위 종료 시)

다음 형식 고정:

```
변경: <파일>:<라인>
검증: <테스트/빌드 결과 1줄>
다음: <후속 작업 또는 "대기">
```

> [!NOTE]
> 회고 `커뮤니케이션.md`의 "응답 말미 명사구 한 줄 요약 (Slack 알림 추출)"과 호환을 위해, 위 3줄 보고 다음 줄에 명사구 한 줄 요약을 덧붙여도 무방하다.

### 2.6 금지된 응답 패턴

- "물론입니다", "알겠습니다", "좋은 질문입니다" 등 인사
- "혹시 ~하실 의향이 있으시다면" 류 권유
- 작업 완료 후 자체 회고 / 평가 (요청 시에만)
- 같은 정보를 표·코드·산문 3중으로 표현

### 2.7 시각화 예외

- 시각화는 컨텍스트가 아닌 별도 위젯으로 렌더되므로 적용 가능
- 단, 시각화 후 같은 내용을 텍스트로 다시 설명하지 말 것

### 2.8 사고 과정 비노출

- "단계별로 생각하면..." 류 사고 노출 금지
- 결론만 제시, 근거는 요청 시에만

## 3. 구조적 트릭 (토큰 절감 효과 순)

### A. 파일 작업은 항상 in-place 편집

- `Read → 전체 출력 → Edit → 전체 재출력` 패턴 금지
- `Edit` 툴은 diff만 컨텍스트에 남기므로 이를 적극 활용한다
- 파일 전체를 응답에 다시 게시하지 말 것

### B. 큰 파일은 Read 범위 제한

- Read 시 `offset` / `limit` 필수, 전체 읽기 금지
- 1000줄 파일 전체를 읽으면 그 전부가 컨텍스트에 적재됨
- 필요 영역만 잘라서 읽고, 추가 필요 시 추가 Read

### C. 검색 결과 압축

- Grep 사용 시 `-c`(카운트) 또는 `-l`(파일명만) 우선
- 본문 매칭은 정말 필요할 때만
- raw 매칭 라인 100개를 그대로 컨텍스트에 두지 않는다

### D. 서브에이전트로 격리

- 대량 탐색·로그 분석은 서브에이전트(Agent 도구, `Explore`/`general-purpose` 등)에 위임
- 서브에이전트는 별도 컨텍스트에서 작업 후 **요약만** 메인으로 반환
- 펌웨어 코드베이스 grep, 멀티 파일 분석 등에 특히 유효

## 4. 위반 시 교정

사용자가 `규칙 N 위반` 또는 `규칙 위반`이라고 짧게 지적하면, 즉시 해당 규칙을 재확인하고 이후 응답에서 동일 패턴을 반복하지 않는다. 변명·사과는 1줄 이내로만.

## 5. 적용 우선순위

1. 사용자가 명시적으로 다른 형식을 요청한 경우 → 사용자 요청 우선
2. 그 외 모든 경우 → 본 지침 적용
3. 본 지침과 프로젝트별 `CLAUDE.md`가 충돌하면 → 프로젝트 `CLAUDE.md` 우선
