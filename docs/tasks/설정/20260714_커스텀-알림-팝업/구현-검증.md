# 구현 검증 — 커스텀 알림 팝업

**TL;DR**: 구현 산출물(`toast-notify.ps1` 신규, `slack-notify.ps1` 연동, 지침 문서)을 3축 검증. 팝업 렌더 정상(렌더샷 실측)·slack→팝업 연동 성공(손자 프로세스 실측)·구문 OK·BOM 이슈 해결 확인. 통과.

## 실측 테스트 결과

| 항목 | 방법 | 결과 |
|---|---|---|
| 구문 | `Parser::ParseFile` (BOM 포함) | toast·slack 둘 다 **OK** |

| 창 상태 | 진단 로그(STA·위치·가시성) | `vis=True`, 우하단 `(1516,898)`, 크기 392×122 **정상** |

## 축_1 지침 준수

- [x] 코딩: 파일명 tools 관례(케밥), 내부 함수 `tdc_` 접두(`tdc_Show-CompletionToast`·`tdc_Build-SparkGeometry`).

- [x] silent 실패 원칙 유지(기존 `slack-notify.ps1`과 동일).

## 축_2 논리 정합성

- [x] 팝업 detached 기동이 훅을 붙잡지 않음(제약_3) — 손자 프로세스 독립 생존 확인.
- [x] Slack POST와 팝업이 독립(요구사항_1) — 팝업 기동을 POST try/catch **앞**에 배치해 Slack 실패에도 팝업 발사.
- [x] 6초 표시(요구사항_4) + 하드 타임아웃(N+4초) 안전장치(위험_5).

## 축_3 근거 검증 (디버깅 이력 포함)

- [x] **인코딩 회귀**: PS 5.1이 BOM 없는 UTF-8의 한글을 오독 → 구문 오류 4건. `UTF8Encoding($true)` BOM 저장으로 해결(실측 재검증 OK). 트러블슈팅에 문서화.
- [x] **"테마 미적용" 오인**: 은수님 관찰 vs 실제. 진단 로그+렌더샷으로 팝업은 정상 테마임을 실측 확인 → 동시에 뜬 카카오톡 알림 착시로 판정(추측 아님, 렌더샷 근거).
- [x] **투명창 캡처 누락**: `AllowsTransparency` 창이 BitBlt 캡처에 안 잡히는 특성 확인 → `RenderTargetBitmap`으로 우회.
- [x] **self-kill**: `Stop-Process` 필터가 명령 텍스트 포함 자기 프로세스 매칭 → `$PID` 제외로 해결.

## 잔여·후속

- 임시 진단 코드(`tdc_Log`/`TOAST_LOG`/`TOAST_SHOT`)는 production 최종본에서 **제거 완료**.
- 다중 세션 동시 완료 시 팝업 겹침(비목표_3) — 후속 개선 여지.
- 시안·렌더 증거 HTML은 작업 폴더에 보관(scratch는 gitignored).
