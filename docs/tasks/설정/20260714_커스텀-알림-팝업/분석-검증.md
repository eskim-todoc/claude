# 분석 검증 — 커스텀 알림 팝업

**TL;DR**: 분석.md를 3축 검증. WPF 채택·detached 실행·Path 심볼 결정이 요구사항/제약과 정합하고 사실에 근거함. `tdc_` 네이밍 논점을 명시적으로 해소. 통과.

## 축_1 지침 준수

- [x] `tdc_` 접두 규칙 논점(§5)을 회피하지 않고 명시 — 파일명은 tools 관례, 함수는 접두 절충으로 결론.
- [x] 다이어그램 Mermaid 사용(§2), ASCII 금지 준수.
- [x] 회귀 감지 원칙(silent 실패 → 수동 트리거 필수) 반영(§7) — `지침/설정/Slack 알림.md` 트러블슈팅과 정합.

## 축_2 논리 정합성

- [x] 제약_3(훅 즉시 반환) ↔ 요구사항_4(6초): §2 detached 자식 프로세스로 해소 — 훅과 팝업 생명주기 분리.
- [x] 위험_4(포커스 탈취) ↔ 요구사항(작업 방해 없이): `ShowActivated=false`로 정합.
- [x] 심볼 선택(§4): 시안의 conic-gradient가 WPF에 없다는 제약을 Path 벡터로 대체 — 요구사항_7(sunburst) 시각 유지.

## 축_3 근거 검증

- [x] WPF STA 요구: WPF는 UI 스레드가 STA여야 함(.NET 공식 동작) → `-Sta` 기동 근거.
- [x] `SystemParameters.WorkArea`: 작업표시줄 제외 영역 반환(.NET WPF API) → 우하단 계산 근거.
- [x] BurntToast 배경색 불가: Windows Toast는 시스템 테마 렌더 → 앞선 조사 결론과 일치.
- [x] tools 관례: `tools/*.ps1` = `slack-notify.ps1`·`check-links.ps1` 실측(Glob) → 케밥·`tdc_` 미사용 확인.

## 리스크 잔여

- WPF `Path` 스파이크 지오메트리는 구현 시 좌표 계산 필요 — 계획에서 구체 좌표/생성 방식 확정.
- detached 프로세스의 콘솔 순간 노출 가능성 → `-WindowStyle Hidden` + `CreateNoWindow`로 억제(계획에서 확정).
