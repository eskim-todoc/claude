# 요구사항: 작업 목록 모듈별 분산화

**TL;DR**: 작업이 누적될수록 `tasks/작업 목록.md`(단일 표)가 기하급수적으로 비대해지는 문제(Sound1 88KB·47행·12모듈이 실증 사례)를 해소하기 위해, 작업 단위 상세 레지스트리를 각 모듈 폴더(`tasks/<모듈>/작업 목록.md`)로 분산하고, 루트 `tasks/작업 목록.md`는 모듈별 링크만 거는 얇은 인덱스로 축소한다. 정본 지침(`폴더-구조.md` §5)과 이를 참조하는 7개 파일을 동기화하고, 루트 저장소 자신의 목록도 즉시 마이그레이션한다.

## 1. 사용자 요청

> "수정하는 김에 좀만 더 수정하자. 작업 목록 파일이 작업이 많아지니 그 내용이 기하급수적으로 늘어나. 대표적인 예가 Sound1 프로젝트가 그래. 그래서 tasks 폴더 내의 각 모듈 폴더 내부에 작업 목록을 각각 추적하게 하는게 좋을거 같아. 기존의 작업 목록은 이제 놔두고. 그냥 각 모듈 내부의 목록 파일을 추적할 수 있게 링크만 거는걸로 하고 싶어. 기존의 작업 목록 내용들은 각 모듈 폴더 내로 이동시키게 하고. 그게 더 관리가 좋을거 같아."

진행 중이던 `20260703_전면위임-강화`(오케스트레이터 전면 위임 정책) 작업과는 주제가 달라 별도 작업 폴더로 분리했다(같은 `meta` 모듈, 같은 세션·브랜치에서 순차 진행). Explore 서브에이전트 2개 병렬 조사로 (1) 관련 지침 인벤토리 (2) 프로젝트별 실제 규모를 확인한 뒤 본 문서를 작성했다.

## 2. 목표

- 목표_1: 정본 지침 `docs/지침/일반/문서/폴더-구조.md` §5(작업 레지스트리)를 "모듈별 목록 파일 + 루트 링크 인덱스" 2단 구조로 재정의
- 목표_2: 이를 참조하는 7개 지침 파일(완료처리.md·4단계-프로세스.md·작업 진행 규칙.md·문서 작성 규칙.md·작업 규칙.md·지침/README.md·프로젝트 초기 세팅.md) 문구 동기화
- 목표_3: `모듈 현황.md`(모듈 단위 헬스 스냅샷)와 신규 "모듈별 작업 목록.md"(작업 단위 생애주기)의 역할이 겹치지 않도록 경계 재확인 — 기존 지침이 이미 "통합 시 정렬 모순"으로 병합을 명시적으로 거부한 결정을 존중
- 목표_4: 루트 저장소 자신에 즉시 자기 적용 — 기존 `docs/tasks/작업 목록.md`의 `meta` 모듈 16행(+갱신 이력 29건)을 `docs/tasks/meta/작업 목록.md`로 이동, 루트 `docs/tasks/작업 목록.md`는 인덱스로 축소

## 3. 수용 기준 (Definition of Done)

### 3.1 기능·산출물

- [ ] 수용기준_2: 7개 참조 파일의 "`tasks/작업 목록.md` = 단일 표" 전제 문구 전량 갱신
- [ ] 수용기준_3: 루트 `docs/tasks/meta/작업 목록.md` 신규 생성 — 기존 16행(+갱신 이력 29건) 이동 + 이번 세션 작업 2건(`20260703_전면위임-강화`·본 작업) 등재
