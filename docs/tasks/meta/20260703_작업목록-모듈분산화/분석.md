# 분석: 작업 목록 모듈별 분산화

**TL;DR**: 정본은 `폴더-구조.md` §5(6곳) — 참조 7개 파일(합 18곳)까지 총 8파일 24곳. Sound1 88KB·47행·12모듈(타 6곳 합계의 6.5배, touch 모듈만 36%)이 문제를 실증한다. 핵심 결정은 "모듈별 목록 파일 = 작업 단위 상세, 루트 인덱스 = 순수 링크 라우터, 모듈 현황.md = 통계 헬스"로 3자 역할을 겹치지 않게 분리하는 것 — 기존 지침이 "작업 목록·모듈 현황 통합 시 정렬 모순"으로 병합을 이미 거부한 결정과 정합시킨다.

## 1. 현 상태 (Current State)

- 현황_1: `폴더-구조.md`(maturity: stable, 정본)는 §1 레이아웃·§5(레지스트리 목적/파일구조/컬럼정의/갱신이벤트/라우팅)·§6(모듈 현황.md)·§7(cross-module 연계)에서 `tasks/작업 목록.md`를 **루트의 단일 표**로 명시 정의한다(`:29-31`, `:116` "단일 표")
- 현황_2: §6.1(`:181`)에 이미 "작업 목록.md(작업 단위 생애주기)와 모듈 현황.md(모듈 단위 헬스)는 차원이 다름 — 둘 다 유지가 정답(통합 시 정렬 모순)"이라는 선행 결정이 있다. 본 작업은 이 결정을 뒤집지 않는다 — "작업 목록의 상세 내용이 어디 있는가"만 바꾸는 것이지, "작업 목록과 모듈 현황을 합친다"는 논의가 아니다
- 현황_3: 정본을 참조·요약하는 7개 파일에서 24곳(정본 6 + 참조 18) 갱신 필요 — Explore 조사 결과:

## 3. 가설·선택지

### 3.2 선택지 (설계 결정)

**쟁점: 루트 `작업 목록.md`(신규 인덱스)와 `모듈 현황.md`의 역할이 겹치지 않는가?**

| 선택지 | 장점 | 단점 |
|---|---|---|
| 선택지_1: 루트 작업 목록.md를 모듈 현황.md와 동일한 통계 컬럼(최종 업데이트·최근 작업·작업 수)으로 재구성 | 정보량 풍부 | §6.1 "정렬 모순" 경고와 사실상 같은 문제 재발 — 두 파일이 같은 데이터를 다른 형식으로 중복 관리하게 됨 |
| 선택지_2: 루트 작업 목록.md는 **순수 링크 라우터**(모듈명 + 목록 파일 링크만, 통계 없음)로 최소화 — 통계는 기존대로 모듈 현황.md 전담 (채택) | 역할 완전 분리 — 라우팅(작업 목록.md) vs 헬스(모듈 현황.md), 중복 데이터 없음 | 루트 파일이 "너무 얇아" 존재 의미가 작아 보일 수 있음 → §5.1에 "왜 인덱스만 있는가"를 명시해 해소 |

**결정: 선택지_2 채택.** 새 역할 3분할: **모듈별 작업 목록.md**(작업 단위 상세 생애주기, §5.2 컬럼 그대로 모듈 스코프로 축소) / **루트 작업 목록.md**(모듈 존재 여부·링크만 안내하는 라우터) / **모듈 현황.md**(모듈 단위 헬스 통계, 변경 없음).

**쟁점: "상태 정의"(5개 상태값) 표를 각 모듈 목록 파일마다 반복할 것인가?**

| 선택지 | 장점 | 단점 |
|---|---|---|
| 선택지_1: 모듈별 목록 파일마다 상태 정의 표 반복 포함 | 파일 단독으로 완결적 | 상태 정의가 전역 공통 규칙인데 N군데 중복 — 향후 상태값 추가 시 N곳 동시 수정 필요 |
| 선택지_2: 상태 정의 정본은 `폴더-구조.md` §5에 유지, 모듈별 파일은 링크로만 참조 (채택) | 단일 진실 원본(SSOT) 유지 | 모듈 파일만 열어보면 상태값 의미를 바로 못 봄(링크 클릭 필요, 경미) |

**결정: 선택지_2 채택** — "갱신 이력"(이벤트 로그)만 모듈별로 자체 보유(해당 모듈 이벤트가 자연 스코프), "상태 정의"는 폴더-구조.md 참조로 통일.

## 4. 핵심 결정

- 결정_1: 3자 역할 분리 — 모듈별 작업 목록.md(상세) / 루트 작업 목록.md(순수 링크 라우터) / 모듈 현황.md(헬스 통계, 불변) — §6.1 선행 결정("정렬 모순으로 통합 안 함")과 정합
- 결정_2: 상태 정의는 폴더-구조.md 정본 1곳 유지, 갱신 이력은 모듈별 분리
- 결정_3: 루트 저장소는 즉시 자기 적용(목표_4) — `docs/tasks/meta/작업 목록.md` 신설, 기존 16행+갱신 이력 29건 이동 + 진행 중인 2건(`20260703_전면위임-강화`·본 작업) 등재는 **`docs/tasks/meta/작업 목록.md` 신설 시점에 바로 새 파일에 기재** — 기존 루트 단일 표에 먼저 등재했다가 다시 옮기는 이중 작업 회피
- 결정_4: `20260703_전면위임-강화`를 먼저 완료(커밋)한 뒤 본 작업 구현 착수 — 공통으로 건드리는 `작업 규칙.md`의 동시 편집(병렬 Workflow 노드가 같은 파일을 동시에 Edit)을 피하기 위한 순차화 ([`서브에이전트 활용.md §6` 동시성 규칙](../../../../지침/일반/서브에이전트%20활용.md))
- 결정_5: Sound1 등 프로젝트 repo 실제 마이그레이션은 범위 외 — 별도 후속 작업으로 권고(우선순위: Sound1 최우선, 근거는 §1 현황_4 표)
