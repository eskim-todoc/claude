# 요구사항: 위키 정책 이관 및 도메인 재편

**TL;DR**: `docs/tasks/meta/20260706_wiki-pkm-고도화/`로 wiki를 판단 시점 트리거 모델로 개편한 직후, 은수님이 구조 자체에 이의를 제기했다 — wiki 프로젝트가 자기만의 운영 방침(CLAUDE.md·운영/ 문서)을 갖는 것 자체가 이상하다는 지적. 운영 방침 전체를 루트 지침으로 이관하고, wiki 프로젝트는 CLAUDE.md 없이 README.md로 시작하며, 콘텐츠(html/·wiki vault/ 전체)를 문서 유형이 아닌 **도메인/주제 기준**으로 대분류·세부분류 폴더에 전면 재편한다.

## 1. 사용자 요청

> "지금 보니까 좀 이상하다. 일단 wiki 프로젝트에서 운영 방침을 갖게 하지 말고, 운영 방침은 전부 루트 지침/헌법 체계로 병합시켜. 기존에 남아 있던 html, wiki vault, agents, claude 파일도 정리하자. 그냥 wiki 프로젝트 폴더내에 README.md 로 시작하게 하고, 내용에 따라 대분류를 시켜서, 대분류 폴더를 만들고, 그 안에 세부 폴더를 만들어서 저장하는 방식으로 하자. 이게 맞지 않아?"

**모호 포인트 해소** (`AskUserQuestion` 3문항):
1. CLAUDE.md 처리 → **완전 제거, README.md만** (얇은 CLAUDE.md 병행 기각)
2. `html/` 폴더(auto-rtt-viewer 사이트, 11+ 페이지) → **이번 범위에 포함**, 새 대분류 체계에 편입
3. 대분류 기준 → **도메인/주제 기준으로 전면 재편** (기존 문서유형 5분류인 프로젝트/학습/일상/참고/사용방법 이름만 유지 방안은 기각)

## 2. 목표

- 목표_1: `projects/wiki`의 운영 방침(동기화 트리거 모델, frontmatter 표준, 공개 검수 체크리스트, source 계약 등)을 루트 `docs/지침/` 체계로 완전히 이관 — wiki 프로젝트 자체엔 정책 문서를 남기지 않는다
- 목표_2: `projects/wiki/CLAUDE.md`·`AGENTS.md`를 제거하고 `projects/wiki/README.md`를 새 진입점으로 신설
- 목표_3: `html/`·`wiki vault/`의 전체 콘텐츠(약 45개 파일)를 문서 유형(프로젝트/학습/일상/참고/사용방법) 기준이 아니라 **도메인/주제**(Sound1, auto-rtt-viewer, ez8300-study, sound1-fw-extractor, AI 운영 등) 기준의 대분류 폴더로 재편하고, 그 안에 세부 폴더(예: Sound1/LED, Sound1/터치)를 둔다
- 목표_4: 재편 과정에서 기존 위키링크·git 이력이 최대한 보존되도록 한다(가능하면 `git mv`로 파일 이동, 링크 일괄 갱신)

## 3. 수용 기준 (Definition of Done)

### 3.1 기능·산출물
- [ ] 수용기준_1: `projects/wiki/CLAUDE.md`·`AGENTS.md` 삭제, `projects/wiki/README.md` 신설(새 폴더 구조 안내 + 루트 지침 링크)
- [ ] 수용기준_2: `projects/wiki/운영/`의 정책성 내용이 루트 `docs/지침/`에 이관되고, wiki 쪽엔 정책 문서가 남지 않음(로그성 데이터는 예외 검토)
- [ ] 수용기준_3: `html/`·`wiki vault/` 전체가 도메인 기준 대분류 폴더 구조로 재편
- [ ] 수용기준_4: 루트 `CLAUDE.md`의 wiki 프로젝트 행이 README.md를 가리키도록 갱신

### 3.2 정합성·검증
- [ ] broken wikilink 0건(재편 후 전수 검증)
- [ ] frontmatter `source_repo`·출처 표기가 새 경로와 일치
- [ ] `이력 및 결과.md` 시계열 로그 + 완료 요약 작성

### 3.3 회귀 방지
- [ ] 루트 `claude_feature_wiki-도메인재편`, wiki `claude_feature_wiki-도메인재편` 브랜치 격리(이미 생성됨)
- [ ] 파일 이동은 가능한 `git mv`로 이력 보존
- [ ] 각 commit이 atomic — 단계별 revert 가능

## 4. 작업 범위 외 (Out of Scope)

- 범위외_1: html 사이트 내부 디자인·콘텐츠 자체의 개선 — 이번엔 위치 이동만, 내용 리라이팅은 하지 않음
- 범위외_2: 기존 문서의 전체 공개 검수(민감정보 재확인) — 이관 시 경로만 갱신, 검수 체크리스트 자체는 루트로 옮기되 실제 재검수는 범위 외
- 범위외_3: 태그 대소문자 불일치 등 기존에 알려진 별도 이슈의 일괄 정정 — 계속 범위 외로 유지

## 5. 위임 범위 (Claude 자율 결정)

- 위임_1: 구체적 도메인 폴더명·세부 폴더 구조 설계
- 위임_2: 루트 지침 체계 내 이관 위치(어느 `docs/지침/` 파일에 통합할지)
- 위임_3: 파일 이동·링크 갱신 시 서브에이전트/Workflow 병렬 활용 여부(대용량 처리 실익 판단)
