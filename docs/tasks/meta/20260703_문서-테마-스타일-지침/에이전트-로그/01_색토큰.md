# 01_색토큰 — nofm 웜 페이퍼 뷰어 색상 변수 전량 추출

**TL;DR**: `:root`(라인 8~38)에 선언된 색상 CSS 변수는 정확히 **25종** — 배경 1·표면 3·텍스트 3·액센트 8(CIS 4+NofM 4)·semantic 6·기타 4. 전량 hex가 원본과 일치(이중 대조). 단 semantic 6종 중 4종(`--warn-bg`·`--danger-bg`·`--info-bg`·`--info-fg`)과 액센트 tint 6종(`--cis-tint-*`·`--nofm-tint-*`)은 **CSS `var()` 참조가 전무**하고, tint 6종은 JS(`CIS_PALETTE`/`NOFM_PALETTE`)에 동일 hex가 하드코딩 중복돼 있다 — SSOT 설계 시 유의 필요.

## 1. 검증 방법

1. `Read` 도구로 파일 라인 1~160 전문 확인 → `<style>` 블록(라인 7~138) 원문 확보.
2. `grep -n -- "--<변수명>\b"` 를 25개 변수명 전체에 대해 **파일 전체(682줄)** 스코프로 실행 — `:root` 선언 라인 + CSS `var()` 참조 + JS `cssVar()`(= `getComputedStyle().getPropertyValue()`) 참조까지 전부 포착.
3. JS 팔레트 객체(`CIS_PALETTE`/`NOFM_PALETTE`, 라인 289~290)의 하드코딩 hex를 `:root` 선언과 문자열 대조.
4. 결과: **25/25 hex 전량 원본과 일치**. 불일치·오타 0건.


## 3. 카테고리별 상세 — 역할·사용처

> [!IMPORTANT]
> **tint 6종 전부 CSS 규칙에서 `var()`로 참조되지 않는다.** `:root`에는 선언돼 있지만 실제 소비는 JS가 라인 289~290에서 동일 hex를 리터럴 배열로 재선언한 `CIS_PALETTE.tints`/`NOFM_PALETTE.tints`를 통해서만 이뤄진다. 즉 이 파일 안에 **같은 색값이 두 곳(CSS 변수 + JS 상수)에 중복 정의**돼 있다. SSOT 설계 시: (a) 원본의 이 이중 정의를 그대로 인정하고 지침에서도 "CSS 변수"와 "JS 팔레트 상수"를 별개 참조로 문서화하거나, (b) 새 지침에서는 애초에 이 중복을 지적하고 단일 출처화를 권고하는 두 옵션이 있음 — 계획 단계 판단 필요.

### 3.6 semantic (6종: warn/danger/info × bg/fg)

| 변수 | 역할 |
|---|---|
| `--warn-bg` | `#F7E7BE` — **선언만 되고 CSS·JS 어디에서도 미사용**(파일 전체에 `var(--warn-bg)` 참조 0건) |
| `--warn-fg` | `#7A5A0E` — `.duration-note`(96, duration 관련 경고 문구) 텍스트색으로 실사용 |
| `--danger-bg` | `#F4DCD0` — **선언만 되고 미사용** |
| `--danger-fg` | `#A23B22` — `.clamp-note`(109, 클램프 경고 강조) 텍스트색으로 실사용 |
| `--info-bg` | `#DEE9E3` — **선언만 되고 미사용** |
| `--info-fg` | `#2F5C50` — **선언만 되고 미사용** |

> [!NOTE]
> semantic 6종 중 절반(`bg` 3종 전부 + `info-fg`)이 이 파일에서 완전 미사용이다. `warn-fg`·`danger-fg`만 실제로 소비되고, `info-*` 그룹은 hex 정의조차 어디서도 참조되지 않는다 — 이 문서 하나만으로는 "배지/배너 컴포넌트"의 실제 배경(bg) 적용례를 확인할 수 없다(향후 알림·배지 UI 확장을 대비한 예약 토큰으로 추정). SSOT 지침에는 포함하되 "정의됨/미사용" 상태를 명시하는 편이 정확하다.

### 3.7 기타 (4종: idle·gridline·baseline)

| 변수 | 역할 |
|---|---|
| `--gridline` | 옅은 구분선. 슬라이더 트랙(69)·`.stats` 그리드 갭(99)·`.tl-row` 하단 구분선(121)·`.row-label` 우측 경계(125) — CSS `var()` 직접 참조 다수. JS 캔버스 눈금자 세로선(`ctx.strokeStyle`, 309)에도 재사용 |
| `--baseline` | `#CBB999` — **CSS 규칙에서 `var()` 참조 0건.** JS `cssVar("--baseline")`(487)로만 소비 — 캔버스 펄스 로우(자극 파형)의 기준 가로선(0-레벨선) 색상 |
| `--idle-fill` | `#C7C0B0` — **CSS 규칙 미사용.** JS `cssVar("--idle-fill")`(325)로 캔버스 유휴(idle/NOP) 슬롯 채우기색 |
| `--idle-border` | `#AAA089` — **CSS 규칙 미사용.** JS `cssVar("--idle-border")`(325)로 유휴 슬롯 테두리색 |

> [!NOTE]
> `--baseline`·`--idle-fill`·`--idle-border` 3종은 **CSS 안에서는 존재감이 없고 오직 JS `cssVar()`(= `getComputedStyle(document.documentElement).getPropertyValue(name)`) 브릿지를 통해서만** 소비된다. `:root` 커스텀 프로퍼티를 "CSS에 쓰려고" 선언한 게 아니라 "JS 캔버스 렌더러가 테마색을 읽어가는 단일 출처"로 쓰는 의도적 패턴으로 보인다 — 캔버스는 `<style>`을 직접 참조할 수 없어 이 브릿지가 필요.

## 4. 부수 발견 — 변수 외 하드코딩 색상 (참고용, 카운트 25종에는 불포함)

`<style>` 블록(라인 7~138) 안에 CSS 변수가 아닌 리터럴 색상이 2곳 있다. 둘 다 `--text-primary`(`#33291C` = `rgb(51,41,28)`)의 RGB 등가치에 알파를 입힌 값이다.

| 위치 | 값 | 용도 |
|---|---|---|
| 라인 132 | `rgba(51,41,28,.18)` | `#tooltip` `box-shadow` |
| 라인 370(JS, 참고) | `rgba(51,41,28,0.28)` | 캔버스 채널 슬롯 내부 분할선 |

CSS `var()`는 알파 채널을 직접 합성할 수 없어(`color-mix()` 등 미사용) 불가피하게 RGB값을 재하드코딩한 것으로 보인다. 신규 지침에서 알파 블렌딩이 필요하면 `--text-primary-rgb: 51,41,28` 같은 별도 RGB 트리플 변수를 함께 정의하는 편이 이런 재하드코딩을 줄인다는 시사점.

## 5. SSOT 설계 참고용 요약

| 상태 | 변수 수 | 목록 |
|---|---|---|
| CSS `var()`로 활발히 소비 | 15 | page-plane·surface-1·card-bg·card-border·gridline·text-primary·text-secondary·text-muted·cis-accent·nofm-accent·warn-fg·danger-fg (+ 슬라이더 트랙 등 다수 재사용) |
| CSS 미사용, JS `cssVar()` 브릿지로만 소비 | 3 | baseline·idle-fill·idle-border |
| CSS `var()` 미참조, JS에 동일 hex 별도 하드코딩(중복) | 6 | cis-tint-1/2/3·nofm-tint-1/2/3 |
| 완전 미사용(정의만 존재) | 4 | warn-bg·danger-bg·info-bg·info-fg |
| 합계 | **25** | — |

**시사점**: 다운스트림 색 토큰 SSOT 지침(02·03·04·05 노드 및 계획 단계)은 25종을 전부 명세에 싣되, "활성/브릿지전용/미사용" 상태 라벨을 함께 기재하는 편이 원본의 실제 소비 패턴을 왜곡 없이 반영한다. 특히 tint 6종의 JS 이중 정의는 재사용 스니펫 작성 시 "CSS 변수만 복사하면 캔버스 팔레트가 안 딸려온다"는 함정으로 이어질 수 있어 04(HTML 적용) 산출물에서 명시적으로 다뤄야 한다.
