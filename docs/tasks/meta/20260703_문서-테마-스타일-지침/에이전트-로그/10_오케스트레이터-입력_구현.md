# 오케스트레이터 입력 — 구현 fan-out

**TL;DR**: 계획 승인 후 지침 4파일 신설 + 정합 3파일. 인덱스(토큰 SSOT) 선행 → 테마/ 3트랙 병렬 → 정합 3 병렬 → 검증. Sonnet·effort max.

## 원본 입력

> "승인해, ④ 구현 진행해" (은수님, 2026-07-03 — 계획.md 승인)

## 요구 해석

계획.md 확정 설계대로 구현. 핵심 의존: 토큰 SSOT(액센트 accent-1/2 재명명·자체완결 hex)가 3트랙보다 먼저 확정돼야 참조 정합. 저술은 위임, 토큰 확정 판단·검증·커밋은 오케스트레이터(§1.1).

## 위임 설계 근거

- [x] 왜 이 분해인가 — Step 1 인덱스(SSOT) 1노드 선행(순차 의존), Step 2 테마/ 3트랙은 인덱스 참조하는 독립 저술이라 병렬, Step 3 정합 3파일 독립 병렬, Step 4 검증 3노드(hex·링크·adversarial 정합).
- [x] 어떤 패턴·왜 — pipeline 성격(Step1→2→3→4 단계 의존) 내부에 각 단계 parallel. Step4는 adversarial-verify 포함.
- [x] 모델·effort — 전 노드 Sonnet · max(지침 SSOT 정밀·복붙 코드 정확성).
