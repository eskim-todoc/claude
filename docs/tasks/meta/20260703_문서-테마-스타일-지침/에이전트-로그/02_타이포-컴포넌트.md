# 02_타이포·컴포넌트 — nofm 뷰어 비색상 디자인 요소 추출

**TL;DR**: `nofm-output-pattern-viewer.html`(L7~138)에서 색을 제외한 디자인 요소를 추출했다. font-size는 9~17px 좁은 대역에 0.5px 단위 미세조정(11.5px·12.5px)을 쓰는 비-모듈러 스케일이며, border-radius는 6px(컨트롤)·10px(점선 주석)·12px(실선 카드)·50%(원형) 4단 체계, border 스타일은 solid=구조/dashed=보조주석으로 의미가 갈린다. 컴포넌트는 헤더·컨트롤(슬라이더+숫자입력)·stats 그리드(헤어라인 기법)·패널타이틀+dot뱃지·note/disabled-msg·타임라인 행(양축 sticky)·툴팁 7종으로 정리했다.

## 1. 타이포그래피

### 1.1 font-family

```css
font-family: system-ui, -apple-system, "Segoe UI", "Pretendard", "Noto Sans KR", sans-serif;
```

- `body`에 단 1회 선언, 전체가 상속 — 컴포넌트별 개별 font-family override 없음(단일 폰트 패밀리 원칙).
- 스택 순서 의도: OS 네이티브 시스템 폰트(웹폰트 로딩 없이 즉시 렌더 + 플랫폼 고유감) 우선 → 한글 글리프 커버리지용 Pretendard(시스템 폰트풍 오픈소스 한글 폰트) → Noto Sans KR(광범위 폴백) → sans-serif 최종 폴백.
- 모노스페이스 폰트는 전혀 쓰지 않음 — 숫자 정렬은 `font-variant-numeric: tabular-nums`(§1.4)로 해결.

### 1.2 font-size 스케일 (오름차순)

| 크기 | 사용처 | font-weight | 비고 |
|---|---|---|---|
| 9px | `.nofm-limit-mark::after`(슬라이더 위 마커 캡션) | 기본(400) | 파일 내 최소 — 데코레이션성 초소형 라벨 |
| 11px | `.controls-secondary label`, `.duration-note` | 500 / 기본 | 보조 컨트롤 라벨·경고 각주 |
| 11.5px | `.row-label`(타임라인 고정 라벨열) | 기본 | 0.5px 단위 미세조정 |
| 12px | `header .sub`, `.controls label`(주 컨트롤), `.unit`, `#tooltip` | 기본 / 600 | 가장 널리 재사용되는 "보조 텍스트" 기준 크기 |
| 12.5px | `.note` | 기본 | 0.5px 단위 미세조정 |
| 13px | `.stats`(그리드 기본), `.clamp-note`, `.disabled-msg` | 기본 / 700 | 본문·데이터 셀 기준 크기 |
| 15px | `.panel-title` | 700 | 섹션 타이틀 |
| 17px | `header h1` | 브라우저 기본(h1 bold 상속, 별도 지정 없음) | 파일 내 최대 — 그래도 일반 웹 h1(24~32px)보다 훨씬 작음 |

**핵심 관찰**: 9~17px라는 좁은 대역 안에서 0.5px 단위(11.5px·12.5px) 미세조정을 쓰는 **비-모듈러 스케일**이다. 4px/8px 배수 같은 정형 스케일이 아니라 눈으로 맞춘 값들 — 데이터 밀도가 높은 계기판/뷰어형 UI의 전형적 특징. 다른 문서에 이식할 때는 "12px=보조 텍스트, 13px=본문/데이터, 15px=섹션 타이틀, 17px=페이지 타이틀"의 **4단 실사용 계층**으로 단순화해 적용 가능.

### 1.3 font-weight 계층

| weight | 사용처 | 의미 |
|---|---|---|
| 500 | `.controls-secondary label` | 보조/부차 라벨 — 가장 약한 강조 |
| 기본(400) | 본문, `.note`, `.stats` 데이터 셀, `.duration-note` | 일반 텍스트 |
| 600 | `.controls label`(주 컨트롤) | 주 컨트롤 라벨 — 크기(12px)는 같아도 weight로 보조 라벨과 구분 |
| 700(bold) | `.stats .head`, `.panel-title`, `.clamp-note` | 헤더·타이틀·경고성 강조 |

크기를 키우지 않고 weight·색만으로 위계를 만드는 지점이 특징적이다. 예컨대 주 라벨(12px/600)과 보조 라벨(11px/500)은 크기 차 1px + weight 차 100 + 색 차(secondary→muted) 세 축을 동시에 미세하게 벌려 위계를 준다.

### 1.4 font-variant-numeric

```css
.controls input[type=number], .controls select {
  font-variant-numeric: tabular-nums;
}
```

- 숫자 입력·select에만 적용. 슬라이더 조작 중 실시간으로 바뀌는 숫자가 고정폭 자릿수로 렌더되어 자리이동(jitter)이 없게 하는 목적 — 라이브 수치 HUD 성격의 뷰어에 핵심적인 디테일.
- `.stats` 데이터 셀(마찬가지로 실시간 갱신되는 숫자)에는 미적용 — 이식 시 "동적으로 바뀌는 숫자를 보여주는 모든 요소"로 확장 적용을 권장할 만한 지점(원본의 잠재적 사각지대).

### 1.5 명시적으로 쓰지 않은 것

line-height·letter-spacing·text-transform 오버라이드가 전무하다 — 대문자 라벨(uppercase 캡션) 같은 흔한 대시보드 기법도 없음. 위계는 오직 **크기·굵기·색** 세 축으로만 만든다는 절제된 원칙. 이식 시에도 이 "조용한" 타이포 원칙(케이스 변형·자간 조정 금지)을 지키는 편이 스타일 일관성에 중요하다.

## 2. 간격·모서리·보더

### 2.1 border-radius 4단 체계

| radius | 사용처 | 계층 의미 |
|---|---|---|
| 1px | `.nofm-limit-mark`(2px 폭 세로 바) | 얇은 바의 미세 라운딩 |
| 2px | 슬라이더 트랙(`.duration-slider-wrap input[type=range]`) | 얇은 트랙(pill) |
| 6px | `input[type=number]`·`select`·`#tooltip` | **"컨트롤/칩" 티어** — 작은 UI 크롬 |
| 10px | `.note`·`.disabled-msg` | **"점선 주석" 티어** — 보조 설명 박스 |
| 12px | `.controls`·`.stats`·`.scrollwrap` | **"카드/컨테이너" 티어** — 구조적 박스 |
| 50% | 슬라이더 thumb(16px)·`.dot`(11px) | 원형 요소 |

3단(6/10/12px) + 원형(50%) + 초박형 요소용 1~2px로 정리된다. 재사용 규칙: **작을수록(6px) UI 부품, 중간(10px)은 점선 주석 박스, 클수록(12px) 실선 구조 컨테이너.**

### 2.2 border 스타일 의미 분화

| 스타일 | 토큰 | 사용처 | 의미 |
|---|---|---|---|
| `1px solid var(--card-border)` | card-border | header 하단, `.controls`, `.stats` 외곽, `.scrollwrap`, `#tooltip`, input/select | **구조적 컨테이너** 경계 |
| `1px dashed var(--card-border)` | card-border(동일 토큰, 스타일만 dashed) | `.note`, `.disabled-msg` | **보조/주석성** 박스 — solid와 색은 같지만 실선→점선 전환만으로 "덜 구조적"임을 신호 |
| `1px solid var(--gridline)` | gridline(더 옅은 별도 토큰) | `.tl-row` 하단, `.row-label` 우측 | **내부 반복 구분선** — 외곽 경계보다 약한 톤의 전용 토큰 사용 |
| `2px solid var(--card-bg)` | card-bg(표면색을 보더로) | 슬라이더 thumb | **컷아웃 링 효과** — 보더 색을 배경색과 같게 써서 accent 채움 주위에 "구멍 뚫린" 여백 링 생성 |

같은 색 토큰(`--card-border`)이라도 solid/dashed 전환만으로 "구조 vs 주석"의 의미를 나눈 것이 재사용 가치가 큰 패턴이다.

### 2.3 padding 리듬

| 요소 | padding | 비율(수직:수평) |
|---|---|---|
| `.controls`(카드) | 18px(균일) | 1:1 |
| `.disabled-msg` | 16px(균일) | 1:1 |
| header | 16px 24px | 1:1.5 |
| main | 18px 24px | 1:1.33 |
| `.note` | 10px 14px | 1:1.4 |
| `.stats > div` | 9px 14px | 1:1.56 |
| `#tooltip` | 6px 10px | 1:1.67 |
| input/select | 5px 6px | 1:1.2 |
| `.row-label` | 4px 10px | 1:2.5(flex 수직 중앙정렬이라 수직 패딩 최소화) |

가장 바깥의 "박스형" 컨테이너(`.controls`, `.disabled-msg`)만 균일 패딩을 쓰고, 안쪽 텍스트 요소로 갈수록 수평이 수직의 1.2~2.5배인 "넓고 낮은" 패딩 비율을 쓴다.

### 2.4 gap·margin

- flex/grid gap 크기 순: `.controls-primary` 28px(그룹 내부가 그룹 간보다 넓음) > `.controls` 최상위 24px > `.controls-secondary` 18px > header 12px > `.panel-title` 10px > `.field-row` 8px > `.stats` 그리드 1px(헤어라인 기법용, §3.3).
- margin-bottom 스케일: `.controls` 16px < `.stats` 18px < `.panel` 26px — 섹션이 커질수록(컨트롤 < 통계 < 패널) 하단 여백도 커지는 시각적 리듬.
- `.tl-row:last-child { border-bottom: none; }` — 리스트 마지막 요소 구분선을 제거하는 표준 기법.

## 3. 컴포넌트 패턴

### 3.1 헤더 (sticky, baseline 정렬)

```css
header {
  display: flex; align-items: baseline; gap: 12px;
  padding: 16px 24px; border-bottom: 1px solid var(--card-border);
  position: sticky; top: 0; z-index: 20;
}
header h1 { font-size: 17px; margin: 0; }
header .sub { font-size: 12px; color: var(--text-muted); }
```

- `align-items: baseline`(center 아님) — 제목(17px)과 부제(12px)의 텍스트 베이스라인을 맞춰, 크기 차가 나는 두 텍스트를 나란히 놓을 때 자연스러운 정렬을 만드는 디테일.
- `position: sticky; top: 0` + `z-index: 20`으로 스크롤 시 상단 고정.

### 3.2 컨트롤 (슬라이더 + 숫자 입력 조합)

```css
.controls {
  display: flex; align-items: center; flex-wrap: wrap; gap: 24px;
  border: 1px solid var(--card-border); border-radius: 12px; padding: 18px; margin-bottom: 16px;
}
.controls-primary { display: flex; gap: 28px; flex: 1 1 auto; flex-wrap: wrap; }
.controls-secondary { display: flex; gap: 18px; margin-left: auto; }
```

- 외곽은 카드 티어(12px radius). 내부는 **주 컨트롤군**(`-primary`, 넓은 28px gap, flex-grow)과 **보조 컨트롤군**(`-secondary`, 좁은 18px gap, `margin-left: auto`로 우측 정렬)으로 2분할 — 위치·간격·크기·색 4축 모두로 주/보조 위계를 강조.
- 라벨 구조: `label`(블록) > `.field-row`(flex, gap 8px, margin-top 6px) > input + `.unit` 접미사 span.
- 슬라이더 폭은 컨텍스트별로 다르게 고정(주 채널 슬라이더 `#kRange` 130px, 보조 필터류 90px) — 대상 값의 범위 감각에 맞춘 시각적 크기 조정.

**네이티브 range 슬라이더 재스타일링**:

```css
.duration-slider-wrap input[type=range] {
  -webkit-appearance: none; appearance: none;
  height: 4px; border-radius: 2px; outline: none; margin: 0;
}
.duration-slider-wrap input[type=range]::-webkit-slider-thumb {
  -webkit-appearance: none; width: 16px; height: 16px; border-radius: 50%;
  border: 2px solid var(--card-bg); margin-top: -6px; /* 트랙(4px) 대비 썸(16px) 높이차 보정 */
}
.duration-slider-wrap input[type=range]::-moz-range-thumb {
  width: 16px; height: 16px; border-radius: 50%; border: 2px solid var(--card-bg);
  /* margin-top 없음 — Firefox는 트랙 박스 모델이 달라 webkit 같은 수직보정 불필요 */
}
```

- 트랙 4px + thumb 16px 원형. webkit thumb만 `margin-top: -6px`로 트랙 중앙에 세로 정렬(코드 주석에 보정값 근거 명시 — 트랙/thumb 크기가 바뀌면 `(thumb-track)/2`로 재계산). `::-moz-range-thumb`엔 이 보정이 없어 브라우저별 미묘한 차이가 그대로 코드에 남아있다.
- thumb 보더 2px는 배경색과 같은 색(card-bg)을 써서 "컷아웃 링" 효과를 만듦.
- webkit/moz 두 벤더 프리픽스 셀렉터에 동일 계열 규칙을 중복 선언해야 크로스브라우저 일관성이 나옴(하나의 selector로 묶을 수 없는 네이티브 슬라이더의 제약).

**슬라이더 위 오버레이 마커**(임계값 표시):

```css
.nofm-limit-mark {
  position: absolute; top: 50%; transform: translate(-50%, -50%);
  width: 2px; height: 16px; pointer-events: none; border-radius: 1px;
}
.nofm-limit-mark::after {
  content: "NofM 한계"; position: absolute; top: -15px; left: 50%; transform: translateX(-50%);
  font-size: 9px; white-space: nowrap;
}
```

- `pointer-events: none`으로 마커가 슬라이더 조작을 가로막지 않게 함.
- `left` 값은 CSS가 아니라 JS(`positionNofmLimitMark`, HTML 주석에 명시)가 실제 thumb 위치를 px로 계산해 인라인 스타일로 지정 — 네이티브 range는 % 위치가 thumb의 실제 이동 가능 범위(트랙 양끝 padding 보정)와 선형으로 일치하지 않기 때문. "네이티브 슬라이더에 정밀 랜드마크를 얹는" 재사용 가능 기법이며, CSS만으로는 풀 수 없고 JS 병행이 필수임을 코드 주석으로 문서화해둔 사례.
- `::after`로 9px 초소형 캡션을 마커 위에 얹는 라벨링 기법.

**숫자 입력**: `width: 68px; padding: 5px 6px; border-radius: 6px; font-variant-numeric: tabular-nums;` — 고정 폭 + tabular-nums로 슬라이더 연동 시 자리 흔들림을 방지.

### 3.3 Stats 비교 그리드 (헤어라인 기법)

```css
.stats {
  display: grid; grid-template-columns: 170px 1fr 1fr; gap: 1px;
  background: var(--gridline); border: 1px solid var(--card-border); border-radius: 12px;
  overflow: hidden; font-size: 13px;
}
.stats > div { background: var(--card-bg); padding: 9px 14px; min-width: 0; }
.stats .head { font-weight: 700; background: var(--surface-1); }
```

- **고정 라벨열(170px) + N개 균등 데이터열(`1fr` 반복)** — "지표명 | 시리즈A | 시리즈B…" 비교 테이블에 바로 재사용 가능한 그리드 골격.
- **헤어라인 구분선 기법**: 그리드 자체 배경을 구분선색(gridline)으로 깔고 `gap: 1px`만 주면 셀 사이 1px 틈으로 그 배경이 비쳐 나와, 셀마다 개별 border 선언 없이도 격자선처럼 보인다. 코드가 매우 간결해지는 실용적 트릭.
- `border-radius: 12px` + `overflow: hidden`을 그리드(부모)에만 주면 사각형 자식 셀들이 부모의 둥근 모서리에 맞춰 잘려나감 — "각진 자식 다수를 가진 컨테이너를 통째로 둥글리는" 표준 기법.
- 헤더 행은 크기를 키우지 않고 **weight(700) + 배경(surface-1, 데이터 행의 card-bg보다 밝음)만으로** 구분.
- `min-width: 0`은 그리드/플렉스 아이템의 콘텐츠 기반 최소폭이 트랙을 밀어내는 현상을 막는 필수 방어 선언(좁은 열에서 자주 누락되는 부분).

### 3.4 패널 타이틀 + dot 뱃지

```css
.panel-title { display: flex; align-items: center; gap: 10px; font-size: 15px; font-weight: 700; margin: 0 0 10px; }
.dot { width: 11px; height: 11px; border-radius: 50%; display: inline-block; }
.clamp-note { font-weight: 700; font-size: 13px; }
```

- `.dot`은 색만 모디파이어 클래스(`.dot.cis`/`.dot.nofm`)로 주입하는 범용 "범례 스와치" — 11px 원, `display: inline-block`으로 텍스트 흐름에 자연스럽게 섞임. 카테고리 범례가 필요한 어디에나 재사용 가능한 최소 단위 컴포넌트.
- 타이틀 줄 끝에 `.clamp-note`(13px/700) 같은 인라인 경고를 같은 줄에 자연스럽게 이어붙이는 구조(같은 `<p>` 안에 `<span>`으로 추가) — 줄바꿈 없이 상태 경고를 타이틀에 붙이는 패턴.

### 3.5 Note / 빈 상태(disabled) 메시지

```css
.note {
  font-size: 12.5px; background: var(--card-bg);
  border: 1px dashed var(--card-border); border-radius: 10px; padding: 10px 14px; margin: 8px 0 12px;
}
.disabled-msg {
  padding: 16px; font-size: 13px; background: var(--surface-1);
  border: 1px dashed var(--card-border); border-radius: 10px; text-align: center;
}
```

- 둘 다 "점선 보더 + 10px radius" 패밀리 — §2.2에서 정리한 대로 dashed는 "구조가 아니라 보조 설명/상태"라는 신호.
- `.note`는 콘텐츠 흐름 안에 좌측 정렬로 끼워지는 각주형, `.disabled-msg`는 `text-align: center` + 더 큰 패딩(16px)으로 **빈 상태 placeholder**(데이터가 없을 때 패널 전체를 대체) 용도로 분화.

### 3.6 타임라인 행 — 양축 sticky (스크롤 매트릭스)

```css
.scrollwrap { overflow-x: auto; border: 1px solid var(--card-border); border-radius: 12px; }
.tl-row { display: flex; align-items: stretch; border-bottom: 1px solid var(--gridline); }
.tl-row:last-child { border-bottom: none; }
.row-label {
  position: sticky; left: 0; z-index: 2; flex: 0 0 132px; width: 132px;
  border-right: 1px solid var(--gridline); font-size: 11.5px; padding: 4px 10px;
  display: flex; align-items: center;
}
canvas.tl-canvas { display: block; cursor: crosshair; }
```

- header가 `top: 0` sticky(수직 고정)인 것과 짝을 이뤄, `.row-label`은 `left: 0` sticky(수평 고정) — **두 축을 각각 다른 컴포넌트에서 독립적으로 sticky 처리**해 가로·세로 모두 스크롤되는 매트릭스에서도 헤더 행과 라벨 열이 항상 보이게 하는 조합 기법.
- z-index 계층: `.row-label`(2) < header(20) < `#tooltip`(50) — 겹침 순서가 "고정 열 < 고정 헤더 < 플로팅 툴팁" 순으로 명확히 분리되어 있음. 재사용 시 이 3단 z-index 스케일을 그대로 채택 가능.
- `cursor: crosshair`는 캔버스가 정밀 좌표 클릭/호버 대상임을 알려주는 어포던스.

### 3.7 툴팁

```css
#tooltip {
  position: fixed; pointer-events: none; z-index: 50;
  border: 1px solid var(--card-border); border-radius: 6px; padding: 6px 10px; font-size: 12px;
  box-shadow: 0 4px 14px rgba(51,41,28,.18); display: none; white-space: nowrap;
}
```

- `position: fixed` + `pointer-events: none`: 마우스 좌표를 따라다니면서도 정작 그 마우스 이벤트 자체를 가로채지 않는 필수 조합.
- radius 6px — 카드 티어(12px)가 아니라 **컨트롤 티어**를 사용, 툴팁이 "작은 UI 칩"으로 취급됨을 보여줌.
- `white-space: nowrap`으로 내용이 바뀌어도 줄바꿈에 의한 레이아웃 흔들림을 방지.
- box-shadow는 순수 검정이 아니라 잉크색(`--text-primary` #33291C → rgb(51,41,28))에 낮은 알파(.18)를 준 값 — 그림자를 배경색이 아닌 텍스트/잉크색 계열로 틴트하는 기법(정확한 색상 자체는 이 문서 범위 밖이지만, "offset 0 4px / blur 14px / alpha ~0.18의 부드러운 elevation 형태"는 비색상 패턴으로 재사용 가치가 있음).
- `display: none`이 기본값이고 JS가 토글 — 인라인 스타일이 아니라 style 속성 전환으로 노출.

## 4. 교차 관찰 (재사용 시 참고)

- **z-index 3단 스케일**: 2(고정 열) < 20(고정 헤더) < 50(플로팅 툴팁) — 임의의 큰 숫자(999 등)를 안 쓰고 실제 필요한 최소 계층만 촘촘하게 배정.
- **elevation(표면) 네이밍 아키텍처**: `--page-plane`(페이지 배경) → `--surface-1`(헤더·인풋 등 옅은 표면) → `--card-bg`(카드·팝오버 등 가장 위 표면)로 이름 자체가 3단 elevation을 서술 — 정확한 hex 값은 색 축(01번 노드 범위)이지만, **토큰 네이밍 체계** 자체는 이 문서에서 다루는 비색상 아키텍처 패턴으로 재사용 가치가 있음.
- **`* { box-sizing: border-box; }`**: 전역 리셋 1줄 — 이후 모든 padding/border 계산이 width에 포함되는 것을 전제로 위 모든 수치(68px 인풋, 132px 라벨열 등)가 설계됨.
- **`body { margin: 0; padding-bottom: 40px; }`**: 마지막 섹션에 개별 margin을 주는 대신 `body`에 하단 여백을 몰아주는 방식 — 마지막 자식 margin collapse 이슈를 원천 차단.
- **font-variant-numeric 확장 여지**: 현재 input/select에만 적용, `.stats` 데이터 셀처럼 실시간 갱신되는 다른 숫자 표시 영역엔 미적용 — 이식 시 "동적 숫자를 표시하는 모든 요소"로 일괄 확장하는 편이 일관적.
