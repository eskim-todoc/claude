# 오케스트레이터 입력 — 분석 fan-out

**TL;DR**: nofm HTML 웜 페이퍼 테마를 재사용 가능한 디자인 시스템으로 지침화하기 위한 현황 분석 — 5노드 fan-out(색 토큰·타이포/컴포넌트·Mermaid 매핑·Obsidian 매핑 parallel + adversarial 정합), Sonnet·effort max.

## 원본 입력

> "projects/Sound1/docs/참고/nofm/정리/nofm-output-pattern-viewer.html 의 문서 테마 스타일이 내가 원하는 테마 스타일이야. html 뿐만 아니라 기타 다른 문서에서도 이 스타일을 적용할 수 있게 지침을 업데이트 해줘."

`AskUserQuestion` 확정: 적용 대상 4종 전부(HTML·Mermaid·Obsidian·토큰 명세), 루트 전역 지침 위치.

## 요구 해석

은수님이 특정 HTML의 룩앤필(웜 페이퍼: 크림 배경·다크 브라운 텍스트·테라코타+틸 액센트)을 마음에 들어 하고, 이를 프로젝트 횡단 재사용 자산으로 만들고 싶어함. MD는 GitHub/Obsidian이 렌더를 제어하므로 "적용"의 의미가 대상마다 다름 → 토큰 명세를 SSOT로 두고 대상별 적용 기법을 각각 제시하는 구조가 최적. 요구 해석·범위 확정은 오케스트레이터 직접(§1.1), 토큰 추출·매핑 기법 조사는 위임.

## 위임 설계 근거

- [x] 왜 이 분해(5개 노드)인가 — 산출물이 4종 적용을 요구하는데, (1)색 토큰과 (2)타이포·컴포넌트는 추출 성격이 달라 분리, (3)Mermaid·(4)Obsidian은 각기 다른 매핑 기법 조사라 독립. 여기에 4종 간 충돌·중복·다크모드·GitHub 렌더 현실을 반증하는 (5)adversarial 정합 노드 추가.
- [x] 어떤 패턴·왜 — **parallel(A~D 추출·매핑) + adversarial-verify(E 정합)**. A~D는 상호 독립 조사라 배리어 병렬, E는 4결과를 받아 "토큰 명세만" 옵션의 중복성·Mermaid 팔레트가 §4.3 기존 정책과 충돌하는지·라이트 단일 테마의 다크모드 공백을 반증 시도.
- [x] 모델·effort 배분·왜 — 전 노드 Sonnet · max. 지침 SSOT가 될 정밀 추출·매핑이라 최고 effort(전면 위임 정책).
