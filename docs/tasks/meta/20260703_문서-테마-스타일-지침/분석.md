# 분석: 문서 테마 스타일 지침

**TL;DR**: 분석 fan-out 5노드(Sonnet max, 659K 토큰) 결과 — 색 토큰 25종·타이포/컴포넌트·Mermaid/Obsidian 매핑을 추출하고 adversarial 정합이 핵심 쟁점 6건을 잡았다. 결정: 액센트 역할 기반 재명명(도메인 무관), 인덱스+`테마/` 4파일 분할, 토큰 명세 자체완결(원본 링크는 각주), Mermaid stroke=잉크·액센트(대비 안전), 라이트 전용(트랙별 명시), 기존 §4.3.2 WCAG 결함은 별도 후속. 상세 raw 분석은 [`에이전트-로그/`](에이전트-로그/) 01~05.

## 1. 현 상태 (Current State)

원본 `projects/Sound1/docs/참고/nofm/정리/nofm-output-pattern-viewer.html`(682줄, self-contained). 웜 페이퍼 라이트 테마.

### 1.1 색 토큰 25종 (노드 01, hex 전량 원본 일치)
| 범주 | 개수 | 대표 |
|---|---|---|
| 배경 | 1 | `--page-plane #EFE7D6` |
| 표면 | 3 | `--surface-1 #FAF5EA`·`--card-bg #FBF7EE`·`--card-border #E2D5BC` |
| 텍스트 | 3 | primary `#33291C`·secondary `#6B5C46`·muted `#6E5F48` |
| 액센트 | 8 | cis(테라코타 `#C15F3C`+tint3)·nofm(틸 `#3E6E64`+tint3) |
| semantic | 6 | warn/danger/info × bg·fg |
| 기타 | 4 | gridline·baseline·idle-fill·idle-border |

특이점: tint 6종은 CSS 미참조(JS 하드코딩 중복), semantic 4종(warn-bg·danger-bg·info-bg·info-fg) 미사용, baseline·idle 3종은 JS 캔버스 전용.

### 1.2 타이포·컴포넌트 (노드 02)
- font-family `system-ui, -apple-system, "Segoe UI", "Pretendard", "Noto Sans KR", sans-serif`, 모노 미사용
- font-size 9~17px 9단(비-모듈러, 0.5px 미세조정), weight 4단(400/500/600/700 — 크기 대신 weight+색으로 위계)
- radius 4단: 6px(컨트롤)·10px(주석)·12px(카드)·50%(원형), border **solid=구조 / dashed=주석**, gridline=옅은 내부 구분선
- 컴포넌트 7종: 헤더(sticky)·컨트롤 카드·stats 헤어라인 그리드(gap:1px 트릭)·panel-title+dot 뱃지·note/disabled-msg(점선)·타임라인 양축 sticky·tooltip

### 1.3 Mermaid 매핑 (노드 03, WCAG 실측)
- 2경로: `%%{init:{'theme':'base','themeVariables':{...}}}%%` + flowchart `classDef`. 4개 예시 렌더 valid
- **핵심 발견**: "옅은 구분선용" 토큰(card-border·gridline 등)을 노드 3px stroke에 쓰면 대비 1.13~1.56:1 실패 → stroke를 잉크·액센트 계열로 교정 시 3.26~7.86:1 확보
- 기존 `작성-스타일.md` 관계: §4.3.1(8요소 구조)=색 무관 **무충돌** / §4.3.2(5색표)=**같은 슬롯 대체 팔레트** / §4.5(라벨 안전)=**보완**

### 1.4 Obsidian 매핑 (노드 04)
- `.theme-light` 스니펫 3계층(표준 46 + 콜아웃 15 + Things 테마 보강 17)
- wiki Vault 주의 3건: (1) 현재 베이스 스킴 **dark** → 라이트 전환 선행 필수, (2) Things 테마 커스텀 변수(H3~H5·태그), (3) 기존 `wiki-site.css`(cool blue)와 팔레트 혼재 가능

## 3. 가설·선택지

### 3.2 선택지 (설계 결정)

**쟁점 A: 액센트 명명 — 원본명(cis/nofm) 계승 vs 역할 기반 재명명?**
| 선택지 | 장점 | 단점 |
|---|---|---|
| `--cis-accent`/`--nofm-accent` 계승 | 원본 추적 쉬움 | Sound1 도메인 약어 — "도메인 무관 전역 스타일" 목표와 배치, 트랙마다 역할 재해석 위험 |
| **역할 기반 `--accent-1`/`--accent-2` (채택)** | 도메인 무관, SSOT가 역할 1개로 고정 | 원본과 이름 다름(매핑 주석으로 해소) |

**결정: 역할 기반 재명명** — `--accent-1`(테라코타 `#C15F3C`, 주 액센트: 강조·인터랙티브·링크)·`--accent-2`(틸 `#3E6E64`, 보조 액센트), tint는 `--accent-1-tint-1/2/3`. 토큰 표에 원본(cis/nofm) 매핑 주석. Mermaid·Obsidian은 이 역할 정의에 종속(adversarial 충돌_1 해소).

**쟁점 B: 파일 구조 — 단일 vs 인덱스+하위?** (adversarial file_structure_rec)
| 선택지 | 장점 | 단점 |
|---|---|---|
| 단일 파일 | 파일 1개 | raw 분석만 1123줄(작성-스타일.md의 2.3배) — 4트랙 복붙 코드 담기 부적합 |
| **인덱스+`테마/` (채택)** | `일반/문서/`·`일반/작업/` 3레벨 분할 선례 정합 | 파일 수 증가 |

**결정: 인덱스+하위 4파일** — `문서 테마 스타일.md`(인덱스=개요+토큰 SSOT+GitHub 렌더+유지보수) + `테마/{HTML-아티팩트, Mermaid, Obsidian}.md`. README 생략(5파일 미만). 토큰 SSOT는 인덱스에 흡수(모든 트랙이 참조하는 핵심이라 최상위).

## 4. 핵심 결정

- 결정_1: **토큰 SSOT 자체완결** — 인덱스에 25색 전량 인라인 hex 표(범주·역할·사용상태) + 타이포/간격/컴포넌트 토큰. 원본 HTML은 각주 링크만(gitignored Sound1 repo라 루트 단독 클론 시 깨짐 — adversarial 충돌_4)
- 결정_2: **액센트 역할 1개 고정** — accent-1/accent-2 재명명, Mermaid·Obsidian 종속(§3.2 쟁점 A)
- 결정_3: **인덱스+테마/ 4파일** (§3.2 쟁점 B) + 작성-스타일.md §4.3.2에 짧은 앵커만(전문 복제 금지 — 정책 stale 방지)
- 결정_4: **Mermaid stroke=잉크·액센트** 원칙 명문화(대비 안전), 선택 기준 기계화 — frontmatter `theme: warm-paper` 필드 있을 때만 웜 팔레트 전환(§7.2 if-then 준수)
- 결정_5: **라이트 전용**(사용자 결정) — 트랙별 명시: Mermaid `darkMode:false` 고정(§4.3.1 요소⑤ 정합)·Artifact HTML "의도적 단일톤 committing" 명시(도구 계약)·정적 HTML 라이트·Obsidian 라이트 전환 안내
- 결정_6: **GitHub 렌더 현실** 인덱스 명문화(4항목) — .md는 CSS 못 입음(백틱 hex 스와치만 예외)·Mermaid는 네이티브 렌더됨·HTML/CSS는 소스로만 보임·"왜 GitHub서 안 보이나" 오인 방지
- 결정_7: **유지보수·드리프트 절차** 명문화 — 4곳 리터럴 hex는 수동 동기화(SSOT 먼저 수정 → grep으로 3곳 반영). "코드 SSOT 아닌 문서 SSOT" 명시
- 결정_8: **기존 §4.3.2 WCAG 결함 별도 후속**(사용자 결정) — 신규 앵커 옆에 결함 주석 + 후속 작업 권고, 이번엔 미교정
