# 요구사항: 영속 콘텐츠 Wiki Vault 통합 (Task γ)

**TL;DR**: Task α (`docs-structure-redesign`)에서 결정한 4가지 정책 중 **D**를 적용. 5 repo의 `docs/사용방법/`·`docs/참고/` 폴더 안 파일들을 `projects/wiki/사용방법/`·`projects/wiki/참고/`로 이전 + 각 repo 해당 폴더 폐지 + 외부 위키링크·문서 인용 재배선. DRY 준수(영속 콘텐츠 단일 출처). Task β(구조 마이그레이션)와 병렬 가능 (영역 독립 — γ는 `사용방법·참고/`·`projects/wiki/`).

## 1. 사용자 지시 원문

> "두 작업을 병렬로 가능하면 병렬로 진행해."
>
> 직전 합의: Task α 결정 4가지 중 D — 영속 콘텐츠 Wiki 통합. `사용방법/`·`참고/`는 Wiki Vault로 이전 + 각 repo에서 폐지.

### 요구사항_2 — 이전 위치 (Wiki Vault)

| 출처 | 목적지 |
|---|---|
| `루트/docs/사용방법/<파일>.md` | `projects/wiki/사용방법/<파일>.md` (또는 `사용방법/<원본 repo>/<파일>.md`로 분류 시) |
| `Sound1/docs/사용방법/<파일>.md` | `projects/wiki/사용방법/<파일>.md` (또는 `Sound1/<파일>.md` 서브폴더) |
| `Sound1/docs/참고/<모듈>/<파일>.md` | `projects/wiki/참고/<모듈>/<파일>.md` |
| `ez8300-study/docs/참고/CFX/[CFX-NN] ...md` | `projects/wiki/참고/CFX/[CFX-NN] ...md` |
| (이하 동형) | |

> [!IMPORTANT]
> 파일 분류(repo별 서브폴더 vs 통합)는 분석 단계에서 결정. 기본 방향: **이전 시 출처 정보는 frontmatter로 기록** (예: `source_repo: Sound1`), 폴더는 도메인 기반 분류 우선.

### 요구사항_3 — 각 repo에서 해당 폴더 폐지

| 작업 | 동작 |
|---|---|
| 파일 이전 후 | `git rm -r 해당 repo/docs/사용방법/` + `git rm -r 해당 repo/docs/참고/` |
| 정합성 | Task α §2.3 표준 폴더 정책 적용 (이미 갱신됨 — `사용방법·참고`는 Wiki Vault) |

### 요구사항_4 — 외부 링크·인용 재배선

기존 작업 산출물·회고·지침·CLAUDE.md에서 `docs/사용방법/`·`docs/참고/` 경로 인용을 새 Wiki Vault 경로로 갱신:

| 위치 | 대상 |
|---|---|
| 루트 `CLAUDE.md` | `docs/사용방법/Slack 작업 완료 알림.md` 같은 링크 |
| 회고 | 사용방법·참고 인용 |
| 지침 | 거의 없음 (Task α에서 이미 갱신) |
| 각 프로젝트 CLAUDE.md | 참고·사용방법 인용 |
| 작업 산출물(archive·활성 — Task β와 충돌 가능, 분석에서 조정) | 인용 갱신 |

### 요구사항_5 — Wiki Vault 구조 매핑

직전 Wiki bootstrap에서 정의된 카테고리 구조 + 새 영역:

```
projects/wiki/
├── 프로젝트/     기존 (각 프로젝트 통합 페이지)
├── 학습/         기존
├── 일상/         기존
├── 참고/         기존 — 도메인 모듈 서브폴더 (CFX·칩·LED·터치 등)
├── 사용방법/     ★ 신규 — 도구·CLI 매뉴얼 (Slack 알림·RTT 등)
└── _attachments/ 기존
```

`참고/` 폴더는 Wiki bootstrap에서 이미 정의됨 — 본 task에서 콘텐츠 채움.
`사용방법/` 폴더는 신규 — Wiki Vault 안에 추가.

### 요구사항_6 — Wiki 페이지 frontmatter (이전 시 추가)

각 이전 파일에 다음 frontmatter 추가 (또는 기존 보존하면서 확장):

```yaml
---
title: <원본 제목>
category: 사용방법 또는 참고
source_repo: <원본 repo — root, Sound1, ez8300-study, ...>
source_path: <원본 경로 — docs/사용방법/<파일>.md>
migrated_from: <원본 commit SHA 또는 날짜>
last_updated: 2026-05-15
tags: [...]
---
```

`source_repo`·`source_path`로 출처 추적. 향후 원본 변경 시 재sync 가능.
