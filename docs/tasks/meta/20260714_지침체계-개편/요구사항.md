# 요구사항: 지침체계 개편

**TL;DR**: 4개 축을 개편한다 — ① 지침·헌법에서 `maturity` 개념 전면 제거(37파일), ② 작업 프로세스를 4단계에서 **각 산출 단계 뒤 검증을 정식 단계로 삽입한 8단계**로 확장하고 검증을 독립 파일로 문서화, ③ rules 및 전 형제 repo의 remote를 HTTPS→SSH로 전환하고 `tools/credentials`의 SSH 키를 배선, ④ 오케스트레이션 시 4단계 산출물·각 검증·위임 프롬프트/입력을 빠짐없이 문서화하도록 지침을 강제화(권한 문제 아님 — 프롬프트·상기·게이트 보강).

## 1. 사용자 요청

사용자(은수님) 원문 요지:

> "지침에서 더 이상 maturity 기능은 필요 없어 … 전체 내용에서 maturity 관련 내용은 전부 제거하자.
> 작업 진행에 대해서 4단계를, 요구사항 → 검증 → 분석 → 검증 → 계획 → 검증 → 구현/처리 → 검증. 이렇게 하게 만들어. 단계마다 검증하도록.
> http로 되어 있는 git은 ssh로 변경해서, tools의 credentials를 활용하도록 해.
> 오케스트레이션을 활용하는 경우, 요구사항·분석·계획·구현 및 각 단계의 모든 검증 과정도 전부 문서로 남겨놓게 해. 오케스트레이션 프롬프트 생성 및 입력에 대한 내용도 전부 문서로 남기고. 이미 지침에 남기라고 되어 있는데, 실제로 보면 네가 안 남겨.
> 서브에이전트의 권한 문제인거야? 그렇다면 나에게 알려줘. 권한을 줘야 한다면 그 방법을 알려주거나, 네가 직접 권한을 허용하게 변경해.
> 지금 입력하는 작업을 최대한 빠르게 처리하기 위해 필요하다면 서브에이전트를 적극 활용해."

### 모호 포인트 해소 (사용자 확정)

| 질문 | 확정 답 |
|---|---|
| maturity 제거 범위 (과거 tasks 포함?) | **지침 + 헌법(CLAUDE.md)만** — 과거 `docs/tasks/`는 소급 수정 금지로 보존 |
| 검증 산출물 형식 | **독립 검증 파일 4개** (요구사항-검증·분석-검증·계획-검증·구현-검증) |
| SSH 전환 범위 | **모든 형제 repo까지** (rules + projects 12개) |
| 검증의 성격 (승인 게이트?) | **자체 검증(문서화) + 사용자 승인 1회 유지** (계획+계획검증 후 구현 전) |
| 핵심 정의 파일 개명 | `4단계-프로세스.md` → **`작업-프로세스.md`** (숫자 중립) |

## 2. 목표

- 목표_1 (maturity 제거): 지침·헌법에서 `maturity` frontmatter 필드·인라인 마커·README 인덱스 열·정의 문단·산문 언급을 전부 제거하고, maturity에 의존하던 로직(CLAUDE.md 인라인 선정 기준 등)을 대체 서술로 재정의.
- 목표_2 (8단계 프로세스): 작업 프로세스를 `요구사항→검증→분석→검증→계획→검증→구현/처리→검증` 8단계로 개편. 검증은 각 산출 단계 직후 **독립 검증 파일**로 남기며, 자체 검증(지침준수·논리정합·근거검증) 성격. 사용자 승인 게이트는 계획+계획검증 완료 후 구현 진입 전 1회 유지.
- 목표_3 (SSH 전환): rules 및 전 형제 repo의 origin을 `git@…` SSH URL로 전환하고, `tools/credentials/github/ssh-key`를 git이 사용하도록 배선. 재현 방법을 credentials README·설정 지침에 문서화.
- 목표_4 (오케스트레이션 문서화 강제): 2노드 이상 fan-out 시 4단계 산출물·각 검증·위임 프롬프트/입력을 반드시 문서화하도록 CLAUDE.md §5(자동주입 core) 강화 + 위임 프롬프트 표준 문구 + 완료처리 점검 게이트 추가. "권한 문제 아님"을 사용자에게 규명 보고(완료).
