## 3. 핵심 결정 사항

### 분석_3 — `모듈 현황.md` 위치 결정 (옵션 가 채택)

| 옵션 | 결정 |
|---|---|
| **가. `tasks/모듈 현황.md`로 위치 이전** ✅ | Archive 폐지 시 자연스러움. list.md와 같은 위치에 배치. 5 repo 일괄 이전은 Task β에서 |
| 나. `모듈 현황.md` 폐지 + list.md 흡수 | list.md 가독성 ↓, 모듈 단위 인덱스의 의미가 옅어짐 |
| 다. 보존 | 일관성 깨짐 |

**채택 가**. 본 Task α의 지침에 정책 명시(`작업 진행 규칙.md §6.1` 5번 단계 위치를 `tasks/모듈 현황.md`로). Task β에서 실제 이전 수행.

### 분석_4 — 본 Task α 자기 적용 면제

| 옵션 | 결정 |
|---|---|
| (i) 본 task 즉시 자기 적용 (새 정책으로 진행) | Task β에서 변환되는 것이 아니라 본 task가 첫 사용 사례. 그러나 본 task 진행 중 정책이 막 정의되므로 *시간 순서상 불가능* |
| (ii) 본 task는 현 구조로 진행, Task β에서 일괄 변환 ✅ | 시간 순서 정합 + Task β의 일관 변환에 본 task도 포함 |

**채택 (ii)**. 본 task 산출물은 `진행상황.md` 별도 + 종료 시 archive 이동(현 구조). 회고 "정책 신설 자기 참조" 항목과 다른 패턴 — 본 task는 *정책 발효 시점이 Task β 종료*라 자기 적용 면제. 면제 사유 명시.

### 분석_5 — 사용방법 폴더 전환기 정책

신규 프로젝트는 표준 폴더에서 `사용방법/` 제외(즉시 적용). 기존 5 repo의 `사용방법/`은 Task γ에서 Wiki 이전 후 폐지 — 본 task 종료 후~Task γ 시작 전은 **전환기**. 지침에 "Wiki 이전 권장, Task γ에서 일괄 처리" 메모 추가.

### 분석_6 — 회고 보강 (자기참조 항목에 본 사례 추가)

[`docs/회고/작업 진행.md`](../../../회고/작업%20진행.md)의 "정책 신설 작업의 자기 참조 — 첫 사용 사례 자기 반영" 항목에 본 Task α 사례 추가:
- 본 task는 4가지 변화 정책 신설로 영향 라인 25곳에 흩어짐
- 다중 위치 grep 점검 패턴 적용 (Phase 1 Explore agent로 전수 식별)
- 자기 적용은 면제 — 사유 명시 (정책 발효 시점이 Task β 종료라 시간 순서상 불가)
- 회고 항목 본문에 *"자기 참조 면제 사례"* 한 줄 추가

## 4. `.gitignore`·외부 링크 영향

### 분석_7 — `.gitignore` 충돌 없음

- 루트 `.gitignore`: `_archive/`·`사용방법/`·`참고/` 차단 없음. 본 task 패치 후에도 영향 없음
- 각 프로젝트 `.gitignore`: 동일

### 분석_8 — 외부 링크 위험 점검

본 task α는 지침 패치만이라 외부 링크 영향 적음. 단:

| 외부 링크 종류 | 영향 |
|---|---|
| `_archive/<모듈>/<작업>/` 경로 인용 (다른 지침·회고·작업 산출물에서) | Task β 시점에 일제히 갱신 필요 (본 task α 범위 외) |
| `_archive/모듈 현황.md` 경로 인용 (직전 archive-modules-index 작업 산출물에서) | Task β 시점에 `tasks/모듈 현황.md`로 일괄 갱신 |
| `사용방법/`·`참고/` 파일 경로 인용 | Task γ 시점에 Wiki 경로로 갱신 |

본 Task α에는 지침 본문에서 `_archive` 표현을 새 정책 표현으로 바꾸므로, 같은 지침 내 자기 참조는 정합됨. 다른 지침·회고가 인용하는 외부 링크는 본 task에서 보전.
