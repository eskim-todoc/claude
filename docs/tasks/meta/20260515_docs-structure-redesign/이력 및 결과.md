## 완료 요약

### 무엇을 했는가

사용자가 docs 구조의 근본 가정 3가지를 재검토 — (1) archive 이동 필요성, (2) 진행상황·이력 차이, (3) list 관리. 분석 결과 4가지 변화 합의 후 정책·지침을 일괄 갱신:

- **A. Archive 폐지** — `tasks/_archive/` 폴더 자체 폐지. 작업 폴더는 완료 후에도 `tasks/<모듈>/<작업>/` 그대로 유지. 외부 링크 안정 + 폴더 이동 비용 0
- **B. 진행상황·이력 통합** — `진행상황.md` 폐지, `이력 및 결과.md` 한 파일에 시계열 로그(진행 중 누적) + 완료 요약(종료 시 추가). 작업당 파일 5 → 4
- **C. 작업 목록.md 단일 표** — `§활성`·`§완료` 분리 폐지. 단일 표 + `상태` 컬럼. 활성만 보기는 grep/필터
- **D. 영속 콘텐츠 Wiki 통합** — `사용방법/`·`참고/` → Wiki Vault로 이전. 각 repo `docs/`에서 폐지

본 Task α는 **정책 + 지침 갱신만**. 25곳 패치 (작업 진행 규칙.md 4 + 문서 작성 규칙.md 7 + 프로젝트 초기 세팅.md 4 + 작업 규칙.md 3 + CLAUDE.md 1 + 회고/작업 진행.md 3, 일부 영역은 한 Edit이 다중 변경 흡수해 실제 Edit 횟수 < 25). Phase 1 Explore agent로 영향 라인 정확 식별 + 응답 4회 분리 (다중 Edit 충돌 회피).

### 핵심 결정

- **`모듈 현황.md` 위치 이전** (옵션 가): Archive 폐지 시 `tasks/_archive/모듈 현황.md` → `tasks/모듈 현황.md`로 자연 이전. Task β에서 5 repo 일괄 적용
- **본 Task α 자기 적용 면제**: 정책 신설 시점과 정책 발효 시점이 시간 순서상 어긋남 — 본 task는 정책을 정의하지만 실제 적용은 후속 Task β에서 일괄 변환. 따라서 본 task는 **현 구조**(진행상황.md 별도·archive 이동)로 진행·종료. 회고 "정책 신설 자기 참조" 항목에 *자기 적용 면제 사례*로 추가
- **사용방법 폴더 전환기**: 신규 프로젝트 표준에서 즉시 제외(`프로젝트 초기 세팅.md §2.3` 갱신). 기존 5 repo의 `사용방법/`은 Task γ까지 유효 (전환기)
- **작업 분할 α → β·γ**: Task α(정책)·Task β(기존 25 작업 마이그레이션)·Task γ(Wiki 통합)로 분할. β·γ는 α 완료 후 병렬 가능

### 후속 영향

- **Task β** (다음 작업): 5 repo의 기존 archive 25 작업을 새 구조로 일괄 변환 — `_archive/<모듈>/<작업>/` → `tasks/<모듈>/<작업>/` 복귀 + `진행상황.md` → `이력 및 결과.md` 시계열 로그 흡수 + 작업 목록.md 활성/완료 → 단일 표 재작성 + `_archive/모듈 현황.md` → `tasks/모듈 현황.md` 위치 이전. 본 Task α도 변환 대상에 포함됨
- **Task γ** (다음 작업, β와 병렬 가능): 5 repo `docs/사용방법/`·`docs/참고/`를 `projects/wiki/사용방법/`·`projects/wiki/참고/`로 이전 + 각 repo 해당 폴더 폐지 + 외부 위키링크 재배선
- **회고 보강**: `docs/회고/작업 진행.md`의 "정책 신설 자기 참조" 항목에 *자기 적용 면제 사례* (시간 순서상 시점 어긋남 → 후속 task 위임) 추가. 향후 정책·인덱스 신설 시 자기 적용 의무 vs 면제 분기 판단에 활용
- **신규 작업 시작 가능**: 본 task 종료 후 신규 작업은 새 정책(이력 및 결과.md 단일 + 단일표 status + 사용방법·참고 Wiki)으로 시작. 기존 25 작업과의 *충돌은 Task β·γ까지 일시적 공존* — 신구 구조 혼재 기간
