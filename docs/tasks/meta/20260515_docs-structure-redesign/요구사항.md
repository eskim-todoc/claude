# 요구사항: docs 구조 근본 재설계 (Task α — 정책 + 지침)

**TL;DR**: 사용자가 docs 구조의 근본 가정을 재검토. 결정 4가지 — (A) Archive 폐지, (B) 진행상황·이력 통합, (C) 작업 목록.md 단일표 + status 컬럼, (D) 영속 콘텐츠 Wiki 통합. 본 task는 **정책 결정 + 지침 갱신만**(Task α). 기존 25 작업의 구조 마이그레이션(Task β)과 사용방법·참고의 Wiki 이전(Task γ)은 별도 후속 작업. 본 task 자체는 현 구조로 진행하고 종료 시 마지막 archive 사용 사례로 남음 — Task β에서 일괄 변환됨.

## 1. 사용자 지시 원문

> "Y. 영속 콘텐츠 → Wiki 통합 뿐만 아니라, 아래와 같이 핵심부터 변경을 고려하고 있어. 루트의 지침부터 말이야.
> 1. 작업 완료 시 아카이브 이동에 대한 필요성
> 2. 각 작업 별로 생성되는 파일의 양. 이력과 진행상황의 차이가 크게 뭐지?
> 3. 위의 변경을 고려해서 리스트나 이력 관리가 어떻게 바뀌면 좋을까?"
>
> 합의: A+B+C+D 전부 적용 / Task α(정책) 먼저 → β(구조)·γ(Wiki) 순차

## 2. 요구사항 — 4가지 변화 정책

### 요구사항_1 — Archive 폐지 (A)

| 항목 | 정책 |
|---|---|
| 작업 폴더 위치 | 완료 후에도 **`tasks/<모듈>/<작업>/` 그대로**. `_archive/` 폴더 폐지 |
| 활성/완료 분리 | `작업 목록.md` 단일 표의 `상태` 컬럼 + 작업 폴더 frontmatter `status` 필드로 식별 |
| 외부 참조 안정 | 폴더 위치 영구 → Wiki 가공 페이지의 `sources` 링크·회고의 작업 인용·CLAUDE.md 링크 등이 변동 없음 |
| 마이그레이션 대상 | 기존 5 repo의 `_archive/<모듈>/<작업>/` 폴더 전부 → `tasks/<모듈>/<작업>/`로 복귀 (Task β) |
| `_archive/모듈 현황.md` | Task β 시점에 `tasks/_index.md`로 위치·이름 변경 (또는 폐지·재설계 결정 — 분석에서) |

### 요구사항_2 — 진행상황·이력 통합 (B)

| 항목 | 정책 |
|---|---|
| 통합 파일명 | `이력 및 결과.md` 유지 (작업의 전체 history) |
| 폐지 파일 | `진행상황.md` |
| 작성 시점 | 단계 ① 시작과 동시에 `이력 및 결과.md` 생성 → 진행 중 시계열 누적 → 완료 시 final 요약 섹션 추가 |
| 구조 | (1) frontmatter (2) TL;DR (3) **시계열 로그** 표 (구 진행상황 누적) (4) **완료 요약** 섹션 (구 이력 — 완료 시 추가) |
| 작업당 파일 수 | 5 → **4** (요구사항·분석·계획·이력) |

### 요구사항_3 — 작업 목록.md 단일 표 + status 컬럼 (C)

| 항목 | 정책 |
|---|---|
| 표 분리 | **§활성·§완료 분리 폐지** — 단일 `## 작업 목록` 표 1개 |
| 컬럼 | `작업명 \| 모듈 \| 태그 \| 상태 \| 시작·완료 \| 폴더 \| 요약` |
| 상태 값 | `진행`·`대기`·`차단`·`완료`·`취소` (현 정의 그대로) |
| 정렬 | 시작일 내림차순 디폴트. 활성만 보기는 상태 컬럼 grep/필터 |
| 갱신 이력 | 표 아래 `## 갱신 이력` 그대로 유지 (작업 등재·완료 추적) |
| 마이그레이션 | Task β 시점에 기존 25 작업의 활성/완료 표를 단일 표로 일괄 재작성 |

### 요구사항_4 — 영속 콘텐츠 Wiki 통합 (D, 직전 Y 합의)

| 항목 | 정책 |
|---|---|
| 이전 대상 | 각 repo `docs/사용방법/` + `docs/참고/` |
| 이전 위치 | `projects/wiki/사용방법/` + `projects/wiki/참고/` (Wiki Vault 안 카테고리 폴더) |
| 잔존 폴더 | 각 repo `docs/`에는 `tasks/`(작업 산출물) + `지침/`(Claude 메타 — 프로젝트 특화 시) + `회고/`(루트만, 프로젝트는 없음) |
| 프로젝트 표준 폴더 | `프로젝트 초기 세팅.md §2.3`에서 `사용방법/`·`참고/`를 표준에서 **제외**. 신규 프로젝트는 `tasks/`만 필수 |
| Wiki 주제 페이지 frontmatter | 직전 합의 — `sources`(repo·archive_path·last_synced)·`related`(위키링크) |
| 마이그레이션 | Task γ에서 실제 파일 이전 + 위키링크 재배선 |

### 요구사항_5 — 본 Task α 범위 한정

본 task는 **정책 결정 + 지침 갱신만** 수행. 다음은 본 task **밖**:

- 기존 25 작업의 archive → 활성 복귀 (Task β)
- 기존 진행상황 → 이력 통합 변환 (Task β)
- 기존 작업 목록.md 활성/완료 → 단일표 재작성 (Task β)
- `사용방법/`·`참고/` 파일들의 Wiki Vault 이전 (Task γ)

### 5.2 논리적 정합성

| 점검 | 결과 |
|---|---|
| 4 변화가 서로 정합 | ✅ A·B·C는 task 구조 변경, D는 영속 콘텐츠 위치. 독립적이나 한 묶음 정책으로 일관 |
| 본 task가 자기 적용 면제 (Task β에서 일괄)인 사유 | ✅ 비요구사항에 명시 — 자기 적용은 Task β에서 일괄 변환 |
| Task α → β → γ 의존성 | ✅ 정책 합의 후 마이그레이션(β)·Wiki 이전(γ) 순서. β·γ는 정책 의존만, 서로 독립 |
