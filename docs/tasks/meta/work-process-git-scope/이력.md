# 이력: 작업 진행 4단계 프로세스 일반화 + Git 범주 처리

**TL;DR**: 모든 작업은 4단계(요구사항→분석→계획→구현)로 진행, Git은 작업 스코프별 repo 분리, 서브에이전트는 병렬·효율 위해 적극 활용.

**기간:** 2026-05-07 ~ 2026-05-07
**모듈/태그:** meta / docs, guideline, workflow, git-scope
**병합:** `claude_develop` ← `claude_feature_work-process-git-scope` (`c2e8864`, feature 커밋 `def1105`)
**연계 작업:** -

## 무엇을 했는가

루트 지침에 세 축의 변경을 적용했다. ① 기존 코딩에 한정되었던 문서 선행 절차를 **모든 작업에 적용되는 4단계 프로세스(요구사항→분석→계획→구현)** 일반 규칙으로 격상해 [`docs/지침/일반/작업 진행 규칙.md`](../../../지침/일반/작업%20진행%20규칙.md)을 신설하고, 코딩 작업 규칙은 일반 규칙을 상속하는 특화 사항만 남기도록 슬림화했다. ② 작업 스코프(루트/프로젝트)별 git repo 분리 규칙을 [`Git/브랜치, 병합 규칙.md`](../../../지침/Git/브랜치,%20병합%20규칙.md)·[`Git/워크플로우.md`](../../../지침/Git/워크플로우.md)에 신설해, 변경 파일 경로 기준으로 어느 repo에 커밋할지 판정·혼합 변경 분리·위반 복구 절차를 명문화했다. ③ 모든 작업에서 병렬 처리·효율을 위해 **서브에이전트 적극 활용** 규칙을 [`docs/지침/일반/서브에이전트 활용.md`](../../../지침/일반/서브에이전트%20활용.md)로 신설했고, 마스터 체크리스트·작업 진행 규칙·컨텍스트 절약 규칙에 cross-ref를 두었다. 인덱스(README·CLAUDE.md)도 함께 갱신했다.

## 핵심 결정

- **산출물 파일명 통일** — `요구사항.md`/`분석.md`/`계획.md`/`이력.md`. 코딩의 `구현계획.md`는 alias로 호환(점진 이행). 사용자 지시 원문이 "구현/처리 계획"으로 코딩 외 작업까지 포함하므로 일반화된 `계획.md`가 더 자연스러움
- **자체 검토 본문 내 포함** — 별도 파일 분리 금지. 검토는 산출물의 신뢰도 보조 자료로 함께 보여야 의미가 있음
- **`진행상황.md` 의무화** — 4단계 작업에 단계 ① 시작과 동시에 생성. 단순 수정 면제 작업은 자동 면제
- **Git 스코프 §0** — 워크플로우의 모든 후속 절차의 선행 조건이므로 §1 브랜치 모델 직전 §0으로 배치. 브랜치, 병합 규칙에는 §스코프 본문 + 위반 복구 표
- **서브에이전트 활용은 별도 지침** — `컨텍스트 절약 규칙`(격리 관점)과 의도가 직교하므로 별도 파일. 두 파일 cross-ref로 연결

## 후속 영향

- 향후 모든 신규 작업은 본 4단계 프로세스 적용 — 단순 수정 예외 외 면제 없음
- 기존 활성 작업(`구현계획.md` 사용)은 그대로 두되 마무리 시 alias 인정. 신규 작업부터 `계획.md` 적용
- 프로젝트(`projects/Sound1/` 등) 측은 별도 동기화 불필요 — 루트 지침 자동 적용. 충돌 시 프로젝트 우선 원칙은 [`문서 작성 규칙.md` §2.1](../../../지침/일반/문서%20작성%20규칙.md#21-루트-vs-프로젝트-docs--적용-범위와-우선순위) 그대로
- Git 스코프 위반 시 사용자 보고·revert/cherry-pick 협의 절차가 활성화됨
