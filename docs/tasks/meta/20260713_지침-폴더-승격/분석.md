# 분석: 지침 폴더 루트 승격

**TL;DR**: `docs/지침/`이 `docs/` 밖으로 나가 루트 `지침/`이 되면서 디렉토리 깊이가 1단 줄어든다. 이로 인해 (A) 지침 서브트리 내부 파일이 트리 밖을 참조하는 링크 7건은 `../` 1개 제거, (B) 지침 서브트리 밖 파일이 안을 참조하는 링크 251건은 스타일에 따라 접두어 교체 또는 `../` 1개 추가가 필요하다. 총 73개 파일 258건. 보정 규칙이 단순·기계적이라 스크립트 일괄 처리가 가능하다.

## 1. 현 상태 (Current State)

- 현황_1: `docs/지침/`은 `일반/`·`Git/`·`코딩/` 하위 40여 개 지침 파일 + `작업 규칙.md`(마스터 체크리스트)로 구성
- 현황_2: `docs/`에는 `지침/` 외에 `tasks/`(작업 기록, `meta/` 모듈 포함 25개 완료 작업)·`plans/`·`참고/`가 형제로 존재
- 현황_3: `CLAUDE.md`(루트)는 `docs/지침/...` 형태의 루트 기준 명시 경로로 지침 각 파일을 38회 링크
- 현황_4: `docs/tasks/meta/` 하위 완료 작업 파일들(요구사항.md·분석.md·계획.md·이력 및 결과.md)은 `../../../지침/...` 형태로 지침을 인용 — 이는 리터럴 문자열에 `docs`가 없지만 실제로는 `../../../`가 정확히 `docs/`까지 올라간 뒤 `지침/...`으로 이어져 `docs/지침/...`을 가리키는 상대경로 스타일
- 현황_5: `docs/지침/일반/작업/양식/{요구사항,분석,계획}.md` 3개 템플릿 파일은 "복사되어 쓰일 위치"(`docs/tasks/<모듈>/<작업>/`) 기준으로 예시 링크를 작성해 두었음 — 템플릿 자신의 실제 저장 위치가 아니라 사용 시점 위치 기준이므로 카테고리 B(밖→안)로 분류

> [!TIP]
> Explore 서브에이전트로 전체 저장소 링크 스캔을 위임해 메인 컨텍스트를 절약했다 ([`서브에이전트 활용.md`](../../../../지침/일반/서브에이전트%20활용.md) §2.1).

## 3. 가설·선택지

### 3.1 선택지 (설계 결정)

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 과거 완료 작업 기록(65개 파일·202건)까지 전부 보정 | 저장소 전체 broken link 0건 달성. Task β(tasks 구조 마이그레이션) 선례와 일관 — 그때도 "외부 인용 11 파일 갱신" 수행 | 커밋에 포함되는 파일 수가 커짐(다만 기계적 일괄 처리라 실작업 부담은 크지 않음) |
| B. 현재 활성 문서(CLAUDE.md·지침 서브트리·컨벤션 문서)만 보정, 과거 기록은 그대로 둠 | 변경 파일 수 최소화 | 과거 작업 기록 202건이 영구히 깨진 링크로 남음 — 요구사항.md 수용기준 "broken link 0"과 직접 충돌 |

**권장**: A. 보정 규칙이 100% 기계적(패턴 매칭 후 `../` 개수만 ±1)이라 파일 수가 많아도 리스크·수작업이 늘지 않는다. B는 스코프를 줄이는 대신 "산출물의 정합성"이라는 이번 작업의 원래 동기를 부분적으로 훼손한다.

## 4. 핵심 결정

- 결정_1: **링크 보정은 스크립트(sed) 기반 일괄 처리**로 수행 — 258건을 Edit 도구로 개별 처리하면 문자열 매치 실패 위험([`4단계-프로세스.md §5.7`](../../../../지침/일반/작업/4단계-프로세스.md))이 크고, 반대로 패턴이 균일해 스크립트가 훨씬 안전
- 결정_2: **이동 커밋과 링크 보정 커밋을 분리** — `git mv` 자체는 순수 이동(diff 없음)이라 1커밋, 링크 보정은 카테고리별로 나눠 2~3커밋. 각 커밋이 독립적으로 revert 가능하도록
- 결정_3: 과거 완료 작업 기록도 포함해 전부 보정 (선택지 A) — 계획.md에서 사용자에게 최종 확인
- 결정_4: `../../../../` 등 기존에 이미 불일치했던 6개 파일은 "현재 파일에 실제로 적힌 up-count"를 그대로 읽어 거기서 +1 — 표준 3-up을 가정하고 일괄 치환하면 이 6개 파일에서 깨짐

## 5. 위험·제약

| 위험 | 가능성 | 영향 | 완화 |
|---|---|---|---|
| sed 정규식이 지침 서브트리 내부 상호참조(변경 불필요)까지 잘못 건드림 | 낮음 | 중 | 카테고리별로 대상 파일 목록을 먼저 확정한 뒤 그 목록에만 스크립트 적용 (전체 저장소 일괄 sed 금지) |
| 기존에 이미 깨져 있던 링크(컨텍스트 절약 규칙.md 등)를 본 작업 탓으로 오인 | 낮음 | 낮음 | 구현 전 baseline broken-link 스캔 실행 후 diff로 "본 작업이 새로 깨뜨린 것"과 "원래 깨져 있던 것" 구분 |
| 최종 검증 누락으로 일부 링크 미보정 | 중 | 중 | 구현 마지막 단계에서 전체 저장소 링크 체커 재실행, 0건 확인 전까지 완료 처리 금지 |
