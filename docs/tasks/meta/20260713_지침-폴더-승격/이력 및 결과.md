## 완료 요약

**기간:** 2026-07-13 ~ 2026-07-13
**병합:** `claude_develop` ← `claude_feature_지침-폴더-승격` (병합 대기 — 은수님 승인 후 진행)

### 무엇을 했는가
`docs/지침/`을 저장소 루트의 `지침/`으로 승격 이동했다(Sound1의 `src/`에 상응하는 실제 산출물이라는 관점). `git mv`로 히스토리를 보존해 34개 파일을 이동한 뒤, 이로 인해 깨지는 상대경로 링크를 두 방향으로 나눠 전량 보정했다 — 지침 내부에서 트리 밖을 가리키는 7건은 `../` 1개 제거, 트리 밖에서 지침 안을 가리키는 217건은 리터럴 `docs/지침` 접두어 교체(CLAUDE.md 등 7개 파일) 또는 파일별 실제 디렉토리 깊이 기준 `../` 재계산(66개 파일, Perl 스크립트)으로 처리했다. `CLAUDE.md`·`문서 작성 규칙.md`·`폴더-구조.md`에 "루트만의 예외"를 명시해 향후 혼동을 방지했다.

### 핵심 결정
- `rules-tasks` 별도 저장소 분리 대신 `rules` 내 `docs/tasks/meta/` 모듈로 진행 — git 이중 승인·계획-구현 히스토리 단절 문제 회피
- 과거 완료 작업 기록(약 65개 파일)까지 포함해 전부 보정 — "broken link 0건" 목표와 Task β 선례 일치
- 링크 보정은 개별 Edit이 아닌 스크립트(Perl) 기반 일괄 처리 — 파일 수가 많아도(66개) 규칙이 100% 기계적이라 리스크가 낮음. Windows Perl의 한글 파일명 인코딩 문제로 `File::Find` 기반 전수 스캔은 포기하고, Grep 도구로 확정한 파일 목록만 스크립트에 전달하는 방식으로 우회
- up-count는 "기존 값 +1"이 아니라 "파일의 실제 디렉토리 깊이로부터 재계산" — 기존에 이미 어긋나 있던 6개 파일도 부작용 없이 함께 정정됨

### 후속 영향
- `컨텍스트 절약 규칙.md`가 참조하는 이미 존재하지 않는 `docs/회고/커뮤니케이션.md` 링크는 이번 작업과 무관한 기존 결함으로 확인 — 별도 task 권고 (범위 외로 남겨둠)
- 병합(`claude_develop` ← 본 feature 브랜치)은 은수님 승인 후 진행
