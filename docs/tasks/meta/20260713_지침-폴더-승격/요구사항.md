# 요구사항: 지침 폴더 루트 승격

**TL;DR**: `docs/지침/`을 저장소 루트의 `지침/`으로 승격 이동한다. `docs/`에는 `tasks/`·`plans/`·`참고/`만 남는다. 목적은 "산출물(지침 본문)"과 "산출물을 만드는 작업 과정 기록(docs/tasks)"을 폴더 레벨에서 분리하는 것 — Sound1의 `src/`가 실제 펌웨어이듯, 이 저장소에서는 `지침/`이 실제 산출물이다.

## 1. 사용자 요청

은수님이 `rules-tasks`라는 별도 프로젝트를 만들어 규칙 개정 작업을 분리하려 했으나, 논의 끝에 별도 저장소 분리는 (a) git 승인 게이트 이중화, (b) 계획-구현 간 히스토리 단절이라는 손해가 있어 폐기하고 **`rules` 저장소 안에서 그대로 관리**하기로 결정했다.

> "헌법/지침과 tasks가 같은 레벨에 있다보니 뭔가 좀 아닌거 같아. ... rules의 경우 헌법/지침이 docs 속성이긴 하지만 사실살 별개로 봐야하지 않아? sound1을 예로들면 src의 역할을 하는게 지금 헌법/지침 내용 같거든."

이어서 두 가지를 확인(AskUserQuestion)했다:
- 승격된 폴더명: **`지침/` 그대로** (기존 용어 유지, 최소 변경)
- `docs/참고/` 폴더: **이번 스코프에서 제외** (별도 이슈 — 이미 wiki 이관 정책 존재)

## 2. 목표

- 목표_1: `docs/지침/` → `지침/` (루트 승격) — git 히스토리 보존 이동
- 목표_2: 승격으로 인해 깨지는 모든 상호 참조 링크를 빠짐없이 갱신 (조사 결과 73개 파일·258건)
- 목표_3: 문서 컨벤션 지침(`문서 작성 규칙.md`·`폴더-구조.md` 등)이 이 승격을 "루트 저장소 고유 예외"로 명시하도록 갱신 (하위 프로젝트의 `docs/지침/` 컨벤션은 변경하지 않음 — Sound1 등은 `지침`이 산출물이 아니라 보조 문서이므로 그대로 `docs/` 하위 유지)

## 3. 수용 기준 (Definition of Done)

### 3.1 기능·산출물
- [ ] 수용기준_1: `git mv docs/지침 지침` 완료, 히스토리 보존 확인 (`git log --follow`)
- [ ] 수용기준_2: `지침/` 서브트리 내부에서 트리 밖(CLAUDE.md·docs/tasks·projects 등)을 가리키는 링크 전부 `../` 1개 제거
- [ ] 수용기준_3: `지침/` 밖 파일에서 `지침/` 안을 가리키는 링크 전부 보정 — 리터럴 `docs/지침` 스타일은 접두어 교체, `../`로 `docs/`까지만 올라가는 스타일은 `../` 1개 추가
- [ ] 수용기준_4: `CLAUDE.md`의 Layout 다이어그램·§핵심 지침 인라인 등 `지침/` 경로를 언급하는 모든 곳 갱신
- [ ] 수용기준_5: `문서 작성 규칙.md`/`폴더-구조.md`에 "루트 저장소는 `지침/`이 루트 승격된 예외" 명시

### 3.2 정합성·검증
- [ ] git diff로 모든 변경 검토 가능
- [ ] 저장소 전체 대상 broken link 스캔 결과 0건 (본 작업으로 인한 신규 breakage 기준 — 기존에 이미 깨져 있던 무관 링크는 별도 이슈로 분리)
- [ ] `이력 및 결과.md` 시계열 로그 + 완료 요약 작성

### 3.3 회귀 방지
- [ ] 본 작업은 `claude_feature_지침-폴더-승격` 브랜치 격리 (완료)
- [ ] 각 commit이 atomic — 단계별 revert 가능 (이동 커밋과 링크 보정 커밋 분리)

## 4. 작업 범위 외 (Out of Scope)

- 범위외_1: `docs/참고/` 폴더 처리 — 사용자가 이번 스코프에서 명시 제외
- 범위외_2: 하위 프로젝트(Sound1 등)의 `docs/지침/` 구조 변경 — 이들은 `지침`이 보조 문서이지 산출물이 아니므로 무관
- 범위외_3: `컨텍스트 절약 규칙.md`가 참조하는 이미 존재하지 않는 `docs/회고/커뮤니케이션.md` 링크 수정 — 조사 중 발견된 기존 이슈이나 본 작업(구조 승격)과 무관한 별도 결함. 이력 및 결과.md에 발견 사실만 기록하고 별도 task로 분리 권장
- 범위외_4: `rules-tasks` 프로젝트(현재 빈 저장소) 정리·삭제 — 은수님이 별도 처리

## 5. 위임 범위 (Claude 자율 결정)

- 위임_1: 258건 링크 보정의 구체적 실행 방식(스크립트 sed vs 개별 Edit) — 정확성·검증 가능성 기준으로 자율 결정
- 위임_2: 커밋 단위 분할(이동 1커밋 + 카테고리별 링크 보정 커밋 분리 여부)

위임 범위 밖 (사용자 결정 영역):
- 사용자결정_1: 완료된 과거 작업 기록(65개 파일, ~202건) 링크까지 전부 보정할지, 아니면 CLAUDE.md·지침 서브트리 등 "현재 활성 문서"만 보정하고 과거 기록은 그대로 둘지 — 계획.md에서 선택지 제시 후 확인
- 사용자결정_2: 계획.md 승인 후 실제 이동·커밋·병합 시점
