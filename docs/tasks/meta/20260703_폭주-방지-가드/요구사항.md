# 요구사항: 서브에이전트 폭주 방지 가드

**TL;DR**: 2026-07-03 문서 테마 작업에서 확정 스펙 대형 저술(257줄)을 effort:max 단일 노드에 위임 → 파일은 완성했으나 자체검토 루프로 transcript 379KB 폭주(토큰·시간 낭비). 재발 방지 3종을 지침화: (1) effort 유형별 맞춤(결정론적 대형 저술은 직접/저-effort), (2) 폭주 서킷브레이커(감시·TaskStop 폴백), (3) 프롬프트 위생(저술/검증 분리·flaky MCP 배제). + 미비 2건: §4.3.2 WCAG 후속 등록·테마 로그 정리.

## 1. 사용자 요청

> "미비된거 마저 해야해. 그리고 [폭주 인시던트 보고 인용] 이거 또 이런 식의 문제가 발생하지 않게 만들어야 할텐데. 어떻게 해야해? 네가 소모시켜버린 내 토큰 어떻게 해. 시간도 엄청 오래걸렸어. 또 반복되면 안될거 아니야."

`AskUserQuestion` 확정:
- 재발 방지: **3개 모두**(effort 유형별 + 서킷브레이커 + 프롬프트 위생), "effort 항상 max"를 "결정론적 대형 저술은 예외"로 완화

## 2. 목표

- 목표_1: effort 정책 완화 — max는 기본(추론·분석·설계·검증), 확정 스펙 결정론적 대형 저술은 오케스트레이터 직접 또는 low/medium
- 목표_2: 폭주 서킷브레이커 신설 — fan-out 감시, 산출물 없이 임계 초과 노드 TaskStop→직접 폴백
- 목표_3: 프롬프트 위생 — 저술/검증 분리, flaky MCP 의존 배제, 노드 단일 명확 산출물
- 목표_4: 2026-07-03 폭주를 §학습 노트로 기록(experimental)
- 목표_5(미비): §4.3.2 Mermaid 팔레트 WCAG 미달(3/5) 교정을 후속 작업으로 `작업 목록`에 등록(대기)
