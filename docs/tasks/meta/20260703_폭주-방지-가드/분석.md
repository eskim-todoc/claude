# 분석: 서브에이전트 폭주 방지 가드

**TL;DR**: 폭주 근본 원인 3가지(effort:max×결정론적 대형 저술의 자체검토 루프 · fire-and-forget · 프롬프트 과부하). "항상 max" 문구는 4개 파일에 있고, effort **위임 여부**는 유지하되 **effort 값만** 유형별로 완화하면 "전면 위임" 취지와 충돌하지 않는다(위임은 그대로, 값만 조정).

## 1. 현 상태 — 폭주 근본 원인

2026-07-03 문서 테마 작업 구현 fan-out에서:
- **원인_1 (핵심)**: 257줄 확정 지침 저술을 effort:max 단일 노드에 위임. 저술 내용은 이미 분석·계획에 확정 → 추론 여지 거의 없음. 그런데 effort:max가 과잉 추론·자체검토를 반복해 파일 완성 후에도 transcript 379KB로 폭주. 직전 동일 노드도 439KB.
- **원인_2**: fan-out을 fire-and-forget — 진행 감시 없음. 산출물 없이 부푸는 노드를 은수님 지적 전까지 미감지.
- **원인_3**: 한 노드에 읽기3 + 대형 저술 + (재연결 중 Mermaid MCP) 검증 몰아넣음 → 루프 유발 소지.

## 3. 가설·선택지

**쟁점: effort 완화가 은수님이 승인한 "전면 위임·effort 항상 max"를 뒤집는가?**

| 관점 | 판정 |
|---|---|
| 위임 여부 | **불변** — 실제 작업은 여전히 전량 서브에이전트 위임(§1.1 예외만 직접) |
| effort 값 | **유형별 조정** — max는 추론(분석·설계·검증)에 유지, 결정론적 대형 저술만 예외 |
| 결정론적 저술의 위임 자체 | 규모 큰 확정 저술은 **오케스트레이터 직접**도 허용(서브에이전트 가치=사고인데 확정 저술엔 사고 여지 적음, §6 ①③ 직접과 같은 논리) |

**결정**: "전면 위임"의 골자(위임 우선)는 유지, effort **값만** 유형별로 다듬는다. 은수님이 max를 고른 취지(품질·사고 최대)는 추론 노드에서 그대로 살고, 폭주가 난 결정론적 저술만 예외 처리 → 취지 훼손 없이 리스크 제거.

## 4. 핵심 결정

- 결정_1: effort **기본 max, 확정 스펙 결정론적 대형 저술은 예외**(직접 또는 low/medium). 근거를 폭주 사례로 명시
- 결정_2: 워크플로우 오케스트레이션.md **§8 폭주 감지·서킷브레이커** 신설 — 감시·임계·TaskStop 폴백·노드 산출물/범위 상한
- 결정_3: 서브에이전트 활용.md **§4.4 프롬프트 위생** — 저술/검증 분리·flaky MCP 배제·단일 산출물
- 결정_4: 폭주 인시던트를 워크플로우 오케스트레이션.md §학습 노트(experimental)에 기록
- 결정_5: §4.3.2 WCAG 후속을 `작업 목록` 대기 등록(실제 교정은 별도)
- 결정_6: 테마 `에이전트-로그/인덱스.md`에 impl fan-out 요약 + 폭주 인시던트 1행 보강
