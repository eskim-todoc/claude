# 요구사항: 작업 lifecycle · 회고 승격 · 프로젝트 우선순위 정책 정련

**TL;DR**: ① `tasks/`에 lifecycle이 없어 비대화 위험 → 옵션 C(`_archive/<모듈>/<작업>/`로 `git mv`+`이력 및 결과.md` 작성) 도입, ② 루트와 프로젝트 docs 충돌 시 프로젝트 우선 명시, ③ 회고는 즉시 효력·지침 승격은 통합/정리 차원으로 단순화. 첫 사례로 `docs-restructure`를 archive 처리.

## 1. 배경

`docs/` 구조와 회고 시스템 도입 이후 운용 중 다음 세 가지 정책 공백이 식별됨:

1. **`tasks/` lifecycle 부재** — 완료된 작업 폴더의 처리 규칙 없음. `meta/20260424_docs-restructure/` 한 건만으로 ~680줄 누적. 작업 수가 늘면 비대화 위험
2. **프로젝트 vs 루트 docs 충돌 시 우선순위 미정의** — 동일 지침이 양쪽에 존재할 때 어느 쪽이 우선인지 명시 안 됨
3. **회고 승격 절차의 효력 시점 불명** — 회고 → 지침 승격 사이에 검증 기간이 있으면 그 동안 회고 효력이 모호

대화에서 합의된 방향대로 정책을 정돈하고 첫 사례를 적용한다.

## 2. 합의된 정책

### 2.1 `tasks/` lifecycle (옵션 C — 아카이브 이동)

- 완료 시그널 직후 `tasks/<모듈>/<작업>/` → `tasks/_archive/<모듈>/<작업>/`로 `git mv`
- 모듈 계층 유지 (active와 archive의 경로 구조 동일)
- 이동과 동시에 `이력 및 결과.md` 작성 (1페이지 요약, 진입판단용)
- `작업 목록.md` 완료 섹션의 폴더 링크는 `_archive/...` 경로로 갱신

### 2.2 프로젝트 vs 루트 docs 우선순위

- **루트 `docs/지침/`** = 전역 기본값. 모든 프로젝트에 자동 적용
- **프로젝트 `docs/지침/`** = 해당 프로젝트 한정 특화 예외만
- **충돌 시 프로젝트 우선** (프로젝트가 더 구체적인 컨텍스트이므로)

### 2.3 회고 승격 운용

- 회고에 등재되면 **즉시 효력 발생** (검증 단계 없음)
- 회고와 지침의 차이는 "효력"이 아니라 "성숙도/통합 정도"
- 충분히 안정화된 회고 → 지침으로 본문 이전 (회고에서는 삭제, 중복 방지)
- 승격 매핑은 [`docs/회고/README.md`](../../../회고/README.md) 하단 표로 추적

## 3. 비목표 (out of scope)

- Sound1 등 프로젝트 repo의 동일 정책 반영 — 후속 작업
- 기존 회고 본문의 지침 승격 실행 — 이번 작업은 정책 도입까지만, 승격은 자연스럽게 트리거될 때
- `_archive/` 내 작업의 추가 정리 (분기/연 단위 통합 등) — YAGNI
