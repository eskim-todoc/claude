# 재설계 아이디어 — 회고·지침·tasks 구조 거시 재검토

**TL;DR**: 4가지 거시 의문을 서브에이전트 4개 병렬 조사로 데이터 검증. **(1)** 회고 35건 중 승격 0건 — 회고·지침은 사실상 평행 레이어, 통합이 합리. **(2)** CLAUDE.md만 자동 주입되므로 분할 자체는 자동 적용에 영향 없음, "필수 지침"은 인라인 또는 SessionStart Hook으로 보장. **(3)** `작업 목록.md`와 `_modules.md`는 차원이 달라(작업 vs 모듈) 통합 불가 — 명명 명확화가 답. **(4)** "구현.md" 별도 산출물 불필요(코드 자체), 사용자 제안 "요구→계획→분석" 순서는 "요구→분석→계획"이 더 자연(분석 없이 계획 불가), 폴더명 날짜 prefix는 가시성에 즉시 효과. **종합 권고**: Package A(즉시 1시간) = Y-1(핵심 지침 인라인) + Z-1(폴더 날짜 prefix) + Z-3(인덱스 명명 명확화). Package B(반나절) = A + X(회고→지침 통합 + maturity 라벨).

## 1. 4가지 고민 — 데이터 진단

### 고민 1: 회고를 따로 관리하는 게 의미 있나?

**데이터** (서브에이전트 A)

| 항목 | 수치 |
|---|---|
| 회고 6파일 총 항목(`## ` 헤더) | 35개 |
| 회고→지침 승격 이력 (README 표) | 0건 |
| 회고/승격 키워드 commit | 0건 |
| 30일간 회고 commit | 24건 |
| 30일간 지침 commit | 22건 |
| 동명 회고·지침 페어 | 다수 (커뮤니케이션·Git 워크플로우 등) |
| 페어 내용 겹침 | 광범위 (동일 텍스트 다수) |

**`회고/README.md` 인용**
> "시간순으로 쌓이며, 일정 기간 검증된 회고는 `docs/지침/`으로 승격될 수 있습니다."
> "승격은 '효력 변경'이 아니라 '정리/통합' 차원이다. 회고에 있을 때도 이미 효력이 있었으며…"

**판단**: 설계상 "단기 인큐베이터 → 지침 승격" 구조이나, **실제로는 35건 중 0건 승격**으로 동작. 효력은 이미 동등하므로 두 레이어가 평행 누적되며 **이중 관리 비용**만 발생. **통합이 합리적**.

### 고민 2: 분할된 지침이 새 세션에서 자동 적용될까?

**데이터** (서브에이전트 D)

| 파일 종류 | 자동 주입 | 비고 |
|---|---|---|
| `~/.claude/CLAUDE.md` (글로벌) | ✅ | 사용자 메시지 형태 |
| `<cwd>/CLAUDE.md` (프로젝트) | ✅ | 동상 |
| 자식 `<dir>/CLAUDE.md` | ✅ (cwd 하위일 때만) | hierarchy |
| `docs/지침/*.md` 본문 | ❌ | Read 명시 호출 필요 |

**핵심 통찰**: 분할 여부와 무관하게 지침 **본문은 어차피 자동 주입 안 됨**. 분할이 자동 적용을 망가뜨리는 게 아니라, 자동 주입은 항상 **CLAUDE.md 인덱스**까지만.

**현 패턴 평가** ("세션 시작 첫 동작: Read 강제 + 보고")
- 의존도: Claude 자율 (긴 세션 시 약화 가능)
- 견고도: 중간 — 실제 본 세션에서도 정상 작동 확인됨

**판단**: 분할 자체는 안전. 단 "반드시 지켜야 할" 지침은 **CLAUDE.md에 인라인**하거나 **SessionStart Hook**으로 강제 주입하면 견고도 ↑.

### 고민 3: `작업 목록.md` ≈ `_modules.md`?

**데이터** (서브에이전트 B)

| 측면 | `_modules.md` | `작업 목록.md` |
|---|---|---|
| 행 단위 | **모듈** | **작업** |
| 컬럼 | 최종 업데이트·최근 작업·작업 수 | 작업명·모듈·태그·상태·시작·완료·폴더·연계·요약 |
| 갱신 시점 | 작업 종료 시 (자동, §6.1) | 작업 상태 변화 시마다 |
| 외부 소비자 | Wiki sync (모듈 변경 감지) | 사용자 (계획·진행) |
| 정렬 기준 | 모듈별 최종 업데이트 내림차순 | 작업별 상태·태그 |

**통합 시뮬레이션**
```
| 모듈 | 작업 | 상태 | 최종 업데이트 |
| meta | permanent-docs-to-wiki | 완료 | 2026-05-15 |
| meta | archive-modules-index | 완료 | 2026-05-15 |
```
→ 작업 12개를 모듈별로 모두 나열하면 `_modules.md`의 **요약 효과 상실**, Wiki sync는 헤더 필터 재구현 필요.

**판단**: 차원이 다르므로 **통합 불가**. 통합 시도는 손해. 대신 **명명·TL;DR로 차원 차이를 명시**하는 게 답.

### 고민 4: 작업 폴더 가시성 + plans + 5파일 표준화

**데이터** (서브에이전트 C)

| 항목 | 현황 |
|---|---|
| 작업 폴더 명명 | kebab-case 영문, **날짜 prefix 없음** |
| 표준 4파일(요구사항·분석·계획·이력) 준수율 | 12작업 중 9개 (75%) |
| 미준수 작업 사유 | 진행 중 단계 제약 (`분석` 또는 `계획` 누락) — 표준 위반 아님 |
| `plans` 임시 보관소 | **존재하지 않음** — 4단계 규칙으로 작업 폴더 내부 관리 |
| 작업 단위 날짜 가시성 | `_modules.md` "작업 상세" 섹션의 `완료일` 컬럼에서만 확인 (폴더 자체엔 없음) |

**작업 진행 규칙 §3 인용**
> Task α부터 `진행상황.md`를 폐지하고 `이력.md` 한 파일로 통합. 작업 시작 시점부터 진행 중 시계열로 누적하다가 완료 시 요약 섹션을 추가.

**사용자 제안 검증**

| 사용자 제안 | 데이터 판단 |
|---|---|
| 폴더명 날짜 prefix | ✅ 즉시 가시성 개선, 정렬 자연. **채택** |
| `plans/` 임시 보관소 | ✗ 불필요 — 작업 폴더 자체가 plans 역할(미시작 = 계획.md만 존재 가능). **기각** |
| 5파일 (요구→계획→분석→구현→이력) | △ "구현.md" 산출물 불필요(코드 자체가 산출). 순서도 "분석→계획"이 자연(분석 없이 계획 불가). **현 4파일 유지** |

## 2. 재설계 옵션

### 옵션 X — 회고·지침 통합 + 성숙도 라벨

**구조**
```
docs/지침/                       ← 회고+지침 통합 (폴더명은 유지 권장)
├── README.md
├── 일반/
│   ├── 커뮤니케이션 규칙.md       ← 회고/커뮤니케이션.md 흡수
│   ├── ...
├── Git/
│   └── 워크플로우.md             ← 회고/Git 워크플로우.md 흡수
└── 코딩/
    └── ...
```

**핵심**: 각 파일·각 섹션 frontmatter 또는 헤더 옆에 **성숙도 라벨**
```yaml
maturity: experimental | stable | core
```
- `experimental`: 최근 추가·검증 중 (현 회고 역할) — 작은 항목 단위
- `stable`: 정착된 룰 (현 지침 역할)
- `core`: 반드시 지켜야 할 핵심 (CLAUDE.md 인라인 후보, 옵션 Y와 연동)

**라이프사이클**
1. 신규 학습 → `experimental` 진입
2. 30일 또는 N건 재적용 후 → `stable` 승격
3. 절대 룰 → `core` 표시 + CLAUDE.md 인라인 (옵션 Y와 연결)

**효과**
- 35항목 이중 관리 비용 제거
- 효력은 이미 동등하므로 사용자 체감 변화 없음
- frontmatter 필터로 검색 가능 (예: `grep -rl 'maturity: core' docs/지침/`)
- 회고 README의 "승격은 효력 변경이 아니라 정리" 논리와 일관

**비용**: 일회성 마이그레이션 (회고 35항목 → 지침 흡수 + 라벨링) — 약 2시간

**위험**: `experimental` 누적 시 신뢰도 저하 → 분기별 정기 재검토 규칙 필요

### 옵션 Y — 핵심 지침 인라인 + 나머지 lazy-load

**Y-1. CLAUDE.md 핵심 인라인 (30분)**
- 현재: 루트 `CLAUDE.md`에 지침 **표만** (제목·링크) — 본문 자동 주입 없음
- 신: 핵심 체크리스트 **풀텍스트 인라인** (50~80줄 추가)
  - 후보: 세션 시작 Read 강제, 명령 모호 시 질문, 커뮤니케이션(존댓말), 서브에이전트 활용, 4단계 프로세스 요지
- 옵션 X와 연동: `maturity: core` 항목 자동 인라인 대상

**Y-2. SessionStart Hook (1시간, 환경 의존)**
- `.claude/settings.json`에 SessionStart Hook 설정 → 세션마다 핵심 지침 자동 출력
- 더 견고하나 환경(Windows·shell) 의존
- 본 프로젝트는 이미 Stop Hook(Slack 알림)·SessionStart Hook(CLAUDE.md 재확인) 검토 흔적 있음 — 추가 부담 낮음

**효과**: "반드시 지켜야 할" 지침 자동 적용 보장, 분할의 자동 적용 위험 해소

### 옵션 Z — 작업 폴더 가시성 + 명명 명확화

**Z-1. 작업 폴더 날짜 prefix (30분)**
- 현: `docs/tasks/meta/guideline-segmentation-analysis/`
- 신: `docs/tasks/meta/20260518_guideline-segmentation-analysis/`
- 효과: 폴더 정렬만으로 최신 작업 식별, 일일이 열어볼 필요 X
- 비용: 기존 12개 작업 일괄 rename + cross-link 갱신
  - cross-link: `_modules.md` 작업 상세 섹션·`작업 목록.md`·간헐적 회고 인용 정도 — 영향 범위 작음

**Z-2. 표준 산출물 4파일 유지 (변경 없음)**
- 현 4파일 = 사용자 5파일 - "구현.md" (코드가 곧 구현)
- 순서: 요구사항 → **분석** → **계획** → (구현=코드) → 이력
- 사용자 제안 "요구→계획→분석"은 현 표준과 어긋남 — 분석이 계획 입력값
- 이력.md 내부에 "결과 보고" 섹션 추가는 현재 컨벤션 내에서 가능

**Z-3. 인덱스 명명 명확화 (10분)**
- `_modules.md` → 유지하되 TL;DR에 "**모듈 헬스 인덱스 (Wiki sync용)**" 명시
- `작업 목록.md` → 유지하되 TL;DR에 "**작업 생애주기 추적 (계획·진행)**" 명시
- → 두 파일이 한눈에 차원이 다름을 인지
- 통합은 불가(고민 3 데이터 참조)

**Z-4. `plans/` 폴더 신설 — 기각**
- 작업 폴더 자체가 plans 역할 가능
- 미시작 작업은 `계획.md`만 있는 폴더로 표현 가능
- 별도 `plans/` 신설은 중복 + mv 부담

## 4. 패키지 추천

### Package A — 최소 변화 (1시간 10분)
- Y-1 (CLAUDE.md 핵심 인라인)
- Z-1 (폴더 날짜 prefix)
- Z-3 (인덱스 명명 명확화)
- → 가장 큰 사용자 통점 3건 해결 (자동 적용·가시성·혼란)

### Package B — 균형 변화 (반나절)
- Package A + 옵션 X (회고→지침 통합)
- → 의문 4건 중 1·3·4 해결 + 자동 적용 보강

### Package C — 풀 리팩토링 (1일+)
- Package B + 분석.md의 P1·P2 (거대 파일 분할) + Y-2 (Hook)
- → 모든 의문 해결, 단 작업량 많음

## 5. 시너지 — 옵션 간 결합 효과

```
옵션 X (maturity: core)
        ↓ "core" 항목을 자동 식별
옵션 Y-1 (CLAUDE.md 인라인)
        ↓ 인라인 대상이 명확
옵션 Y-2 (SessionStart Hook)
        ↓ "core" 항목만 자동 주입 강제 가능
```

→ X·Y는 단독 적용도 가능하나 결합 시 **자동화 가능**. X 없이 Y-1만 하면 "어느 게 core인지" 사람 판단 필요.

Z는 X·Y와 독립 — 어느 순서로든 진행 가능.

| 사용자 우선순위 | 추천 |
