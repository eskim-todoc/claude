### 무엇을 했는가

사용자가 제기한 4가지 거시 의문 — (1) 회고를 따로 관리하는 게 의미 있나, (2) 분할된 지침이 새 세션에 자동 적용될까, (3) list와 _modules는 사실상 같은 개념 아닌가, (4) 작업 폴더 가시성·plans·5파일 표준화 — 에 대한 데이터 검증을 거쳐 Package C 풀 리팩토링을 7개 atomic commit으로 실행했다. 핵심 변경: ① 회고 폴더 폐지(35항목 → 지침 6 파일 §학습 노트 흡수 + `maturity: core|stable|experimental` 라벨로 성숙도 보존), ② 거대 파일 2개 분할(`문서 작성 규칙.md` 494줄·`작업 진행 규칙.md` 224줄을 각각 인덱스 + 하위 3·2 파일로), ③ 작업 폴더 12개에 `YYYYMMDD_<slug>` 날짜 prefix 일괄 적용으로 정렬·가시성 확보, ④ 명명 변경 2건(`_modules.md`→`모듈 현황.md`, `이력.md`→`이력 및 결과.md`), ⑤ 루트 `CLAUDE.md`에 maturity:core 등급 7개 핵심 지침 풀텍스트 인라인으로 새 세션 자동 적용 보장, ⑥ SessionStart Hook으로 강조 메시지 시스템 차원 주입까지. 영향 50+ 파일·80+ 라인.

### 핵심 결정

- **회고 통합 결정 (옵션 X)**: 회고 README의 "검증된 회고는 지침으로 승격" 정의가 35건 중 0건 승격이라는 데이터 근거. 회고와 지침이 사실상 평행 누적 레이어로 동작하고 있어 이중 관리 비용만 발생. maturity 라벨(`core | stable | experimental`)로 성숙도를 보존하면서 단일 레이어로 통합. 라이프사이클은 `experimental` 진입 → 검증 후 `stable` 승급 → 절대 룰은 `core` 표시.
- **분할 안전성 보장 (Y-1·Y-2)**: 서브에이전트 D 조사로 "CLAUDE.md만 자동 주입, 본문은 분할 여부 무관하게 Read 명시 호출 필요" 확인. 분할 자체는 자동 적용에 영향 없으므로 거대 파일 분할 진행. 핵심 지침은 CLAUDE.md `§핵심 지침` 인라인 + SessionStart Hook 강조 메시지로 3중 안전망 구축.
- **list/_modules 통합 거부 + 명명 명확화 (Z-3)**: 두 파일이 작업 단위 생애주기 vs 모듈 단위 헬스 스냅샷으로 차원이 다름(서브에이전트 B 데이터). 통합 시 정렬 모순 + Wiki sync 로직 복잡화. 통합 대신 명명만 신 명명으로 변경.
- **폴더 날짜 prefix (Z-1) + plans 폴더 거부 + 5파일→4파일 유지**: 작업 폴더명에 `YYYYMMDD_<slug>` 적용으로 정렬만으로 시간순 식별 가능. plans 별도 보관소는 불필요(작업 폴더 자체가 미시작 시 plans 역할). "구현.md" 산출물 불필요(코드 자체가 구현). 사용자 제안 "요구→계획→분석" 순서는 분석이 계획 입력값이라 "요구→분석→계획"이 자연.
