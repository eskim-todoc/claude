# 분석: 루트 지침 세분화 가능성

**TL;DR**: 현 구조(16파일·2레벨)는 이미 회고(6파일·1레벨)보다 세밀. 전역 313회 인용으로 죽은 지침 0개. 일률 추가 분할은 인덱스·cross-link 비용이 이득을 초과 → **선택적 분할 권장**. P1 `문서 작성 규칙.md` 494줄·14섹션·136회 인용을 인덱스+3 하위로 분할, P2 `작업 진행 규칙.md` 224줄·13섹션·106회 인용을 4단계/완료처리 2개로 분할, P3 루트 `CLAUDE.md` 인덱스 표에 `계획 모드 자동 진입.md` 1행 누락 보강. 나머지 13파일은 유지 — 분할 임계점(>300줄+>10섹션+책임 다름) 미달.

## 1. 분석 목적과 방법

**질문**: "루트 기반으로 작성된 모든 지침들을 더 세분화 시켜서 관리해야 컨텍스트 및 AI 기억에 도움이 될까?"

**방법**: 서브에이전트 3개 병렬 조사
- (A) `docs/지침/` 16파일 메타데이터 수집 (Explore agent)
- (B) `docs/회고/` 분할 모델 + 전역 인용 빈도 (Explore agent)
- (C) 산출물 저장 위치 컨벤션 확인 (Explore agent)

## 3. 세분화 트레이드오프 — 가설별 평가

### 가설 A: "더 세분화하면 도움된다"
**찬성**
- 거대 파일(>300줄)은 `frontmatter+TL;DR`만 보고 필요성 판단하기 어려움 → 전수 읽기 강제 → lazy-load 깨짐
- 단일 책임 분할 시 `Grep` 매칭 정확도 ↑, 변경 시 git diff 좁아짐
- 필요한 섹션만 `Read`로 로드 → 컨텍스트 절약

**반대**
- 인덱스 행 수 증가 → 루트 `CLAUDE.md` 표 가독성 ↓
- cross-link 313건 중 일부 마이그레이션 필요 (일회성)
- "어디서 찾지?" 의사결정 비용 — 짧은 파일이 너무 많아지면 검색 분산

### 가설 B: "현재가 적정"
- 평균 ~150줄 → 한 번에 읽기 부담 없음
- 도메인 분리(일반/Git/코딩) 이미 명확
- 무분별한 분할은 과적합

### 가설 C: "오히려 통합이 낫다"
- 가장 짧은 3파일(커뮤니케이션 42·구현 패턴 41·README 25) 흡수 시?
- → 효과 미미. 단일 책임 잃어 체크리스트 역할 약화 → **기각**

### 결론
- 가설 A의 **선택적 적용** + 가설 B의 **큰 틀 유지**
- 분할 임계점: `>300줄 + >10섹션 + 섹션 간 책임 다름` 모두 충족 시

## 4. 권장 액션 (우선순위)

### P1 — `문서 작성 규칙.md` 분할 (494줄 · 14섹션 · 136회 인용)

**현 구조 (대표 섹션)**

- §3: 폴더 구조 (2레벨 고정)

- 그 외: 페이지 컨벤션·링크·이미지·코드블록

**분할안 (인덱스 + 3 하위 파일)**

| 새 파일 | 내용 | 추정 줄 수 |
|---|---|---|
| `지침/일반/문서 작성 규칙.md` (인덱스로 축소) | 진입점, 4개 하위 링크, 공통 원칙 | 30~50 |
| `지침/일반/문서/폴더-구조.md` | 현 §3 (2레벨 고정·tasks 레지스트리) | 100~130 |
| `지침/일반/문서/메타-frontmatter.md` | 현 §9 (frontmatter·TL;DR·README) | 80~100 |
| `지침/일반/문서/작성-스타일.md` | 현 §6 (GFM·Alert·Mermaid·코드블록) | 150~180 |

**효과**: lazy-load 효율 30~50% → 70~80% (추정). "폴더 구조만 알고 싶을 때" 100줄만 로드, 전체 로드 불필요.
**비용**: cross-link 136건 중 ~30%만 신규 경로로 재타게팅 필요. 다수는 인덱스 페이지가 흡수 → 마이그레이션 부담 낮음.

## 5. "AI 기억"에 대한 답

사용자 질문의 핵심 후반부에 대한 응답:

**현 메커니즘**
1. 세션 시작 시 루트 `CLAUDE.md`만 자동 주입 → 표만 인덱스로 인지
2. 필요 시 `Read`로 지정 지침 로드 (lazy-load)

**세분화 영향 분석**

| 측면 | 변화 |
|---|---|
| 인덱스 표 (자동 주입) | 행 증가 → 인지 부담 약간 ↑ |
| 지정 로드 (필요 시) | 더 정확히 필요한 부분만 로드 가능 → 컨텍스트 절약 |
| 시맨틱 검색 (`Grep`) | 단일 책임 분할 시 매칭 정확도 ↑, false positive ↓ |
| 갱신 비용 | 일회성 마이그레이션 + 이후 갱신은 동일 |

**결론**: 매번 모든 지침을 전수 로드하지 않으므로 (2)·(3)의 이득이 (1)의 손실보다 큼. 단, 무분별한 분할은 (1)을 초과 부담시킴 → **거대 파일에 한해 분할이 순이득**.

## 7. 부수 발견

### 7.1 루트 인덱스 ↔ 실제 파일 정합성 (P3 근거)
- 루트 `CLAUDE.md` 일반 그룹 표: **8행** (CLAUDE.md L62~69 인용)
- 실제 `docs/지침/일반/` 폴더: **9파일**
- **누락 1건**: `계획 모드 자동 진입.md` — 핵심 지침 누락 영향 큼

### 7.2 cross-link 구조
- 지침 폴더 내부 상호 인용은 낮음 (마스터 ↔ 서브 위주)
- 루트 `CLAUDE.md` + `docs/지침/README.md`가 인덱스 허브 역할
- → 분할 시 두 허브 갱신만으로 대부분 정합성 회복

### 7.3 회고에서 배울 점
- 회고는 1레벨 카테고리로도 충분히 작동 (평균 70줄·6파일)
- 지침은 책임 영역이 더 넓어 2레벨이 정당화됨
- 거대 파일을 회고 수준 분할 깊이(평균 70~100줄)로 줄이는 게 P1·P2의 목표선

## 8. 후속 처리 (사용자 결정 영역)

본 분석은 **분석.md 단일 파일**만 작성. 사용자가 "파일 하나만"으로 명시한 만큼 다음은 보류:

| 보류 항목 | 사유 | 활성화 조건 |
|---|---|---|
| `요구사항.md` 작성 | 4단계 ① 단계 — 본 작업이 분석 한정이라 미작성 | P1·P2·P3 실제 실행 결정 시 |
| `계획.md`·`이력.md` 작성 | 4단계 ③④ 단계 — 분석 한정 | 동상 |
| `docs/tasks/_modules.md` 갱신 | "파일 수정 금지" 지시 | 사용자 승인 시 |
| `docs/tasks/meta/작업 목록.md` 갱신 (있다면) | 동상 | 동상 |

**중요**: 본 폴더(`docs/tasks/meta/guideline-segmentation-analysis/`)와 본 분석.md만 신규 생성됨. `_modules.md` 인덱스에는 반영되지 않은 상태(일시적 정합성 어긋남). 사용자 후속 결정에 따라 표준 작업으로 승격하거나 폐기.

## 9. 결론 한 줄

**현 구조는 "선택적 분할"이 답**. 일률 세분화는 비효율, 일률 통합은 손실. 거대 파일 2개 분할 + 루트 인덱스 1건 보강이 ROI 최대.
