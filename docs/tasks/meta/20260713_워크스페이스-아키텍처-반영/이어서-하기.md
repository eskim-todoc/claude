# 이어서 하기 — 워크스페이스 아키텍처 개편 지침 반영

> [!IMPORTANT]
> **새 세션 첫 동작**: ① 루트 `CLAUDE.md` Read 후 한 줄 보고(의무) → ② 이 파일을 읽었으면 아래 §5 계획대로 **바로 ④ 구현 착수**. 요구사항/분석/계획 표준 4문서는 구현 첫 커밋에서 함께 작성한다(4단계 산출물 의무). 은수님이 "모든 권한" 표명 + 계획 사전 합의 완료 상태이므로 재승인 없이 무중단 실행하되, 진짜 판단이 필요한 지점만 질문.

## 1. 한 줄 요약

저장소 구조가 `E:\Claude` 단일 git(그 아래 `projects/` 중첩)에서 `E:\workspace\`(git 아닌 엄브렐러) 아래 `rules/`(헌법 저장소)와 `projects/<name>/`(형제 독립 repo)로 바뀌었다. 이 변화를 헌법·지침 전반에 반영한다.

## 2. 배경 (왜)

- 옛 구조: `E:\Claude\` = 단일 git repo. 그 안에 `projects/<name>/`가 중첩된 독립 repo(git-under-git), gitignored.
- 새 구조: `E:\workspace\` = git 아닌 로컬 엄브렐러 폴더. 그 아래 `rules/`(이 저장소 = 헌법·지침)와 `projects/<name>/`가 **형제 독립 repo**. 각자 자기 `.git`. git-under-git 소멸.
- 은수님 워크플로우 변경: 이제 rules에서 `projects/` 하위를 세팅하지 않는다. 새 프로젝트는 은수님이 직접 `workspace/projects/<name>/`로 clone → **그 프로젝트 폴더에서 세션을 열고** → 루트 헌법을 참조해 in-place 세팅하도록 명령한다.

## 3. 확정 결정 (AskUserQuestion, 2026-07-13)

- **결정 1 — 중앙 Projects 레지스트리: 완전 폐지.** rules는 프로젝트 목록을 추적하지 않는다. 각 프로젝트는 자기 CLAUDE.md로 self-describing. (근거: 현재 `workspace/projects/`에 옛 표에 없는 프로젝트 다수 — 이미 현실과 어긋남.)
- **결정 2 — 머신 경로 표기: 구조 중심 서술 + 예시.** "workspace 엄브렐러 아래 rules + projects 형제" 구조로 서술하고 구체 경로는 `E:\workspace` 예시로만. 기술적으로 절대경로가 필요한 훅/설정만 실경로.
- **결정 3 — 크로스 repo 참조: 절대경로 표준.** wiki 등 다른 저장소 참조는 `E:\workspace\...` 절대경로(또는 전역 CLAUDE.md 포인터).

## 4. 현재 상태 (인수 시점)

- **브랜치**: `claude_feature_워크스페이스-아키텍처-반영` 생성됨(현재 커밋 없음, `claude_develop` 8195dc5 기반). 새 세션은 이 브랜치로 체크아웃하거나, 없으면 `claude_develop`에서 새로 만든다.
- **격리 가드**: `.claude/settings.json`에 `"worktree": {"bgIsolation": "none"}` 추가됨. **새 세션부터** 이 repo에서 메인 체크아웃 직접 편집 가능(옛 세션은 시작 시 캐시라 막혔음).
- **작업 폴더**: `docs/tasks/meta/20260713_워크스페이스-아키텍처-반영/` (이 파일 존재).
- **미완**: 표준 4문서(요구사항/분석/계획/이력)와 실제 지침 편집 전부 미착수.
