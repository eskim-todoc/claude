# 분석 — 워크스페이스 아키텍처 개편 지침 반영

**TL;DR**: `grep "E:\Claude|E:/Claude"`로 38개 파일이 걸렸고, 그중 과거 `docs/tasks/**` 스냅샷(범위 외)을 제외한 **활성 파일 15종**이 편집 대상이다. 계획 §5에 명시된 12종 외에 `rename_sessions.README.md`·`.claude/memory/{github,preferences}.md` 3종이 추가 발견되어 성격에 맞는 Step에 편입한다. `위키 배경지식 조회.md`는 `E:\Claude`는 없지만 `projects/wiki` 상대경로 전제가 있어 절대경로화 대상.

## 3. 핵심 편집 판정

### 3.1 중첩 repo 전제 (Git 규칙)

- 옛 서술: "작업이 일어난 디렉토리가 아닌 **변경 파일 경로 기준**으로 repo 결정. 루트에서 세션 열고 `projects/<이름>/` 내부 작업해도 그 변경은 프로젝트 repo에." — 이는 git-under-git 전제.
- 새 서술: "**세션이 열린 저장소 = 작업 대상 repo. 각 repo 독립, 한 세션 한 repo.**" 형제 구조에서는 rules 세션에서 다른 프로젝트 파일이 애초에 보이지 않으므로 "혼합 변경" 시나리오 자체가 소멸.

### 3.2 중앙 Projects 레지스트리 (결정 1)

- `CLAUDE.md` L93~115 Projects 표 + `프로젝트 초기 세팅.md` 단계 ④(루트 표 갱신)·단계 ⑤(루트 repo push)가 레지스트리 유지를 전제 → **전량 제거**.
- "프로젝트 내부 표준 구조" 소절은 세팅 절차가 참조하므로 **유지**.

### 3.3 크로스 repo 참조 (결정 3)

- wiki는 이제 `E:\workspace\projects\wiki` 형제 repo. `projects/wiki` 상대경로(rules 기준)는 더 이상 유효하지 않음 → 절대경로.
- 프로젝트 CLAUDE.md 템플릿의 `../../CLAUDE.md`(중첩 전제) → `E:\workspace\rules\CLAUDE.md` 절대경로.

### 3.4 기능 파일 무음 실패 (실제 버그)

- `.claude/settings.json` L20 slack 훅이 `E:/Claude/tools/slack-notify.ps1`를 가리켜 **현재 알림이 무음 실패 중**. 실경로로 복구가 실제 버그 수정.
- `rename_sessions.py`의 `CREDENTIALS_FALLBACK`도 옛 경로 → 실경로.

## 4. 추가 세팅 반영 (신규 요구)

- 표준 폴더 세트에 `.claude/settings.json`(내용 `{"worktree":{"bgIsolation":"none"}}`) 포함. 백그라운드 세션이 각 프로젝트 메인 체크아웃을 바로 편집 가능하게. repo별 설정이라 프로젝트마다 필요.

## 5. 접근

- 단계 ④ 편집은 오케스트레이터(세션) 직접 수행 — 여러 파일에 걸친 정밀 편집이라 서브에이전트 위임보다 직접이 정확. 트리거어도 없음.
- 커밋은 계획 §5의 Step 경계를 따라 atomic 6개로 분리.
