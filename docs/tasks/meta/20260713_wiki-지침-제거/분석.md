# 분석 — wiki 참조 전수 조사 및 처리 판정

**TL;DR**: `grep "wiki|Wiki|위키|Obsidian|Vault"`로 활성 16파일이 걸렸다. (가) wiki 운영·반영·조회 지침, (나) docs 구조의 wiki 의존 문구, (다) Obsidian 테마(유지 대상)로 분류한다. (가)·(나)는 제거·정리, (다)는 보존. `.gitignore`의 `.obsidian/`은 앱 메타 무시 규칙이라 무관하게 유지.

## 1. 조사

```bash
grep -rn "wiki|Wiki|위키|Obsidian|Vault|vault" 지침/ CLAUDE.md .gitignore  # docs/tasks 스냅샷 제외
```

활성 16파일 매칭. 성격별 3부류 + 무관 1건으로 분류.

## 3. 부류 (나) — docs 구조의 wiki 의존 문구 → **걷어냄**

자동 동기화("wiki가 pull") 시절의 잔재. wiki 의존을 제거하고 문구를 rules 자립적으로 정리.

> [!NOTE]
> `모듈 현황.md`는 원래 "Wiki가 rules를 pull해 sync할 때 진입판단용"으로 설계된 인덱스다. wiki 자동 sync가 폐지되므로 "외부 sync 진입판단용"이라는 존재 이유가 사라진다. 다만 파일 자체(모듈별 최종 업데이트 인덱스)는 완료처리 흐름이 갱신하는 유용한 헬스 지표이므로 **유지하되, "Wiki sync" 목적 문구만 제거**하고 "모듈 헬스 스냅샷"으로 목적을 재서술한다.

## 5. 무관 — 유지

- `.gitignore` L29 `# Obsidian workspace metadata` + `.obsidian/` — Obsidian 앱이 만드는 로컬 메타 무시 규칙. wiki 운영과 무관, 유지.

## 6. 판단 지점 (계획에서 확정)

- **slack 사용법 링크** (`CLAUDE.md` L94·L158): slack-notify.ps1은 rules 도구인데 사용법 문서가 형제 wiki repo에 있다. wiki를 "잊는" 취지에는 링크 제거가 맞으나, 사용법 위치 안내라는 정보 가치가 있다. → **계획 §에서 최소 정보(형제 repo 경로)만 남기는 방향으로 처리**, 은수님 승인 시 확정.
- **한 세션 한 repo 원칙**: wiki repo 파일은 이 세션에서 건드리지 않는다. rules 쪽 제거만 수행하고, wiki 자체 지침 신설은 은수님이 wiki 세션에서.
