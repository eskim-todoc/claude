## 3. 가설·선택지

### 3.1 가설 (root cause·디버깅)

해당 없음 — 신규 지침 저술 작업(디버깅 아님).

### 3.2 선택지 (설계 결정)

**선택지_A — 밸리데이션 §4 오디오 예시·§5 CFX 온타깃 처리** (위임_3)

| 선택지 | 장점 | 단점 |
|---|---|---|
| 도메인 중립 예시로 교체 + §5 일반화 | 루트 지침으로 자기완결, 임베디드 외 작업에도 적용 | 원본의 구체성 일부 상실 |
| 예시 전면 배제(추상 규칙만) | 가장 짧음 | 계층 개념이 추상적이라 예시 없으면 적용 난이도↑ |
| 프로젝트 예시 그대로 유지 | 작업량 최소 | 루트 지침에 Sound1 도메인 침투 — SSOT 원칙 위배 |

→ **도메인 중립 예시로 교체 + §5 일반화 채택**. 계층 개념은 예시 없이는 오해 소지가 크고(유닛↔모듈 승격 오해가 원본 §2.1의 핵심 경고), CFX 온타깃 모델의 알맹이("테스트 코드는 삽입하지 않고 테스트 가능한 구조만 준비", "단순 유닛은 로직 설명으로 갈음")는 벤더 무관한 유용 원칙이라 고유명만 제거하면 승격 가치가 크다.

**선택지_B — 레지스터 지침의 적용 예시**

| 선택지 | 장점 | 단점 |
|---|---|---|
| 범용 MCU 예시로 교체(타이머 prescaler 등) | 벤더 중립 + 구체성 유지 | 예시 창작 필요 |
| 예시 삭제 | 짧음 | 5게이트 적용법이 추상적으로만 남음 |

→ **범용 MCU 예시로 교체**. 원본 예시의 가치는 "불확실 2건 → 실기 전 추가 확인"이라는 판정 흐름 시연이므로, 도메인만 바꿔 보존.
