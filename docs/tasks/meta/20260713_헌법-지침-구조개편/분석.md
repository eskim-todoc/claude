# 분석 — 헌법·지침 구조 현황 및 개편 방향

**TL;DR**: 서브에이전트 9노드 병렬(general-purpose·sonnet, 245 tool-use, ~1M 토큰)로 현 구조를 심층 조사했다. 핵심 진단: (1) **진입점 3중복이 이미 drift 발생** — CLAUDE.md 지침표와 README표가 서로 다른 파일을 누락(에이전트로그구조↔커밋메시지 교차 누락). (2) **온디맨드 무결성 취약** — README는 CLAUDE.md에서 inbound 링크 0, 깨진 상대경로 다수, deprecated 파일을 현재형으로 인용하는 5곳. (3) **폴더가 결합도를 반영 못함** — 서브에이전트 3종·문서/테마/양식이 흩어짐. (4) 중복 규칙(Git Identity 6곳+, 서브에이전트 위임정책 4곳 등)이 실제 drift를 유발 중. 원본 조사는 [`첨부_분석_현황조사-9관점.json`](첨부_분석_현황조사-9관점.json).

## 1. 조사 방법

`restructure-analysis` 워크플로우 — 9개 관점을 general-purpose 서브에이전트로 병렬 fan-out, 각자 실제 파일을 Read/Grep해 구조화 findings 반환. 원본 전량은 첨부 JSON(941줄) 보존.

## 2. 요구사항별 핵심 발견·처리 방향

### R1 진입점 3중복 (CLAUDE.md · README · 작업 규칙.md)
- **발견**: 세 파일이 사실상 같은 인덱스/규칙을 세 벌 유지. 이미 실측 drift — 계획모드 maturity 오기재, 에이전트로그구조(CLAUDE 누락)↔커밋메시지(README 누락) 교차 누락. `커밋 메시지.md`는 CLAUDE표 없으면 링크 그래프에서 유실.
- **핵심 트레이드오프**: CLAUDE.md §핵심지침은 "maturity:core 풀텍스트 인라인 → 세션 자동 주입 보장"이 **의도된 설계**. 단순히 링크로 치환하면 이 안전장치가 사라진다.
- **처리 방향**: ① **인덱스 표는 `지침/README.md` 단일 SSOT**로, CLAUDE.md는 표 삭제 후 README로 라우팅 링크. ② **상세 규칙은 `작업 규칙.md` 체크리스트 단일 원문**, CLAUDE.md는 각 규칙 1줄 초압축 명령형 + 링크. ③ CLAUDE.md core 인라인은 **완전 제거하지 않고 "초압축 명령형 1줄"로 유지**(자동 주입 안전장치 보존) — 상세는 전량 링크 위임. ④ 통합 전 README표 3건 drift부터 선(先) 정정(누락 파일 유실 방지).

### R2 서브에이전트 폴더 분리
- **발견**: 서브에이전트 활용·워크플로우 오케스트레이션·에이전트 로그 구조 3파일이 `일반/`에 평평하게 위치. 상호링크 20건+로 사실상 한 도메인. CLAUDE.md는 에이전트로그구조 누락, README는 워크플로우오케스트레이션 누락.
- **처리 방향**: `지침/서브에이전트/`(Git·코딩과 동급 **2레벨 최상위 카테고리**) 신설, 3파일 이동. 폴더명 중복 회피 위해 파일명 접두어 제거(→ `활용.md`·`오케스트레이션.md`·`로그 구조.md`). `지침/서브에이전트/README.md` 신설(언제 어느 파일). 관련 링크(8파일 ~15곳) 갱신.

### R3 4단계 검증 하네스 (할루시네이션 방지)
- **발견**: 4단계-프로세스.md는 산출물 형식·자체검토는 규정하나, **각 단계에서 사실·링크·근거를 강제 검증하는 하네스가 약함**. (별도 조사 aspect 없이 요구사항 기반 설계 필요.)
- **처리 방향(설계 단계 상세화)**: 각 단계에 **검증 게이트** 명문화 — ① 요구사항: 사용자 의도 재진술+모호점 질문 강제. ② 분석: "읽고 인용(파일·라인)" 원칙, 추측 금지, 근거 링크 필수. ③ 계획: 자기 반박(왜 틀릴 수 있나) 1스텝. ④ 구현: 편집 후 grep 재검증·링크 무결성 확인. 서브에이전트 활용 시 adversarial-verify 연계.

### R4 문서·테마·양식 통합
- **발견**: '문서가 어떤 형태여야 하는가'라는 한 관심사가 `문서 작성 규칙.md`+`문서/`, `문서 테마 스타일.md`+`테마/`, `작업/양식/` 3갈래로 분산. 양식 4파일은 두 마스터 인덱스(CLAUDE·README) 어디에도 없는 고아 브랜치.
- **처리 방향**: `지침/일반/문서/`를 문서형식 단일 홈으로 — `문서 테마 스타일.md`→`문서/테마 스타일.md`, `테마/`→`문서/테마/`, `작업/양식/`→`문서/양식/`. `문서/README.md` 신설. 이동 후 상대링크 깊이 재계산(첨부 JSON에 이동 매핑표·링크 방향성 주의 상세).

### R5 설정 폴더 신설 + tools 정리
- **발견**: **statusline·스피너 한글 설정은 rules 밖 사용자 홈(`~/.claude/settings.json`·`statusline.ps1`)에만 존재, rules에 설명 문서 0건.** slack은 배선(.claude/settings.json)·실행(tools/slack-notify.ps1)·credential은 rules에 있으나 사용법은 형제 wiki repo. **tools/ 4파일 전부 실사용 — 삭제 대상 0건.**
- **처리 방향**: `지침/설정/` 신설해 **환경설정 설명 문서를 새로 작성**(slack 알람 배선·statusline·스피너 한글). 실행 파일은 tools/ 유지하되 **statusline은 사용자 홈 고정(예외 명시)**. tools 삭제 없음(요구사항 R5의 "불필요 파일 제거"는 tools엔 해당 없음 — 문서에 명시).

### R6 credentials → tools/credentials
- **발견**: 런타임 깨지는 참조 **정확히 2곳** — `slack-notify.ps1` L4(상대경로, 실패 시 silent exit 0 → 반드시 수동 테스트), `rename_sessions.py` L25(하드코딩). **`.gitignore`는 수정 불필요**(`credentials/` 패턴이 앵커링 없어 어느 깊이든 매치 — git check-ignore 실측). 문서 참조(CLAUDE.md·memory/github.md·프로젝트초기세팅·rename README) 갱신 필요. credentials/README.md stale(4종 중 2종만), `github/ssh-key` 참조 0건(고아 후보 — 삭제는 사용자 확인 필요, 이번엔 이동만).
- **처리 방향**: `credentials/`→`tools/credentials/` `git mv`, 참조 2곳 코드 수정 + 문서 참조 갱신 + slack 훅 수동 테스트. .gitignore 주석만 선택적 갱신.

### R7 Projects 경로/아키텍처 잔재
- **발견**: CLAUDE.md Layout에 `Sound1` 박제(레지스트리 폐지 취지 위배 — 자기모순). §프로젝트 내부 표준 구조 ASCII 트리 = 프로젝트 초기 세팅.md와 중복(이미 drift). 작성-스타일.md `projects/mermaid-study` 상대경로 3건 깨짐(off-by-one `../`). 문서 테마 스타일.md Sound1 각주 폴더명 실제와 다름(`sound1-fw-e8300`).
- **처리 방향**: Layout `projects\` 하위를 `<name>\` 플레이스홀더로. §표준구조 트리 삭제→세팅 문서 링크. 깨진 상대경로 3건 수정(또는 워크스페이스 절대경로). Sound1 각주 일반화.

### R8 중복 지침 공통 추출
- **발견**: Git Identity(`김은수 <eunsu.kim@to-doc.com>`) 6곳+, 서브에이전트 위임정책 4곳(drift 발생), maturity 정의(README↔메타-frontmatter 중복), 라벨링 규칙 3곳, tdc_ 접두어 3곳, GFM+Alert+Mermaid 4곳. 커뮤니케이션 규칙.md는 본문↔학습노트 자체 중복.
- **처리 방향**: 각 중복 항목 **단일 SSOT 지정 + 나머지는 1줄+링크**. SSOT 매핑: Git Identity→브랜치,병합 규칙.md / 라벨링·GFM→작성-스타일.md / tdc_→네이밍 컨벤션.md / maturity 정의→메타-frontmatter.md / 서브에이전트 위임→서브에이전트/활용.md. **의도된 이중화(CLAUDE 요약 vs 상세)와 비의도 중복(상세끼리 베낌) 구분** — 후자만 제거. "공통 종류(용어집/공통 폴더)" 신설은 항목이 흩어진 정도를 보고 설계에서 판단.

### R9 온디맨드 링크 무결성
- **발견(깨진/약한 링크 목록)**: ① README inbound 0(CLAUDE.md→README 링크 없음). ② 작성-스타일.md projects 상대경로 3건 off-by-one. ③ 컨텍스트 절약 규칙.md §6 `docs/회고/커뮤니케이션.md` 죽은 링크(회고 폴더 폐지됨). ④ 계획모드(deprecated) 현재형 인용 5곳. ⑤ 문서 테마 스타일.md Sound1 각주 폴더명 오류.
- **처리 방향**: 개편 완료 후 **온디맨드 검증 workflow**로 첫 진입점부터 전 링크 추적·시나리오 테스트(R10). 위 5건 포함 전수 수정.

## 3. 설계 결정 지점 (자율 진행 — 판단 근거 기록)

은수님이 "미리 커밋 후 구현까지 자율 진행"을 지시했으므로, 아래 트레이드오프는 설계 단계에서 **근거와 함께 결정**하고 문서화한다(사후 은수님 검토·롤백 가능).

| 결정 | 선택(잠정) | 근거 |
|---|---|---|

| 상세 규칙 SSOT | **작업 규칙.md 체크리스트** | core 라벨 취지(자동 적용)와 정합. |
