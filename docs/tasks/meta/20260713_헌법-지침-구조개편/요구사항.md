# 요구사항 — 헌법·지침 구조 전면 개편

**TL;DR**: rules의 헌법·지침 구조를 개편해 (1) 온디맨드 단일 진입점을 확립하고 중복(CLAUDE.md·README·작업 규칙)을 제거, (2) 서브에이전트·문서·설정 관련 지침을 각 전용 폴더로 재편, (3) 4단계 프로세스에 할루시네이션을 막는 빡센 검증 하네스를 심고, (4) credentials를 tools 하위로 옮기고 불필요 파일을 정리하며, (5) 지침 간 중복을 공통 종류로 추출하고, (6) 첫 진입점부터 모든 지침이 온디맨드로 링크 무결하게 참조되도록 만든다. 구조 설계·검증에 서브에이전트를 대량 투입한다.

## 1. 배경 (왜)

현 구조는 반복적 증설로 다음 문제가 누적됐다:
- **진입점 중복**: `CLAUDE.md`(핵심지침 인라인+지침표)·`지침/README.md`(지침 인덱스 표)·`지침/작업 규칙.md`(마스터 체크리스트)가 사실상 같은 인덱스 역할을 세 벌 유지.
- **폴더 혼재**: 서브에이전트 관련 지침(`서브에이전트 활용`·`워크플로우 오케스트레이션`·`에이전트 로그 구조`)이 `일반/`에 흩어짐. 문서·테마 지침도 인덱스와 하위가 분산.
- **검증 취약**: 4단계 프로세스가 산출물 형식은 규정하나, 각 단계에서 사실·링크·근거를 검증하는 하네스가 약해 할루시네이션 여지가 있음.
- **경로 잔재**: 과거 단일 git·중첩 projects 전제의 경로·아키텍처 서술이 곳곳에 남음.
- **온디맨드 미보장**: 첫 진입점에서 출발해 모든 지침에 링크로 도달 가능한지 체계적으로 검증된 적 없음.

## 2. 요구사항 (은수님 지시, 2026-07-13)

| # | 요구사항 | 핵심 |
|---|---|---|
| R1 | 진입점 중복 제거 | `CLAUDE.md`·`README.md`·`작업 규칙.md`의 중복 내용을 간소화. CLAUDE.md는 **온디맨드의 첫 시작 지점**(지침 폴더를 가리키는 진입점)으로. 단, 지침/docs 계층 구조와 정합하게 설계. |
| R2 | 서브에이전트 폴더 분리 | 서브에이전트 관련 지침을 전용 폴더로 모음(현재 `일반/`에 혼재). |
| R3 | 4단계 검증 하네스 | 4단계 프로세스에 **할루시네이션 방지 = 빡센 검증** 역할을 강화. 각 단계에서 사실·링크·근거 검증을 강제. |
| R4 | 문서·테마 양식 통합 | 문서·테마 등 양식 관련 지침을 하나의 폴더로 모음. |
| R5 | 설정 폴더 신설 | `설정/` 폴더 신설 — slack 알람·statusline·스피너 한글 설정 등 **환경설정 문서**를 한곳에. 실행할 `.ps1`은 여전히 `tools/`. **tools의 미사용/불필요 파일 조사·제거.** |
| R6 | credentials → tools 하위 | credentials를 tools 밑으로 이동(깔끔한 도구 계층). |
| R7 | Projects 경로/아키텍처 잔재 제거 | 관리 방법이 아닌 **경로·아키텍처·폴더 구조**에 대한 Projects 잔재 지침을 조사·제거. |
| R8 | 중복 지침 공통 추출 | 서브에이전트·코딩·git·일반 등에서 중복 언급되는 지침을 **공통으로 묶어 새 종류로** 만들고 온디맨드로 링크. |
| R9 | 온디맨드 링크 무결성 | 첫 시작점 기준 **모든 지침이 온디맨드로 참조 가능**해야 함. 링크 연결을 **빡세게 검증**. |
| R10 | 서브에이전트 대량 투입 | 구조 설계·검증에 서브에이전트 대량 투입 — **구조 잡기+구조 검증 ≥ 50%**, **구현 후 온디맨드 충족 검증 ≥ 30%**. 직접 온디맨드 시나리오 테스트 포함. 모든 결과 문서화. |

## 3. 실행 방식 (은수님 명시)

- **승인 대기 없이 미리 커밋 후 구현까지 자율 진행.** 은수님은 결과 문서를 보고 아니면 커밋을 복원. → 각 단계를 **잘게 커밋**해 롤백 지점을 촘촘히 남긴다.
- **서브에이전트 대량 오케스트레이션.** 구조 설계·검증이 서브에이전트 총량의 50%, 구현 검증이 30%.
- **모든 결과 문서화.** 분석·설계·검증·구현·온디맨드 테스트 결과를 작업 폴더에 남긴다.

## 4. 목표 산출물 구조 (방향, 설계 단계에서 확정)

- 온디맨드 진입: `CLAUDE.md`(첫 시작점, 최소 골격 + 온디맨드 라우팅) → 지침 카테고리 → 개별 지침. 중복 제거.
- 폴더 재편 후보: `지침/서브에이전트/`, `지침/문서/`(테마·양식 흡수), `지침/설정/`, `지침/공통/`(중복 추출), `tools/credentials/`.
- 4단계 검증 하네스: 각 단계 산출물에 **검증 체크·근거 링크·자기 반박** 스텝을 명문화.

## 5. 완료 기준

- [ ] 진입점 3중복(CLAUDE.md·README·작업 규칙) 해소 — 역할 분리·중복 제거.
- [ ] 서브에이전트·문서/테마·설정 지침이 각 전용 폴더로 재편.
- [ ] `설정/` 폴더 신설(slack·statusline·스피너 등) + tools 불필요 파일 제거.
- [ ] credentials가 `tools/` 하위로 이동 + 참조·gitignore 갱신.
- [ ] Projects 경로/아키텍처 잔재 제거.
- [ ] 중복 지침 공통 종류로 추출.
- [ ] 4단계 프로세스에 검증 하네스 명문화.
- [ ] **온디맨드 링크 무결성 100%** — 첫 진입점에서 모든 지침 도달 가능, 깨진 링크 0(서브에이전트 검증 + 시나리오 테스트).
- [ ] 설계·검증·구현·테스트 결과 문서화, 작업 목록·모듈 현황 등재, `claude_develop` 병합.

## 6. 범위 외

- 각 지침의 **내용(정책) 자체의 재작성** — 본 작업은 **구조·중복·링크·검증 하네스** 개편이 핵심. 내용은 이동·병합·중복 제거 과정에서 최소 변경.
- wiki repo(형제) 관련 — 이미 분리 완료(2026-07-13 선행 작업).
- 과거 `docs/tasks/**` 스냅샷.

## 7. 자체 검토 (2축)

> 검증 하네스 blocker① 소급 보강 — 본 작업이 신설하려는 3축 하네스는 아직 미발효이므로 현행 2축으로 자기 적용.

- **지침 준수**: 4단계 산출물 frontmatter+TL;DR 갖춤. 요구사항은 은수님 10개 지시를 재진술(원문 표+배경)했고 추측 없이 지시 그대로 구조화. 4단계 프로세스 대상(지침 변경)이며 은수님이 "미리 커밋 후 자율 진행" 지시로 승인 게이트 면제.
- **논리 정합성**: R1~R10이 서로 충돌 없이 배타적. 완료 기준이 각 R에 대응. 범위 외(정책 재작성·wiki·과거 tasks)를 명시해 스코프 크리프 차단.
