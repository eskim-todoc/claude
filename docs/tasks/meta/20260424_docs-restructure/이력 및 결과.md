## 무엇을 했는가

루트 `docs/`의 flat 구조 + 파일명 프리픽스 컨벤션(`[지침] ...`)을 폐지하고 **유형별 폴더 + tasks 레지스트리** 모델로 전환했다. 결과물:

- 영속 문서: `지침/{일반,Git,코딩}/`, `사용방법/` 폴더로 분류 (프리픽스 제거)
- 작업 문서: `tasks/<모듈>/<작업>/` 2레벨 고정, 고정 파일명(`요구사항.md`/`분석.md`/`구현계획.md`/`진행상황.md`)
- `tasks/list.md` 작업 레지스트리 신규 (활성·완료 분리, peer 링크 + feature 태그로 cross-module 연계)
- 루트 9개 파일 `git mv`, 내부 링크 9건 + CLAUDE.md 11건 갱신, 본 작업 폴더에 기획 4종 작성

## 핵심 결정

- **2레벨 고정 (모듈/작업)** — 3레벨은 한 작업이 복수 서브토픽에 걸칠 때 분류 경직화 위험. 서브토픽은 list의 태그로 표현
- **scope별 독립 list** — 루트와 프로젝트는 각자 list 유지. cross-scope는 절대 경로 peer 링크 (feature 전용 폴더는 YAGNI로 미도입)
- **체크리스트는 지침의 하위 유형** — `기준/` 같은 별도 폴더 두지 않고 `지침/`에 직접 배치
- **`참고/`는 모듈 서브폴더 권장** — `tasks/<모듈>/`과 축 정렬해 도메인 일관성

## 후속 영향

- Sound1 repo에 동일 모델 migration (별도 작업, 동일 일자 완료) — Sound1 `docs/`의 22개 파일 재편
- 본 컨벤션이 운용되며 발견된 정책 공백 → [`policy-refinement`](../policy-refinement/) 작업으로 보완 (lifecycle, 프로젝트 우선순위, 회고 즉시효력)
- `이력 및 결과.md` 형식 자체도 그 후속 작업에서 정의됨 — 본 문서는 새 형식의 첫 백필 사례
