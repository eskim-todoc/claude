# 요구사항: docs 폴더 구조 세분화

**TL;DR**: 작업당 4개 문서 누적·병렬 작업·프로젝트 확산으로 flat 구조가 한계. 영속(지침/사용방법) vs 작업(`tasks/<모듈>/<작업>/`)을 분리하고, `작업 목록.md`로 활성·완료를 중앙 관리, peer 링크+feature 태그로 cross-module 연계를 표현하면서 기존 링크는 무손실 유지한다.

## 1. 사용자 요청

사용자는 누적되는 문서 폭증과 활성/완료 구분 불가 문제를 해결하기 위해 `docs/` 폴더 구조를 세분화해 달라고 요청. flat+프리픽스 컨벤션은 다음 변화로 한계에 봉착:

- `feedback_code_docs_first.md` 규칙: 코딩 작업마다 `[요구사항]` / `[분석]` / `[구현계획]` 3개 문서 누적
- `feedback_parallel_orchestration.md` 규칙: 병렬 작업 증가로 동일 시점에 여러 작업 문서 공존
- 세션 간 핸드오프용 `[진행상황]` 문서 추가 → 작업당 4개로 증가
- 프로젝트(Sound1 등)에도 동일 규칙 적용 필요 (Sound1 `docs/`는 이미 22개 파일 누적)

flat 유지 시 **파일 수 폭발, 관련 작업 묶기 어려움, 활성/완료 구분 불가**.

현재 구조 (개선 전):

```
docs/
├── [지침] 작업 규칙.md
├── [지침] [Git] 브랜치, 병합 규칙.md
├── [사용방법] Slack 작업 완료 알림.md
└── ... (총 9개)
```

## 2. 목표

- 목표_1: 작업별 문서들을 **한 폴더에 묶어** 핸드오프·탐색·정리 용이
- 목표_2: 영속 문서(지침·사용방법 등)와 작업 문서 **명확히 분리**
- 목표_3: **활성 vs 완료** 작업 구분을 `작업 목록.md`로 중앙 관리
- 목표_4: **cross-module 연계 작업** 표현 (peer 링크 + feature 태그)
- 목표_5: 전역(`E:\Claude\docs\`)과 각 프로젝트(`projects/<이름>/docs/`)에 **동일 규칙 적용**
- 목표_6: 기존 문서 **링크·참조 무손실 유지** (CLAUDE.md 포함)

### 새 구조

```
docs/
├── 지침/
│   ├── 작업 규칙.md                       (마스터 체크리스트)
│   ├── 일반/
│   │   ├── 커뮤니케이션 규칙.md
│   │   └── 문서 작성 규칙.md
│   ├── Git/
│   │   ├── 브랜치, 병합 규칙.md
│   │   └── 워크플로우.md
│   └── 코딩/
│       ├── 작업 규칙.md
│       ├── 네이밍 컨벤션.md
│       └── 분석·디버깅 규칙.md
├── 사용방법/
│   └── Slack 작업 완료 알림.md
└── tasks/
    ├── 작업 목록.md                            (작업 레지스트리)
    └── <모듈>/
        └── <작업슬러그>/
            ├── 요구사항.md
            ├── 분석.md
            ├── 구현계획.md
            └── 진행상황.md
```

### 핵심 규칙 요지

- **영속 문서**: 유형별 폴더가 분류 역할 겸함, 프리픽스 제거. 2레벨까지 허용
- **작업 문서**: `tasks/<모듈>/<작업슬러그>/` 2레벨 고정. 서브토픽은 폴더가 아닌 list의 태그로 표현 (이유: 3레벨은 한 작업이 복수 서브토픽에 걸칠 때 분류 경직화 위험)
- **작업 슬러그**: kebab-case 영문 권장
- **모듈 이름**: 도메인 용어 (루트=`meta`/`git`/`docs`/`tools`, Sound1=`LED`/`touch`/`power`)
- **`작업 목록.md`**: 활성·완료 섹션 분리, 마크다운 테이블 (작업명·모듈·태그·폴더·상태·시작일·연계·요약)
- **cross-module 연계**: peer-to-peer 링크 + 3개 이상 작업 그룹은 공통 태그 `feature:<이름>`
- **갱신 이벤트**: 작업 시작/진행상황 갱신/완료 시그널마다 list 동기화
- **새 작업 라우팅**: list 조회 → 기존 폴더 이어가기 vs 신규 분리 사용자 확인
- **스코프 독립성**: 루트와 각 프로젝트는 독립 list 유지. cross-scope는 절대 경로 peer 링크 (feature 전용 폴더는 YAGNI)
