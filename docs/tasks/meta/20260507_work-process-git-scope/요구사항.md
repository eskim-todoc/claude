# 요구사항: 작업 진행 4단계 프로세스 일반화 + Git 범주 처리

**TL;DR**: 모든 작업(코딩/문서/메타 등)에 4단계 진행(요구사항 분석→현상태 분석→구현·처리 계획→구현·처리)을 강제하고, 각 단계 산출물(.md)·자체 검토·완료 시 이력 정리를 의무화한다. Git은 작업이 속한 스코프(루트 또는 프로젝트)의 repo에 커밋한다.

## 1. 사용자 지시 원문

> 1. 프로그래밍 뿐만 아니라, 내가 지시하는 모든 작업 지시 사항은 '요구사항 분석'→'현상태 분석'→'구현/처리 계획'→'구현/처리'의 과정으로 진행해야 해. 또한 진행상황 문서를 통해 현재 진행 중인 상태를 계속 업데이트 하면 돼. 그리고 각 단계에서는 해당하는 산출물이 md 파일로 출력되어야 해. 그리고 각 단계에서 출력되는 결과를 검토해야해. 각 단계에서 출력되는 결과를 검토하는 방법은 내가 정해준 지침에 맞는지, 그리고 네가 생산한 결과가 말이 되는 것인지 자체 검증을 하는거야. 모든 과정이 끝나면 이력 문서로 전체 정리하는거고.
>
> 2. Git은 해당하는 범주 내에서 처리해. 예를 들어, 루트폴더에서 세션을 열고 프로젝트 폴더 내부의 세부 프로젝트를 작업했다 하더라도, 프로젝트에 속한 작업은 해당 프로젝트의 깃에 업데이트 해야하는거야.

## 2. 요구사항

### 요구사항_1 — 4단계 작업 진행 프로세스 일반화

| 항목 | 내용 |
|---|---|
| 적용 범위 | **모든 작업 지시**(코딩, 문서 작성, 지침 변경, 설정 변경, 분석·조사 등) |
| 단계 | (1) 요구사항 분석 → (2) 현상태 분석 → (3) 구현·처리 계획 → (4) 구현·처리 |
| 단계별 산출물 | 각 단계마다 `.md` 파일 생성 (`요구사항.md`, `분석.md`, `계획.md`, 구현 결과물) |
| 진행상황 문서 | `진행상황.md`로 현재 단계·이슈·다음 동작을 지속 업데이트 |
| 단계별 검토 | 각 단계 산출 직후 **자체 검증 2축**: ① 사용자 지정 지침 준수 여부, ② 산출물 자체의 논리적 정합성 |
| 완료 처리 | 모든 과정 종료 시 `이력 및 결과.md`로 전체 요약·결정·후속 영향 정리 |

> [!IMPORTANT]
> **현재 코딩 한정 규칙 → 일반 규칙으로 격상.** 기존 `docs/지침/코딩/작업 규칙.md`(요구사항.md→분석.md→구현계획.md 3단계)는 모든 작업에 적용되는 4단계 프로세스의 코딩 특화 사례로 재정의된다.

### 요구사항_2 — Git 작업 범주별 스코프 분리

| 항목 | 내용 |
|---|---|
| 핵심 규칙 | 작업이 **속한 스코프의 repo**에 커밋한다 (작업이 일어난 디렉토리 기준이 아님) |
| 시나리오 | 루트(`E:\Claude`)에서 세션을 열어도, `projects/<이름>/` 내부 작업은 **해당 프로젝트 repo**에 커밋 |
| 판단 기준 | 변경되는 파일이 어느 repo의 git에 추적되는지 — 루트 repo or 프로젝트 repo |
| 혼합 변경 | 루트와 프로젝트 양쪽에 걸친 변경은 **각 스코프 별도 커밋·브랜치 분리** |
| 브랜치 모델 | 각 repo는 `claude_*` 브랜치 모델을 독립적으로 적용 |

### 요구사항_3 — 서브에이전트 활용 (병렬·효율)

> 사용자 추가 지시(2026-05-07): "모든 작업에 대해서 병렬 처리 및 효율적인 처리를 위해 서브에이전트를 활용할 수 있다면, 적극 활용하기 바람"

| 항목 | 내용 |
|---|---|
| 적용 범위 | **모든 작업** |
| 목적 | 병렬 처리 + 처리 효율 |
| 활용 강도 | 가능하면 **적극 활용** (단순 위임 아닌 first-class 도구로) |
| 활용 패턴 | 광범위 탐색·다중 가설 분석·독립 작업 동시 실행·대용량 로그 분석·다중 파일 일괄 처리 등 |
| 서브에이전트 종류 | `Explore`(읽기 전용 검색), `general-purpose`(다단계 조사·실행), `Plan`(설계 계획) 등 |
| 병렬 호출 방법 | 한 응답에 multiple Agent 호출(독립 작업 시) |
| 안티패턴 | 단일 lookup·이미 결과 있는데 중복 호출·서브에이전트 결과를 본인이 다시 같은 검색으로 검증 |
| 컨텍스트 절약과의 관계 | 컨텍스트 격리 효과는 부수 효과. 본 규칙은 **속도·효율** 관점에서 강조 (서로 보완 cross-ref) |

## 3. 비요구사항 (Out of Scope)

| 항목 | 비고 |
|---|---|
| 단순 수정 예외 유지 | 오타·설정값 변경 등 **명백한 단순 작업**은 4단계 면제 (현행 코딩 규칙 §예외와 동일) |
| 회고/메모리 정책 | 본 작업 대상 아님 — 별도 |
| 프로젝트 측 `docs/지침/` 동기화 | 루트 지침이 자동 적용되므로 별도 수정 불필요. Sound1 측 특화 지침이 본 변경과 충돌하면 후속 작업으로 검토 |
