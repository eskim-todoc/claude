# 요구사항: 개인 Wiki 프로젝트 초기 구축

**TL;DR**: 사용자가 옵시디언으로 .md를 보고 있는 현재 상태를 확장해, 문서간 위키링크·이미지 임베드가 자유로운 **나무위키 형식**의 개인 Wiki를 `projects/wiki/`에 독립 repo로 구축. 콘텐츠는 프로젝트 횡단 지식(메인)·학습·일상·참고로 분류. 로컬 시작 → 추후 허가 사용자 한정 웹 공개(GitHub 기반 가능). **신규 프로젝트 초기 세팅 트리거 + Wiki 특화 구조** 결합 — 표준 `src/`·`tests/` 폴더는 제외하고 Vault 친화 레이아웃 적용.

## 1. 사용자 지시 원문

> "나만의 Wiki를 만들거야."
>
> 합의 답변:
> - **Wiki 형태**: "일단 잘 모르는 상태인데, 내가 옵시디언을 설치해서 md 문서를 보는 정도로 사용하고 있어. 이걸 활용해서 문서간 링크도 되고, 안에 사진도 넣고 해서 나무위키 같은 느낌으로 만들고 싶어. 그래서 시작은 로컬에서 보는데, 나중에는 웹으로 올려서 보고 싶은 마음이 있어."
> - **저장 위치**: `projects/wiki/` (독립 repo)
> - **콘텐츠**: "각 프로젝트에서 구현된 개발이나 기술 정보 등을 요약하고, 나중에 관련 지식이 필요할 때 찾아 볼 수 있는 느낌." + 개인 학습·기술 메모 + 프로젝트 횡단 지식 + 일상·아이디어·일기 + 참고 자료 아카이브
> - **공개 범위**: "로컬이 기본이고, 나중에 웹으로 올려서 허가된 사용자만 보게 하고 싶어. 그 방식이 깃허브가 편하면 그렇게 해도 돼."

## 2. 요구사항

### 요구사항_1 — Obsidian Vault 기반 로컬 운영

| 항목 | 내용 |
|---|---|
| 기반 도구 | Obsidian (사용자 기존 설치·사용 중) |
| 핵심 기능 | 위키링크 `[[페이지명]]`, 이미지 임베드 `![[그림.png]]`, Graph View 자동 활용 |
| Vault 위치 | `projects/wiki/` 폴더 자체를 Obsidian Vault로 지정 |
| Vault 설정 | `.obsidian/` 폴더(앱이 자동 생성) — 추적/제외 정책 명시 (요구사항_6 참조) |

### 요구사항_2 — 콘텐츠 분류 체계 (4축 + 첨부)

사용자 답변에서 명시된 4가지 콘텐츠 카테고리를 폴더 단위 분류로 매핑:

| 카테고리 | 폴더(안) | 메인 용도 |
|---|---|---|
| 프로젝트 횡단 지식 (**메인 용도**) | `프로젝트/` | Sound1·auto-rtt-viewer 등 각 프로젝트의 개발·기술 정보 요약. 후일 검색 자료 |
| 개인 학습·기술 메모 | `학습/` | 임베디드·툴·언어·개념 등 학습한 내용 |
| 일상·아이디어·일기 | `일상/` | 기술 외 메모, 아이디어 노트, 데일리 로그 |
| 참고 자료 아카이브 | `참고/` | 외부 자료 정리, 북마크, 인용 |
| 첨부(이미지·파일) | `_attachments/` | Obsidian 기본 첨부 폴더로 지정 |

> [!NOTE]
> 폴더명·축 구성은 분석·계획 단계에서 사용자 협의 가능. 카테고리 매핑 자체는 사용자 답변 직접 반영이라 필수 유지.

### 요구사항_3 — "나무위키 느낌" 구현 패턴

| 항목 | 구현 |
|---|---|
| 문서간 링크 | Obsidian 위키링크 `[[페이지]]` 일관 사용 (마크다운 링크 대신) |
| 이미지/사진 | 페이지 내 `![[그림.png]]` 임베드, 파일은 `_attachments/`에 보관 |
| 카테고리 진입 | 각 분류 폴더 루트에 **MOC**(Map of Content) 페이지 1개 — 카테고리 인덱스 역할 (나무위키 분류 페이지 대응) |
| 그래프 시각화 | Obsidian Graph View 기본 활용 — 별도 도구 도입 없음 |
| 검색 | Obsidian 내장 검색 + 태그(`#`) 자유 사용 |

### 요구사항_4 — 콘텐츠 시드 (최소 골격)

초기 구축 시 **빈 폴더만 두지 않고** 다음 시드 페이지를 작성:

| 페이지 | 위치 | 역할 |
|---|---|---|
| `홈.md` | Vault 루트 | Wiki 진입점. 4개 카테고리 MOC·최근 페이지·전역 안내 |
| `프로젝트/MOC.md` | 프로젝트/ | 프로젝트 카테고리 인덱스. 각 프로젝트(Sound1 등) 페이지 링크 자리 |
| `학습/MOC.md` | 학습/ | 학습 카테고리 인덱스 |
| `일상/MOC.md` | 일상/ | 일상 카테고리 인덱스 |
| `참고/MOC.md` | 참고/ | 참고 카테고리 인덱스 |

### 요구사항_5 — 공개 범위 정책 (로컬 우선, 추후 웹)

| 단계 | 정책 |
|---|---|
| 단계 1 (현재) | 로컬 전용. Git은 사용하되 push는 사용자 결정 후 |
| 단계 2 (추후) | **Private GitHub repo**로 push. 사용자가 repo 생성·연결 |
| 단계 3 (미래, 옵션) | 정적 사이트 생성기(예: **Quartz 4**)로 빌드 → 외부 공개. 본 요구사항에는 포함되지 않으며 별도 작업 |

> [!IMPORTANT]
> **본 작업의 산출물은 단계 1~2 한정.** 단계 3(웹 공개 SSG 도입)은 미래 별도 작업으로 분리. 단, 현 단계 구조 설계 시 **단계 3 호환성을 깨지 않도록** 분석 단계에서 확인.

### 요구사항_7 — CLAUDE.md (프로젝트 진입점)

루트 [`프로젝트 초기 세팅.md`](../../../지침/일반/프로젝트%20초기%20세팅.md) §3 슬림 패턴을 기반으로 Wiki 특화 변형:

| 항목 | 내용 |
|---|---|
| frontmatter | name·purpose·type=메타·applies_to=[wiki]·tags=[project, wiki, obsidian, knowledge-base] |
| TL;DR | Wiki 목적·옵시디언 기반·분류 체계 1줄 요약 |

| §작업 라우팅 | `docs/tasks/작업 목록.md` (선택. Wiki에선 활용도 낮을 수 있어 분석 단계에서 결정) |
| §운영 컨벤션 | Wiki 특화 — 페이지명 규칙·위키링크 사용·MOC 패턴·첨부 위치 |

### 요구사항_8 — 표준 폴더 풀 세트 변형

루트 [`프로젝트 초기 세팅.md`](../../../지침/일반/프로젝트%20초기%20세팅.md) §2.3 표준 폴더는 코드 프로젝트 가정. Wiki에는 다음과 같이 변형:

| 항목 | 변형 |
|---|---|
| `src/` | **제외** — Wiki는 코드 프로젝트 아님 |
| `tests/` | **제외** — 동일 |
| `docs/` | **최소화** — Wiki 자체 메타 운영용. `docs/tasks/작업 목록.md`만 유지 또는 전체 생략 결정(분석 단계) |
| 콘텐츠 폴더 | 추가 — `프로젝트/`·`학습/`·`일상/`·`참고/`·`_attachments/` |
| `.obsidian/` | 추가 — Obsidian 앱이 자동 생성. 일부 파일 추적 (요구사항_6) |

> [!NOTE]
> 표준 절차의 5단계 흐름(진단→CLAUDE.md→폴더→루트 인덱스→Git)은 유지. 폴더 세부 구성만 Wiki 특화.

### 요구사항_9 — 루트 CLAUDE.md Projects 표 갱신

루트 `CLAUDE.md` Projects 표에 한 줄 추가:

```
| [wiki](projects/wiki/CLAUDE.md) | 개인 Wiki (옵시디언 Vault, 프로젝트 횡단 지식 + 학습·일상·참고) | 로컬 우선, 추후 private GitHub + (선택) 웹 공개 |
```
