# 분석: 개인 Wiki 프로젝트 초기 구축

**TL;DR**: 옵시디언 Vault 기반으로 `projects/wiki/`에 신규 프로젝트 골격을 만든다. [`프로젝트 초기 세팅.md`](../../../지침/일반/프로젝트%20초기%20세팅.md) 5단계 흐름 유지 + 폴더만 Wiki 특화 변형(`src/`·`tests/`·`docs/` 생략, 콘텐츠 4 카테고리 + `_attachments/` 추가). `.obsidian/`은 통무시 + 코어 설정 5종 화이트리스트. 미래 Quartz 4 SSG 호환은 위키링크·이미지 / 한국어 헤딩 앵커는 회피. GitHub Pages private은 Pro 계정 필요(정보 안내만).

## 1. 현 상태 (Current State)

`projects/wiki/` 경로는 비어있고 루트 `CLAUDE.md` Projects 표에 wiki 행이 아직 없음. 사용자는 옵시디언으로 .md를 보고 있으며 Vault로 활용할 수 있는 상태. Quartz 4 SSG는 외부 조사 결과(Explore agent) 위키링크 지원 + 한국어 폴더·파일명 가능, 한국어 헤딩 앵커는 미지원([issue #1155](https://github.com/jackyzha0/quartz/issues/1155)). GitHub Pages private은 GitHub Pro($4/월) 이상 필요.

## 3. 가설·선택지

### 3.1 가설 (root cause·디버깅)

해당 없음 — 본 작업은 신규 구축이며 디버깅이 아님.

### 3.2 선택지 (설계 결정)

#### 표준 절차 변형 (Wiki 특화)

[`프로젝트 초기 세팅.md`](../../../지침/일반/프로젝트%20초기%20세팅.md) §2.3 표준 폴더 풀 세트는 코드 프로젝트 가정. Wiki는 다음과 같이 변형:

| 항목 | 표준 | Wiki 변형 | 사유 |
|---|---|---|---|
| `src/` | 빈 폴더 + `.gitkeep` | **생략** | Wiki는 코드 프로젝트가 아님 — 콘텐츠가 본체 |
| `tests/` | 빈 폴더 + `.gitkeep` | **생략** | 동일 |
| `docs/` | `지침/`·`사용방법/`·`참고/` + `tasks/작업 목록.md` | **생략** | Wiki 본체가 곧 docs. 운영 메타 작업은 본 루트 `docs/tasks/meta/`에서 처리 |
| 콘텐츠 폴더 | (해당 없음) | **추가** — `프로젝트/`·`학습/`·`일상/`·`참고/` | 사용자 답변 4축 카테고리 1:1 매핑 |
| 첨부 폴더 | (해당 없음) | **추가** — `_attachments/` | Obsidian 기본 첨부 폴더 컨벤션 |
| `.obsidian/` | (해당 없음) | **사용자 측 자동 생성**, `.gitignore`만 선반영 | Obsidian 앱이 Vault 첫 진입 시 생성 |
| 5단계 흐름 (진단→CLAUDE.md→폴더→루트 인덱스→Git) | 유지 | **유지** | 변형 사유 없음 |

> [!IMPORTANT]
> 본 변형은 본 프로젝트 한정. 표준 [`프로젝트 초기 세팅.md`](../../../지침/일반/프로젝트%20초기%20세팅.md) 자체에 "Wiki 케이스" 분기를 넣는 변경은 **본 작업에서 하지 않는다** — 향후 Wiki 같은 비코드 프로젝트가 누적되면 별도 작업으로 절차 자체 일반화 검토.

#### Obsidian Vault 운영 결정

##### 분석_4 — `.obsidian/` 추적 정책

외부 자료 컨센서스(Explore agent 조사): `.obsidian/*` 통무시 후 **코어 설정만 화이트리스트** 패턴.

| 파일 | 추적 | 사유 |
|---|---|---|
| `app.json` | 추적 | 에디터·뷰·디스플레이 설정 — 환경 일관화 |
| `appearance.json` | 추적 | 테마·폰트 — 환경 일관화 |
| `core-plugins.json` | 추적 | 코어 플러그인 on/off — 환경 일관화 |
| `community-plugins.json` | 추적 | 설치한 커뮤니티 플러그인 목록 |
| `hotkeys.json` | 추적 | 단축키 — 사용자별 환경 일관화 |
| `workspace.json`·`workspace-mobile.json` | 제외 | 열려있는 패널·탭 등 UI 상태 — 기기별 |
| `cache/`·`plugins/<name>/data.json` (대부분) | 제외 | 사용자 데이터·캐시 |
| `.trash/` (Obsidian 내부 휴지통) | 제외 | 임시 |

> [!NOTE]
> `.obsidian/` 폴더는 본 작업에서 미리 만들지 않음. 사용자가 옵시디언으로 Vault를 처음 여는 순간 앱이 자동 생성. `.gitignore`는 선반영해 두므로 자동 생성된 폴더가 git에 들어와도 노이즈 없음. 화이트리스트 5개는 사용자가 옵시디언 첫 설정을 마친 뒤 직접 `git add` 해 추적 시작.

##### 분석_5 — 첨부 폴더명 (`_attachments/` vs `assets/`)

| 옵션 | 장점 | 단점 |
|---|---|---|
| **`_attachments/`** 채택 | Obsidian 기본값, `_` 접두로 카테고리 폴더와 시각 분리, 검색·정렬 시 상단 묶임 | `_` 시작 폴더를 무시하는 일부 도구 존재 (예: Jekyll) |
| `assets/` | 일반 웹 컨벤션 | Obsidian 기본 첨부 설정과 불일치 — 매번 설정 변경 필요 |

채택 이유: 사용자가 Obsidian 기본 동작에 익숙해지는 것이 우선, 추후 SSG는 폴더명을 빌드 설정으로 매핑 가능 (Quartz는 `_` 접두 폴더를 자동 무시 안 함).

##### 분석_6 — MOC 페이지명 (`MOC.md` vs `프로젝트.md`)

| 옵션 | 위키링크 표현 | 비고 |
|---|---|---|
| **`MOC.md`** 채택 | `[[프로젝트/MOC]]`, `[[프로젝트/MOC\|프로젝트 횡단 지식]]` | 검색 시 모든 MOC을 한 번에 찾기 용이 |
| `프로젝트.md` (카테고리명) | `[[프로젝트]]` | 폴더명과 충돌 가능성(Obsidian이 폴더로 갈지 페이지로 갈지 모호) |

채택 이유: 폴더명-페이지명 충돌 회피 + MOC 전체 일괄 검색.

### 3.3 미래 SSG 호환성 (Quartz 4 가정)

본 작업에서 SSG 도입은 안 하나, 구조 결정 시 호환성을 깨지 않게 점검:

| 항목 | Quartz 4 호환 | 본 구조 대응 |
|---|---|---|
| 위키링크 `[[페이지]]` | 지원 | 본 구조에서 우선 사용 권장 |
| 이미지 임베드 `![[그림.png]]` | 지원 | `_attachments/` 보관 + 임베드 |
| 한국어 폴더·파일명 | 지원 (URL 인코딩 후 라우팅) | 그대로 사용 OK |
| 한국어 헤딩 앵커 `#섹션` | 비ASCII 미지원 ([issue #1155](https://github.com/jackyzha0/quartz/issues/1155)) | CLAUDE.md §운영 컨벤션에 "앵커는 영문/숫자 슬러그 권장" 노트 |
| `_` 접두 폴더 | 자동 무시 안 함 (그대로 빌드) | 추후 SSG 도입 시 `_attachments/`를 정적 자산으로 명시 매핑 |
| frontmatter `draft: true` | 지원 | 비공개 페이지 처리 가능 |

> [!NOTE]
> 본 호환성 정보는 결정의 *제약*이 아니라 *알림*. 본 작업 산출물은 SSG 미도입 상태에서 완결.

### 3.4 GitHub repo·Pages 정책

| 항목 | 결론 |
|---|---|
| 본 작업 범위 | `git init` + 첫 커밋 + `claude_develop` 신설까지 (**push 안 함**) |
| Wiki repo `origin` 연결 | 사용자가 GitHub에서 **private repo 생성** 후 `git remote add origin <URL>` + `push -u`. 본 작업 외 |
| GitHub Pages private | **GitHub Pro($4/월)** 이상에서만 private repo + private Pages. 무료 계정은 public 필수 또는 Cloudflare Access 등 3rd-party 인증 추가 |
| 사용자 안내 위치 | 최종 보고에서 `_(TBD)_` placeholder 안내와 함께 명시 |

### 3.5 Windows + 한국어 인코딩 점검

`git log --name-status`로 한국어 폴더·파일명이 mojibake 없이 출력되는지 첫 커밋 직후 확인. 문제 시 `git config core.precomposeunicode true` 설정.

### 8.3 미해결 이슈

| 이슈 | 처리 |
|---|---|
| `_attachments/`에 `.gitkeep` 두는 게 SSG에 들어가도 무해한가 | Quartz는 frontmatter 없는 `.gitkeep`은 일반 파일로 인식, 빌드에 그대로 들어가나 정적 자산 폴더로 명시 매핑 시 비노출. 본 작업 범위 외 |
| 사용자가 다른 기기와 Vault 동기화 시작 시 추적 화이트리스트 외 파일이 ignore돼 누락 우려 | 사용자 후속 안내에 명시 — 필요 시 화이트리스트 확장 |
