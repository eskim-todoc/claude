# 요구사항: 오케스트레이터 전면 위임 정책 강화

**TL;DR**: 메인 세션(오케스트레이터)을 "분석·프롬프트 설계·위임"에 전담시키고, 사용자에게 전달되는 실제 작업 산출물은 규모·난이도 불문 전량 `Workflow` 경로의 Sonnet 서브에이전트가 생성하도록 핵심 지침을 개정한다. 현행 "단순 단일 lookup 예외"를 폐지하고, 서브에이전트 effort 기본값을 `high`(난이도별 차등)에서 **항상 `max`** 로 상향한다.

## 1. 사용자 요청

> "내가 주 세션의 모델과 effort를 가장 좋은 상태로 설정하고, 너에게 입력하는 프롬프트를 네가 분석해서 네가 직접하는게 아니고, 네가 Sonnet 최고 effort로 작업을 시킬 수 있게 입력 프롬프트를 네가 다시 만들고 작업을 시키는거야. [...] 너는 직접 일하는게 아니고, 일을 어떻게 하면 가장 효율적으로 최선의 방향으로 할 수 있는지 그 작업 내용을 만드는데 중점을 두고, 진짜 작업은 밑의 Sonnet 서브 에이전트들을 활용하는거지."

기술적 가능성을 확인한 뒤, `AskUserQuestion`으로 두 가지 모호점을 해소했다:

- **적용 범위**: "이번 세션 한정" vs "지침 영구 반영" → 은수님 선택: **지침 영구 반영**
- **위임 강도**: "지침 기본값 유지(단순 lookup 예외 + effort 기본 high)" vs "전면 위임 + 항상 max" → 은수님 선택: **전면 위임 + 항상 max**

## 2. 목표

- 목표_1: 오케스트레이터가 사용자에게 전달되는 실제 작업 산출물을 직접 만들지 않고, 전량 `Workflow` 경로 Sonnet 서브에이전트에 위임하도록 핵심 지침(`서브에이전트 활용.md`·`워크플로우 오케스트레이션.md`·`CLAUDE.md` §5) 개정
- 목표_2: 위임된 서브에이전트 effort 기본값을 `high`(난이도별 차등: 단순 `low`·최고난도 `xhigh`)에서 **항상 `max`** 로 상향
- 목표_3: "전면 위임"이 "오케스트레이터가 어떤 도구도 직접 못 쓴다"를 의미하지 않도록 경계를 명확히 문서화 — **위임 설계에 필요한 오케스트레이터 자기 컨텍스트 확보(대화 파악·어떤 파일을 훑어야 위임 프롬프트를 잘 짤지 조사)는 예외로 남고, 사용자에게 전달되는 산출물/실행 결과만 100% 위임 대상**임을 명시
