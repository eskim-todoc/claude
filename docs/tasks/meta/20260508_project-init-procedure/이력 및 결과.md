## 무엇을 했는가

루트 지침에 [`docs/지침/일반/프로젝트 초기 세팅.md`](../../../지침/일반/프로젝트%20초기%20세팅.md)를 신설했다. 사용자가 `projects/` 아래 git clone한 신규 프로젝트에 대해 자유 표현 트리거("기본 세팅 해줘"·"초기화" 등)를 쓰면 Claude가 ① 진단 → ② CLAUDE.md(Sound1·auto-rtt-viewer 슬림 패턴) → ③ 표준 폴더 풀 세트(`src/`·`tests/`·`docs/{지침,사용방법,참고}/`·`docs/tasks/list.md`) → ④ 루트 CLAUDE.md Projects 표 갱신 → ⑤ Git 처리(feature → develop 머지 → push, default branch 보호 시 옵션 제시)의 5단계로 자동 처리한다. CLAUDE.md 본문 템플릿과 list.md 템플릿을 본 지침에 인라인하고, TL;DR·담당 범위·한 단락 소개는 `_(TBD)_` placeholder로 두어 사용자가 나중에 채우는 정책(Q2=B). 마스터 체크리스트(`작업 규칙.md` §3)·지침 README·루트 CLAUDE.md 인덱스에 신규 지침을 등재했다.

## 핵심 결정

- **자유 트리거(Q1=A)** — 슬래시 명령이 아닌 키워드 매칭. "새 프로젝트 생성", "기본 세팅", "초기화" 등 자연어 표현 인식
- **placeholder 정책(Q2=B)** — TL;DR·담당 범위·한 단락 소개는 즉시 묻지 않고 `_(TBD)_`. 자동 추출 가능 항목(origin URL·main branch·프로젝트명)만 채움. 사용자가 후속 1턴에 placeholder 보고 받고 채움
- **표준 폴더 풀 세트(Q3=A)** — 프로젝트 성격 묻지 않고 항상 동일 풀 세트 생성. 빈 폴더는 `.gitkeep`로 추적
- **자동 push(Q4=A)** — feature → develop 머지 → push까지 일괄. default branch 보호 차단 시 sullivan 사례처럼 옵션 제시(PR·develop 신설·권한 추가)
- **4단계 면제(Q5=A)** — 본 절차 *적용*은 정형 반복이라 면제. 단순 수정 예외(§7)와 동급. 단, 본 절차 *변경* 시는 4단계 적용
- **템플릿 인라인(결정_1)** — 별도 templates 폴더 신설 부담 회피, lazy loading·진화 추적 용이
- **기존 충돌 처리(결정_2)** — CLAUDE.md 있으면 사용자 yes/no 확인, 폴더는 비파괴 추가
