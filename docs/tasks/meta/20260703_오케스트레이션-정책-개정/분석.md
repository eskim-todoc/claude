# 분석: 오케스트레이션 정책 개정

**TL;DR**: 전면 위임·effort max 프레이밍은 서브에이전트 활용.md(TL;DR·§1·§1.1·§2.1·§3.1·§5·§6)·워크플로우 오케스트레이션.md §1·CLAUDE.md §5·작업 규칙.md §3에 분포. adaptive는 설정 레벨이 아니라 Sonnet 5 모델 특성(effort=상한, 그 안에서 자동 조절) → max 고정 해제로 실현. 폭주 가드(§4.4·§7)는 유지.

## 1. adaptive effort 사실 (claude-code-guide 검증)

- "adaptive"라는 effort 레벨은 **없음**(`/effort`: low·medium·high·xhigh·max·ultracode).
- Sonnet 5/Opus 4.7+는 **adaptive reasoning 항상 켜짐** — 단계별 사고량 자동 배분(설정 불가·모델 특성).
- effort 값 = **상한(천장)**. 모델은 천장 안에서 작업량에 맞춰 자동 조절.
- ∴ 은수님 의도("작업량 따라 스스로 조절") = **effort 미지정(세션 상속)** 으로 max 고정 해제. 폭주(2026-07-03)는 max 천장이 너무 높아 결정론적 작업에서 과잉 생성된 것 → 근본 해소.

## 3. 핵심 결정

- 결정_1: **트리거 기반** — 트리거어(오케스트레이션·여러 페르소나·서브에이전트들로·여러 에이전트·병렬로·fan-out·워크플로우로 등) → dynamic workflow. 그 외 판단(간단→직접, 광범위·독립 병렬 실익 시만 위임)
- 결정_2: **effort 미지정(세션 상속)** — model:sonnet 유지, effort 인자 생략, Sonnet adaptive reasoning 자동 조절. max 고정 폐지
- 결정_3: §1.1 재프레이밍 — "전면 위임의 유일한 예외"→"오케스트레이터가 직접 하는 일"(트리거 없는 간단 작업 포함)
- 결정_4: §5 안티패턴 재정의 — "직접 처리=안티패턴" 폐기. 새 안티패턴 = 과소 위임(트리거·실익 무시)·과잉 위임(트리거·실익 없이 전량)
- 결정_5: 폭주 가드(§4.4 프롬프트 위생·§7 서킷브레이커·결정론적 저술 직접) 유지 — 트리거 시 fan-out에도 여전히 필요
- 결정_6: 결정론적 지침 개정이라 오케스트레이터 직접(fan-out 없이) — 새 정책 자기 적용(트리거 없음·간단)
