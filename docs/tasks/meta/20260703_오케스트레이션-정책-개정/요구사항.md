# 요구사항: 오케스트레이션 정책 개정

**TL;DR**: 이번 세션에 세운 두 정책을 은수님 지시로 개정. (1) **전면 위임 → 트리거 기반**: 은수님이 "오케스트레이션/여러 페르소나/서브에이전트들로" 등 트리거어를 쓸 때만 dynamic workflow, 그 외엔 판단해 간단하면 직접. (2) **effort 기본 max → 미지정(세션 상속)**: Sonnet 5 내장 adaptive reasoning이 작업량에 맞춰 자동 조절하도록 max 고정 해제.

## 1. 사용자 요청

> "1. 오케스트레이션 작업 방식을, 내가 오케스트레이션, 여러 페르소나, 서브에이전트들로 등의 말을 하면 dynamic workflow 방식으로 진행해. 그 외에는 네가 판단하여 간단한 일이면 세션에서 직접 처리해. 2. 서브에이전트의 모델을 Sonnet, effort max로 했는데, Sonnet에 adaptive effort 방식으로 작업량에 따라 스스로 변경하게 해줘. 가능해?"

확인 사항:
- **#2 사실 검증**(claude-code-guide): "adaptive" effort 리터럴 설정은 없음. Sonnet 5는 adaptive reasoning이 항상 켜져 있어 effort **상한** 안에서 작업량에 맞춰 자동 조절. → 의도 실현 = `effort: max` 고정 해제.
- `AskUserQuestion`: #2 effort 방식 = **미지정(세션 상속)** 채택(은수님이 /effort로 상한 제어, Sonnet 자동 조절).

## 2. 목표

- 목표_1: dynamic workflow를 **트리거어 기반**으로 — 트리거 시 fan-out, 그 외 판단(간단→직접). 전면 위임 정책 대체
- 목표_2: 서브에이전트 effort를 **미지정(세션 상속)** 으로 — max 고정 해제, Sonnet adaptive reasoning 위임. effort 기본 max 정책 대체
- 목표_3: 두 변경을 4개 파일에 일관 반영(서브에이전트 활용.md·워크플로우 오케스트레이션.md·CLAUDE.md §5·작업 규칙.md §3)
- 목표_4: 폭주 가드(서킷브레이커·프롬프트 위생·결정론적 저술 직접)는 유지 — 여전히 유효
