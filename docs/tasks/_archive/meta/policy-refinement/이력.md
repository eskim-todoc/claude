# 이력: 작업 lifecycle · 회고 승격 · 프로젝트 우선 정책 정련

**TL;DR**: lifecycle·우선순위·회고 승격 세 정책 공백을 `_archive/<모듈>/<작업>/` 모델·프로젝트 우선·회고 즉시 효력으로 정돈. `문서 작성 규칙.md`·`회고/README.md` 갱신, `docs-restructure` 이력 백필+archive 첫 적용. `이력.md` 병합 hash 사후 확정 비대칭은 향후 회고 트리거 후보.

**기간:** 2026-04-27 ~ 2026-04-27
**모듈/태그:** meta / docs, convention, lifecycle
**병합:** `claude_develop` ← `claude_docs_policy-refinement` (병합 hash는 사후 git log로 확인)
**연계 작업:** ← [`_archive/meta/docs-restructure`](../docs-restructure/) (선행 — 본 작업이 그 정책 공백 보완)

## 무엇을 했는가

`docs/` 운용 중 식별된 세 가지 정책 공백(작업 lifecycle, 루트·프로젝트 docs 충돌, 회고 승격 시점)을 정돈하고 첫 사례를 적용했다. 결과물:

- **`tasks/_archive/<모듈>/<작업>/`** 도입. 완료 시그널 직후 `git mv`로 이동, 모듈 계층 유지
- **`이력.md`** (1페이지 요약) 형식 정의 및 완료 시 필수 파일로 등록
- [`문서 작성 규칙.md`](../../../../지침/일반/문서%20작성%20규칙.md) 갱신 — §2.1 (충돌 시 프로젝트 우선), §3.1 (`_archive/` 레이아웃), §3.4 (archive 절차·`이력.md` 형식·검색 시 유의), §4.4 (갱신 이벤트)
- [`회고/README.md`](../../../../회고/README.md) 갱신 — 회고와 지침 효력 동등 명시, "지침 승격" 섹션과 승격 이력 표 신규
- 첫 archive 적용: [`_archive/meta/docs-restructure/`](../docs-restructure/) — `이력.md` 백필 후 이동
- 본 작업도 동일 절차로 `_archive/`로 이동 (이 문서가 그 결과)

## 핵심 결정

- **회고와 지침의 효력은 동등** — 차이는 "성숙도/통합 정도"뿐. 검증 기간을 두면 회고 효력이 모호해져서 회고를 두는 의미가 약해짐. 즉시 효력 + 사후 통합 모델로 단순화
- **모듈 계층 유지 (`_archive/<모듈>/<작업>/`)** — 활성과 archive의 경로 구조가 같아서 `list.md` 링크 갱신이 단순(`prefix만 추가`). 평탄화는 모듈 단위 그루핑을 잃어서 기각
- **이력.md는 원본 4종과 함께 보존** — 정보 압축 시 다음 유사 작업의 레퍼런스 가치 손실 위험. archive 폴더는 1페이지 요약(이력.md) + 원본의 2단 구조
- **승격 이력은 회고 README에 통합** — 별도 파일은 git log로 추적 가능한 정보의 중복. README는 회고 폴더의 진입점이라 자연 노출

## 후속 영향

- **운용 이슈 발견** — `이력.md`의 "병합 hash" 필드는 작업 archive 시점에 미확정 (병합은 사후). 첫 적용 사례인 본 작업과 [`docs-restructure`](../docs-restructure/이력.md) (백필이라 hash 확보됨) 가 비대칭. 다수 사례 누적 후 회고 트리거 가능
- **Sound1 등 프로젝트 repo의 동일 정책 반영은 후속 작업** — 본 작업은 루트 한정
- **`tasks/[!_]*/` 패턴** — 활성 작업만 검색 시 권장 패턴으로 §3.4.3에 명시. Glob 패턴 충분히 활용 안 되면 추후 별칭/도구 검토 가능
