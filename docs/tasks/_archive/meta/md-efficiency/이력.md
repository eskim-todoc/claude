## 무엇을 했는가

LLM(Claude)이 매 세션마다 긴 md 파일을 모두 읽는 비용을 줄이기 위해 lazy loading 3패턴을 도입했다. md 형식 자체는 유지하되, 사용 패턴을 바꿔 "LLM이 읽어야 할 양 자체"를 줄였다.

- 컨벤션 명문화: [`문서 작성 규칙.md §9`](../../../../지침/일반/문서%20작성%20규칙.md) 신규 — frontmatter (YAML 메타) / TL;DR (1줄 요약) / 폴더 README 형식 정의
- 영속 문서 13개에 frontmatter+TL;DR 적용: 지침 8개, 회고 5개
- 폴더 인덱스 3개 신규: [`지침/README.md`](../../../../지침/README.md), [`사용방법/README.md`](../../../../사용방법/README.md), [`tasks/README.md`](../../../README.md) (`회고/README`는 기존 유지)
- 적용 효과: 일반 작업당 ~30~50% 토큰 절감 예상 (정성)

## 핵심 결정

- **md 유지, 패턴만 변경**: AsciiDoc/Org-mode/Typst 등 대안은 LLM 학습 데이터가 적어 오히려 손해. 같은 md 안에서 "LLM이 읽어야 할 양"을 줄이는 게 효과 큼.
- **Phase 3 (YAML 분리) 미진행**: `tasks/list.md`의 표 형식이 이미 사람·LLM 양쪽에 충분히 효율적. 활성 작업이 적어 절감 미미, 다수 참조처 갱신으로 회귀 위험 큼 → YAGNI.
- **CLAUDE.md vs 폴더 README 역할 분리**: CLAUDE.md=폴더 단위 인덱스, `<폴더>/README.md`=파일 단위 인덱스. §9.4에 명문화하여 중복·혼선 회피.

## 후속 영향

- **신규 영속 문서 작성 시 컨벤션 준수 필수**: 모든 영속 문서는 frontmatter+TL;DR, 모든 영속 폴더는 README 필수 (§9 적용 범위).
- **Sound1 등 프로젝트 docs 미적용**: 같은 컨벤션을 프로젝트 repo로 확산할지는 별도 작업으로 분리.
- **`사용방법/Slack 작업 완료 알림.md` (76줄)**: frontmatter+TL;DR 적용 후보. 다음 라운드 또는 즉시 가능 (이번 작업 범위 외).
