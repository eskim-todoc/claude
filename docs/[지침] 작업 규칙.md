# 작업 규칙 체크리스트

> **모든 작업을 시작하기 전에 아래 규칙을 확인할 것.**

---

## 1. 커뮤니케이션
- [ ] 사용자 대상 메시지는 **존댓말**로 작성 (반말 금지)

> 상세: [`[지침][일반] 커뮤니케이션 규칙.md`]([지침][일반]%20커뮤니케이션%20규칙.md)

---

## 2. 문서 작성
- [ ] 문서는 사용자가 다른 포멧을 명시하지 않는 한 **GFM Markdown(`.md`)**으로 작성
- [ ] 파일명은 `[카테고리] 문서명.md` prefix 컨벤션 준수
- [ ] '~하고 정리해' 요청 시, 작업 위치의 `docs/`에 `.md`로 정리

> 상세: [`[지침][일반] 문서 작성 규칙.md`]([지침][일반]%20문서%20작성%20규칙.md)

---

## 3. 프로그래밍 작업
- [ ] 코드 작성 전 **문서 선행**: `[요구사항]` → `[현상분석]` → `[구현계획]`
- [ ] 문서 작성 후 **사용자 승인**을 받은 뒤 구현 시작
- [ ] 필요 시 `[시험방법]`, `[사용방법]` 추가 작성

> 상세: [`[지침][프로그래밍] 프로그래밍 작업 규칙.md`]([지침][프로그래밍]%20프로그래밍%20작업%20규칙.md)

---

## 4. Git
- [ ] `claude_` 접두사 브랜치에서만 작업 (main 직접 커밋 금지)
- [ ] 파일 수정 전 feature 브랜치 생성 후 체크아웃
- [ ] 모든 병합은 `--no-ff`로 수행
- [ ] 커밋 완료 후, 병합 전 **사용자 확인** 필수
- [ ] Author/Committer: `김은수 <eunsu.kim@to-doc.com>` — AI 표시 절대 금지
- [ ] 커밋 메시지에 `Co-Authored-By` 등 AI 관련 라인 금지

> 상세: [`[지침][개발] Git 브랜치·병합 규칙.md`]([지침][개발]%20Git%20브랜치·병합%20규칙.md) / [`[지침][개발] Git Workflow 플로우차트.md`]([지침][개발]%20Git%20Workflow%20플로우차트.md)
