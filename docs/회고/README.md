# 회고 (Lesson & Learn)

이 폴더는 사용자와의 작업 중 학습한 패턴·교정·검증된 판단을 누적하는 곳입니다. `docs/지침/`과 달리 시간순으로 쌓이며, 일정 기간 검증된 회고는 `docs/지침/`으로 승격될 수 있습니다.

## 회고와 지침의 차이

| 측면 | `docs/회고/` | `docs/지침/` |
|---|---|---|
| 성격 | 학습 기록 (Lesson) | 공식 규칙 |
| 누적 방식 | 시간순/주제순 | 카테고리별 통합 |
| 성숙도 | 신생 (검증 중) | 안정 (검증 완료) |
| **효력 시점** | **즉시** | **즉시 (회고와 동일)** |
| 갱신 빈도 | 새로 발견 시 즉시 추가 | 회고가 안정화되면 본문 흡수 |

> [!IMPORTANT]
> **회고와 지침은 효력에서 동등하다.** 차이는 "성숙도/통합 정도"일 뿐이다. 회고에 등재되는 즉시 동작에 영향을 미치며, 시간이 지나 안정화된 항목이 지침으로 통합된다 (단순 카테고리 정리 차원).

## 트리거 — 언제 회고를 추가하는가

Claude가 다음 중 하나에 해당한다고 판단할 때, 사용자에게 *"이 내용을 `docs/회고/<카테고리>.md`에 기록할까요?"*라고 묻습니다.

1. **사용자가 교정한 경우** — *"아니 그거 말고"*, *"다음부터는~"* 등 명시적 교정
2. **사용자가 비전형적 선택을 받아들인 경우** — Claude의 비표준 판단을 사용자가 *"좋아"*, *"맞아"* 등으로 승인 (성공 사례도 기록 — 안 그러면 검증된 판단을 잃음)
3. **일반화 가능한 패턴 발견 시** — 한 작업 안에서 반복적으로 등장하는 규칙

## 저장 범위

> [!IMPORTANT]
> **저장 O — 일반화 가능한 장기 사실**
> - 일반 규칙·워크플로우 (예: 브랜치 모델, 문서 선행 원칙)
> - 사용자 선호 (예: 존댓말, 응답 말미 요약)
> - 검증된 판단·패턴

> [!CAUTION]
> **저장 X — 일시적·작업 스코프**
> - 진행 중인 작업의 상태·진행률·중간 결과
> - 현재 가설·디버깅 단서
> - 특정 작업에만 의미 있는 맥락
>
> → 작업 상태는 `docs/tasks/<모듈>/<작업>/[진행상황].md` 같은 핸드오프 문서로 관리.

## 항목 형식

각 회고 항목은 다음 구조를 따릅니다:

````markdown
## <제목> (YYYY-MM-DD)

<요지를 한 문장으로>

**Why:** 사용자가 명시한 또는 추정되는 이유.

**How to apply:** 미래의 Claude가 이 회고를 어떻게 적용할지 — 트리거 조건과 행동.
````

## 지침 승격

회고 항목이 충분히 안정화되어 카테고리 통합·일반화가 가치 있어지면 [`docs/지침/`](../지침/)으로 본문을 옮긴다. 절차:

1. 지침의 적절한 카테고리 문서에 본문 통합 (필요 시 형식 다듬기)
2. 회고에서 해당 항목 본문 **삭제** (중복 방지)
3. 아래 "승격 이력" 표에 한 줄 추가

> [!NOTE]
> 승격은 "효력 변경"이 아니라 "정리/통합" 차원이다. 회고에 있을 때도 이미 효력이 있었으며, 옮긴다고 더 강해지지 않는다.
