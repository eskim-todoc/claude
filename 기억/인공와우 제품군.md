# 인공와우 제품군

**TL;DR**: 은수님은 **인공와우(cochlear implant) 회사**에서 일하신다. 제품은 **외부기 · 내부기 · 리모콘 앱 · 매핑 앱** 네 조각. 외부기 계보는 **설리번 → 설리번1.5 → Sound1**이고, **은수님은 1.5세대부터 투입**되셨다. **Sound1 펌웨어는 1.5세대를 기반으로 마이그레이션한 것**이라 코드에 이전 세대의 흔적이 그대로 남아 있다 - 특히 **BLE 칩은 QCC 인데 매크로 이름은 아직 `NRF_`다.**

## 1. 제품 구성

| 조각 | 역할 |
|---|---|
| **외부기** | 소리를 받아 처리해 내부기로 보낸다. **이 저장소의 펌웨어가 도는 곳** |
| **내부기** | 체내 이식. 전극으로 자극한다 |
| **리모콘 앱** | 외부기를 **무선으로 제어**(볼륨·맵 전환·On/Off 등). 안드로이드 - 저장소는 §1.1 |
| **매핑 앱** | **내부기 사용 파라미터를 찾는** 피팅 도구 (T/C 레벨·전극 맵 등) |

## 2. 외부기 계보 - 3세대

| 세대 | DSP | BLE | 은수님 | 비고 |
|---|---|---|---|---|
| **설리번** (Sullivan) | **Ezairo 7150** | nRF51822 | 투입 전 | 원조 |
| **설리번1.5** (1.5세대) | **Ezairo 8300** | nRF51822 | **여기부터 투입** | **7150 단종에 따른 칩셋 마이그레이션** |
| **Sound1** | Ezairo 8300 | **QCC** | 담당 | 1.5세대 기반 + 기능 추가 |

**확신도: 확인됨** (은수님 진술 2026-08-18 + 아래 §3 코드 근거)

**두 번의 갈아타기가 서로 다른 층에서 일어났다** - 8300 전환은 **설리번 → 1.5**에서, QCC 전환은 **1.5 → Sound1**에서. 그래서 *"1.5세대와 같다"* 는 말은 **DSP 층에서는 참이고 BLE 층에서는 거짓**이다. 어느 층 이야기인지 늘 구분한다.

## 3. Sound1 = 1.5세대 기반 마이그레이션 - 코드에 남은 흔적

> 은수님: *"Sound1 E8300 펌웨어는 1.5세대를 기반으로 했고, 마이그레이션 하면서 이것저것 추가한거야. 가속도센서 -> 터치센서로 변경 등과 같이."*

### 3.1 함정 - `NRF_` 이름이 QCC 하드웨어를 가리킨다

```c
// projects/sound1-fw-e8300/src/2__cm3/source/board/board.h:22~25
#define DIO_NUM_NRF_SWDIO_NRESET                 // NOT USED ANY MORE
#define NRF_SPI_CS_PIN                    DIO21  // v0.35, NET: QCC_SPI_CS
#define NRF_SPI_CLK_PIN                   DIO28  // v0.35, NET: QCC_SPI_CLK
#define NRF_SPI_MOSI_PIN                  DIO26  // v0.35, NET: QCC_SPI_MOSI
```

**확신도: 확인됨.** 매크로 이름은 nRF 시절 그대로인데 **주석의 실제 넷 이름은 QCC**다. `tdc_ble_protocol.h` 의 *"nRF 자체 처리"* 주석들도 같은 성격의 유물이다.

> [!CAUTION]
> **`grep nrf` 결과를 「아직 nRF를 쓴다」로 읽으면 안 된다.** 반대로 `grep qcc` 로만 찾으면 BLE 배선을 통째로 놓친다. **이름이 아니라 넷·주석을 봐야 한다.**

### 3.2 EZ 와 QCC 가 마이크를 공유한다

```c
// projects/sound1-fw-e8300/src/1__cfx/lib_cfx/lib_audio_in.h:22, 37
// EZ와 QCC가 마이크를 공유하기 때문에,
#define LIB_DMIC_IDX_DMIC2 1  // U9, QCC      (FIFO MIC1)
```

**확신도: 확인됨(코드 주석).** 마이크 2개 중 **DMIC1 = U7(EZ, MIC0)** · **DMIC2 = U9(QCC, MIC1)** 이고 **QCC 쪽과 공유**한다. **[sound1/필수성능시험.md](sound1/필수성능시험.md) 와 직결될 수 있다** - 마이크 입력을 기준으로 삼는 시험에서 공유 상대가 마이크를 점유하면 어떻게 되는지는 **아직 확인 안 했다(미확인)**.

### 3.3 센서 교체

가속도센서 → **터치센서**. 구현은 `projects/sound1-fw-e8300/src/2__cm3/source/touch/tdc_touch.c`. **확신도: 확인됨(파일 존재)**

## 4. 내부기(ISD) 칩 - 함정 하나

### 4.1 「10V」가 서로 다른 두 대상을 가리킨다

**자극용 10V 는 «칩 내부 클럭 게이트»와 «칩 외부 스텝업 컨버터» 두 단계인데, 코드에서 둘 다 «10V»로 불린다.**
**확신도: 확인됨** - `projects/sullivan-1-5-fw-hw-test-link-pwr-bt-period` 의
`99_includeBoard/isd_ver1_1_2.h` 레지스터 정의 + `internalDevice/isd_interface_init_ISD.c` 주석 (2026-08-26).

| | `IO_Config` / SYSCLK_OE | `Stimul_10V` / VTG_UP_START |
|---|---|---|
| 레지스터 | **`0x10`** | **`0x11`** |
| 켜는 것 | 칩 **내부**. 주석은 *"SYSCLK_OE 을 1로 설정하여 자극 10V PMIC 활성화"* | 칩 **외부** 10V 스텝업 컨버터 (*"칩 외부 핀으로 여기서 설정 값이 출력됨"*) |
| 함수·순서 | `isd_path_Open()` (`ISD_Power_Ok` 상태) | `enableStimul_10v()` - **그 다음 상태**(`ISD_pathOpen_Ok`) |
| SW 검증 | **없다.** 되읽는 코드가 0건 | **있다.** `VTG_LOCK` 비트를 백텔로 되읽어 확인 |

> [!CAUTION]
> **«10V 를 켜는 코드»를 찾으라는 지시를 받으면 어느 쪽인지부터 가른다.** 이름이 둘 다 10V 라
> 엉뚱한 쪽을 고칠 수 있다. 순서상 SYSCLK_OE 가 먼저이고 외부 컨버터가 나중이다.

### 4.2 하드웨어로 10V 를 물리적으로 강제할 수 있다

은수님 진술 (2026-08-26): *"실제 하드웨어에서 이 설정과 무관하게 10V를 켤 수 있거든."* **확신도: 확인됨(진술)**

시험 보드에서 SW 제어를 끄고 HW 로 강제한 상태를 만들 수 있다. sullivan-1.5 에는 그것을 위한
`disable_ISD_SYSCLK_OE_SW` 매크로가 있다(기본 꺼짐). **단, 칩이 SYSCLK_OE 없이도 이후 backtel
통신에 정상 응답하는가는 SW 분석으로 확정할 수 없다** - 그 확인이 이 시험의 목적이다.
