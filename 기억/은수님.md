# 은수님

**TL;DR**: 헌법이 «어떻게 말할지»(존댓말·호칭·페르소나)를 규정한다면, 여기는 «무엇을 전제하고 말할지»다. **전제 확인은 양방향이다** - 제 분석이 틀린 적도, 은수님 전제가 사실과 다른 적도 있다(§3). 확신을 과장하지 말고 그때마다 코드를 연다. **펌웨어만이 아니라 리모콘 앱·도구도 직접 만드신다**(§2.1). 문서는 나중에 다시 읽으실 것을 전제로 쓴다.

> **소속·제품**: 인공와우(cochlear implant) 회사. 제품 구성과 외부기 3세대 계보(설리번 → 설리번1.5 → Sound1)는 [인공와우 제품군.md](인공와우%20제품군.md).

## 2. 코드에 대한 배경 - 인수인계 받아 스터디하는 입장

> 본인 진술 (2026-08-13): *"자세한 이유를 몰라. 나도 인수인계 받아서 스터디하는 입장이거든."*

**Sound1 의 CFX(DSP) 쪽 - 오디오 체인·AGC·FFT·BFP - 은 전임자가 쓴 코드**이고 은수님이 넘겨받아 파악하시는 중이다. 반면 **cm3(ARM) 쪽과 BLE·자극 로직은 은수님이 직접 다루신다.**

**투입 시점이 설리번1.5부터**다 - **설리번 세대 코드는 은수님 이전 것**이고, Sound1 은 그 1.5세대를 기반으로 마이그레이션한 것이다. 즉 **지금 보는 코드에는 은수님이 쓰지 않은 층이 두 겹 깔려 있다.** «왜 이렇게 되어 있나»를 물으실 때 이미 아실 거라 전제하지 않는다.

| 적용 | |
|---|---|
| CFX 쪽 | **«왜 이렇게 되어 있는가»를 함께 설명한다.** 코드를 읽으면 안다는 전제를 두지 않는다 |
| cm3·BLE 쪽 | 구조를 이미 아신다. **결론과 근거만** 간결히 |

> [!NOTE]
> 그렇다고 CFX 를 모르시는 게 아니다. `>>5` 를 하신 이유를 **정확히 기억해 내셨고 제 설명이 틀렸음을 짚으셨다**(§3). 「인수인계 받았다」는 «출처를 다 되짚지는 못한다»는 뜻이지 «모른다»가 아니다.

### 2.1 펌웨어만 하시는 게 아니다 - 앱과 도구도 직접 만드신다

**리모콘 앱(안드로이드·PC)과 그 보조 도구를 은수님이 직접 만드신다** (확인됨, 2026-08-26).

| 무엇 | 근거 |
|---|---|
| **안드로이드 리모콘 앱** | `설정 의존성과 앱 UI 규칙` 을 요청하시고, 직접 만드신 구현 사례 문서를 저장소에 두셨다.<br/>**`projects/sullivan-1-5-fw-hw-test-link-pwr-bt-period` repo** 의 `docs/참고/리모콘 프로토콜/안드로이드 앱 구현 사례.md` (형제 repo 라 상대 링크가 닿지 않아 경로로 적는다) |
| **브라우저 도구** | *"리모콘 측에서 docs 폴더에 html 문서도 생성해놨거든"* - 「백텔 NopStandby 타이밍 뷰어」(`docs/참고/백텔 링크 체크/자극 타이밍 스코프.html`). FIFO 24칸 배치를 그려 기준값과 대조해 주는 인터랙티브 뷰어다 |

| 적용 | |
|---|---|
| 프로토콜을 바꿀 때 | **앱이 무엇을 해야 하는지까지** 답이 나와야 끝난다. 펌웨어만 고치고 «앱은 알아서» 로 두지 않는다 |
| 은수님이 만드신 문서·도구를 발견하면 | **찾아갈 길부터 확인한다.** 위 html 은 파일만 있고 어디서도 참조되지 않아 «정리해라» 지시가 나왔다 - 내용이 아니라 **연결이 빠진 것**이었다 |

## 3. 검증 성향 - 전제 확인은 양방향이다

**제 분석을 그대로 받지 않으시고, 걸리는 부분을 구체적 근거로 되물으신다.**
초기 두 건은 **제가 틀렸고**, 세 번째는 **은수님 전제가 사실과 달랐다.**
어느 쪽도 «맞을 것»으로 전제하지 않고 **그때마다 코드로 확인하는 것**이 유일하게 통하는 방법이다.

| # | 누가 무엇을 주장했나 | 상대의 확인 | 결과 |
|---|---|---|---|
| 1 | **제가**: 믹서 `>>5` 는 과하니 `>>4` 로 줄이면 분해능이 2배 좋아진다 | *"볼륨 9, 10 에서 역으로 소리가 작아지는 현상이 있었다. 65535 가 최대여야 했다"* | **은수님이 맞았다.** `>>4` 는 볼륨 순서를 깨고 FFT 를 넘긴다. 제 문서 두 곳을 고쳤다 |
| 2 | **제가**: 데시메이션 게인이 유니티에서 −5.17 dB 밀려 있다 | *"SDK `analog_in.h` 의 `Sys_Calc_Gain_Factor_Val()` 로 계산하면 1092 였던 거 같은데, 아닌가?"* | **은수님이 맞았다.** SDK 는 `floor(log2())` 를 쓴다. 데이터시트 인쇄식을 실수 `log2` 로 읽은 제 오독이었다 |
| 3 | **은수님이**: *"코인 사용시 ... 가속기 방식 안쓰고 그냥 스탭 설정 만큼씩만 오르잖아. **이건 맞지?**"* (2026-08-26, sullivan-1.5) | 코드를 열어 보니 그 자리만 `TxPowerLevel++` **두 번, 2 스텝 고정**이었다. 상승 스텝 설정을 보지 않는 유일한 상승 지점이었다 | **은수님 전제가 달랐다.** 착수 전에 정정 보고했고, 그래서 그 요구가 «현상 유지»가 아니라 **상승 폭 2배인 실제 변경**임이 드러났다 |

> [!CAUTION]
> **«이건 맞지?» 는 동의를 구하는 말이 아니라 확인해 달라는 요청이다.** 3번이 그 사례다 -
> 그대로 «네 맞습니다» 했다면 은수님은 현상 유지인 줄 알고 **상승 폭이 2배 되는 변경**을 승인하셨을 것이다.
> 전제가 코드에 관한 것이면 **반드시 그 자리를 열어 본 뒤** 답한다.

> [!CAUTION]
> **적용 - 확신도를 과장하지 않는다.** 근거가 코드면 «코드로 확인», 인쇄물이면 «문서로 확인», 유추면 «추정»이라고 **구분해서 쓴다.** 1·2 두 사고 모두 **인쇄된 문서를 구현보다 위에 둔 것**이 원인이었다.
>
> 여기서 나온 규칙: **데이터시트의 인쇄된 수식보다 SDK·펌웨어의 실제 구현이 우선이다.** 계산 함수가 SDK 에 있는지 먼저 찾는다.

## 4. 지시 해석

| 사실 | 적용 |
|---|---|
| **범위를 넘겨 짚는 것을 싫어하신다.** 2026-08-18 *"먼저 앞서 나가지 말고, 지금은 내가 말하는 것에만 집중해봐."* | 새 작업 초입에 **스코프 질문을 여러 개 던지지 않는다.** 말씀하신 것만 처리하고 다음을 기다린다 |
| **선택지보다 «지금 무엇을 정하는 것인가»를 먼저 원하신다.** 2026-08-26 한 세션에서 선택지 제시(`AskUserQuestion`)를 **두 번 되돌리셨다.** 첫 번째 뒤에는 *"그러니까 0이면 disable, 1~100은 enable, 255는 무한이라 이거지?"* 로 **모델부터 확인**하셨고, 두 번째 뒤에는 선택지 대신 **원하는 답을 산문으로 직접** 주셨다 | 선택지를 던지기 전에 **무엇을 왜 정해야 하는지 한 단락으로 세운다.** 표·미리보기가 촘촘해도 그 앞에 «이게 무슨 결정인가»가 없으면 되돌아온다. 되돌아오면 **선택지를 다시 만들지 말고 배경부터 다시 설명**한다 |
| **되묻는 것이 실제로 이득이었다.** 2026-08-24 백텔 슬롯 - 제안을 그대로 구현했으면 **이득 0인 커밋**을 하고 개선했다고 보고할 뻔했다. 2026-08-26 코인 - 통합 방식을 여쭌 덕에 «통합의 대가»(앱이 인덱스를 잠그면 무한까지 잠긴다)를 발견했다 | 지시가 **구현 방법**까지 담고 있어도, **무엇을 고치려는 것인지**가 불명확하면 착수 전에 한 번 여쭌다. 그 한 번이 두 번 다 방향을 바꿨다 |
| **문서를 나중에 실제로 다시 읽으신다.** *"pdf 읽고 끝내지만 말고 분석한 내용도 나중에 또 볼수 있게 별도로 정리해놓고"* · *"내일 와서 확인해볼게"* | 대화로 답하고 끝내지 않는다. **찾아갈 수 있는 위치에 문서로 남긴다.** 폴더를 특정해 달라고 하시면 그대로 따른다 |
| 작업을 걸어 두고 자리를 비우시는 경우가 있다 | 중간에 막히면 **가정을 세우고 끝까지 진행**한 뒤 가정을 명시한다. 물어보고 멈춰 있으면 하루가 날아간다 |
| **인허가·시험 업무를 직접 담당하신다.** 기준서를 본인이 작성하신다 | [sound1/필수성능시험.md](sound1/필수성능시험.md) |
