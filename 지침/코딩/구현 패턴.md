# 코딩 구현 패턴

**TL;DR**: 코드 구현 시 되도록 FSM (Finite State Machine, 유한 상태 머신) 방식 우선 적용. 함수를 짤 때는 **유닛 경계**(결정론적 입출력·HW 의존 격리)를 의식한다 — 단, 테스트를 위한 분해는 금지하고 독립성이 자연스러운 곳만 가른다(§계층 인식 설계).

## FSM 우선 원칙

코드를 구현할 때는 가능한 한 **FSM 방식**으로 작성한다. 동작·플로우를 명시적 상태(state)와 전이(transition)로 표현해, 비차단·이벤트 기반 처리, 디버깅, 검증을 용이하게 한다.

### 적용 대상

- 멀티 스텝 시퀀스 (LED fade, 통신 프로토콜, 부팅 절차 등)
- 시간 흐름·이벤트에 따라 동작이 달라지는 모든 처리
- ISR / main loop 협력 구조
- 비차단 (non-blocking) 처리

### FSM 구현 시 권장 사항

- **상태 정의 명시화**: `enum` / `typedef` 로 상태 집합 선언, 변수명·주석으로 의미 명확화
- **전이 조건 분리**: 각 상태의 진입·유지·전이 조건을 함수 / 분기로 분리, 조건 중첩 회피
- **단일 step 함수**: ISR 또는 main loop 가 매 tick `step()` 한 번 호출, 호출자는 즉시 return
- **부수효과 격리**: 상태 전이 시점에서만 외부 자원(GPIO, 타이머 등) 조작
- **현재 상태 가시화**: 디버깅·로그 용으로 현재 상태 조회 인터페이스 제공 권장

### 회피 패턴

- `for { step(); delay_ms(1); }` 형 동기 폴링 (호출자 블로킹) — 비차단/ISR 기반 시스템에서 회피
- 플래그 + 분기가 누적되어 암묵적 상태머신이 되는 구조 — 명시적 FSM 으로 리팩토링
- 한 함수가 다중 상태 처리 + 전이 + 부수효과를 모두 담당

## 예외

> [!NOTE]
> 단순 1-shot 처리, 순수 계산 함수, 단순 setter/getter 등 상태 흐름이 없는 코드는 FSM 으로 만들지 않는다. 과도한 추상화 회피.

## 계층 인식 설계

FSM 의 `step()` 함수처럼 **상태·입력 → 다음 상태·출력이 결정론적인 단위**는 그대로 **유닛 후보**다. 함수를 짤 때 순수 계산과 하드웨어 접근을 한 함수에 섞지 말고(의존성 격리), 유닛 경계를 의식한다.

- 계층 분해·의존성 테스트 순서: [`밸리데이션 계층화.md`](밸리데이션%20계층화.md) §7.1 (코딩 방법)
- 하드웨어 설정에 관여하면: [`레지스터·하드웨어 설정 검증.md`](레지스터·하드웨어%20설정%20검증.md) 5게이트 병행

> [!IMPORTANT]
> 위 §예외의 "과도한 추상화 회피"와 **같은 방향**이다. **테스트를 위한 분해는 금지** — 독립성이 자연스러운 곳만 유닛으로 가르고, 간단한 glue 는 하드코딩해도 된다.
