# 경로·참조 표기

**TL;DR**: 같은 repo 내는 **상대경로**(공백은 `%20` URL 인코딩), 크로스 repo(형제 `projects/*`·`wiki`)는 **절대경로**(`E:\workspace\...`), 과거 `docs/tasks/**` 스냅샷은 **소급 수정 금지**. 링크 무결성은 `tools/check-links.ps1`로 검증한다.

## 1. 같은 repo 내 참조

- 마크다운 링크는 **상대경로**. 공백은 URL 인코딩(`%20`).
- 예: `[활용.md](../서브에이전트/활용.md)`, `[작성 규칙.md](작성%20규칙.md)`
- 링크 무결성은 [`../../tools/check-links.ps1`](../../tools/check-links.ps1)로 검증(코드블록·외부 URL·순수 앵커 제외, bare 상대링크까지).

## 2. 크로스 repo 참조 (형제 독립 repo)

- rules와 `projects/<name>`·`wiki`는 엄브렐러(`E:\workspace\`) 아래 **형제 독립 repo**다. 상대경로로 안정 참조 불가.
- 크로스 repo 참조는 **절대경로**(`E:\workspace\projects\...`) 또는 전역 `CLAUDE.md` 포인터를 쓴다.
- 형제 repo는 gitignored라 rules 단독 클론 환경에서는 없을 수 있음 — "예시 경로이며 프로젝트별로 확인" 캐비트를 병기한다.

## 3. 과거 tasks 스냅샷

- 완료된 `docs/tasks/**` 산출물의 경로 언급은 **불변 스냅샷**이다 — 구조 개편·이동 시 소급 수정하지 않는다(작성 당시 사실 보존).

## 4. 기술적 절대경로 (훅·설정)

- 훅·스크립트가 실행에 쓰는 경로(`.claude/settings.json` 훅 `-File`, 스크립트 하드코딩 fallback 등)는 실경로 절대경로(`E:\workspace\rules\...`)를 쓴다 — 상대 해석이 세션 cwd에 좌우되면 안 되기 때문.
