# 문서 작성 규칙 (인덱스)

**TL;DR**: 모든 영속 문서는 GFM(.md) + frontmatter(name·purpose·type·tags) + TL;DR. 폴더는 `지침/`(산출물)·`tasks/`(작업 과정 기록) 2대 카테고리 — **루트는 `지침/`이 `docs/` 밖 최상위 승격**(2026-07-13~), 프로젝트는 `docs/지침/` 그대로. 작업 폴더명은 `YYYYMMDD_HHmm_<slug>` 날짜+시각 prefix(시각 2026-08-05~). 세부 파일 라우팅은 [`README.md`](README.md)가 유일 인덱스, 본 파일은 개념·적용범위·구 prefix 매핑 전용.

## 1. 적용 범위

- 루트 작업 → `지침/`(지침 산출물) + `docs/tasks/`(작업 기록)
- 프로젝트 작업 → `projects/<이름>/docs/`(지침·tasks 모두 `docs/` 하위 유지)
- 각 스코프는 **독립적인** 폴더 구조와 `tasks/작업 목록.md`(모듈별 분산) 레지스트리를 유지한다. 크로스 스코프 참조는 절대 경로 링크로 표현.

### 1.1 루트 vs 프로젝트 docs — 적용 범위와 우선순위

| 위치 | 성격 | 적용 범위 |
|---|---|---|
| 루트 `지침/` | **전역 기본값** | 모든 프로젝트에 자동 적용 |
| 프로젝트 `docs/지침/` | **특화 예외** | 해당 프로젝트 한정 |

> [!IMPORTANT]
> **충돌 시 프로젝트 지침이 우선한다.** 프로젝트 지침은 그 프로젝트의 더 구체적인 컨텍스트(하드웨어 제약·도메인 관습 등)를 반영한 의도적 예외이기 때문이다.

원칙적으로 프로젝트 지침은 **꼭 필요할 때만** 작성한다 — 가능한 모든 규칙을 루트에 두고, 어쩔 수 없이 특화가 필요한 경우만 프로젝트 측에 둔다.

## 2. 세부 지침

문서 형식 관련 세부 지침(폴더 구조·메타/frontmatter·작성 스타일·테마 토큰·양식)의 라우팅은 [`README.md`](README.md)가 **유일 인덱스**다 — 신규 파일 추가 시 그 표만 갱신한다(폴더 내 이중 인덱스 방지). 본 파일은 개념·적용 범위·구 prefix 매핑만 다룬다.

## 3. '정리해' 요청 시

- 사용자가 '~하고 정리해', '~하고 정리해봐' 등으로 정리를 요청하면, **작업이 수행된 위치의 `docs/` 폴더**에 `.md` 문서로 정리한다.
- 정리 내용의 성격에 따라 배치:
  - **영속적 규칙·가이드** → `지침/` 또는 `사용방법/` 아래
  - **작업 관련 산출물** → 해당 `tasks/<모듈>/YYYYMMDD_HHmm_<작업>/` 폴더 내부
- 다이어그램·절차 흐름이 포함되면 Mermaid로 작성한다.

## 4. 기존 prefix 컨벤션 (구 규칙, 참고용)

2026-04-24 이전에는 `[카테고리] 문서명.md` 프리픽스 컨벤션을 썼다. 구 프리픽스는 새 폴더에 대응:

| 구 프리픽스 | 신 위치 |
|---|---|
| `[지침]`, `[지침] [일반]`, `[지침] [Git]`, `[지침] [코딩]` | `지침/` 하위 2~3레벨 |
| `[사용방법]` | `사용방법/` (별도 wiki repo) |
| `[요구사항]` / `[분석]` · `[현상분석]` / `[구현계획]` / `[시험방법]` | `tasks/<모듈>/<작업>/요구사항.md` 등 고정 파일명 |
| `[참고]` | `참고/<모듈>/<파일>.md` (별도 wiki repo) |
| `[기준]` | `지침/<파일>.md` (체크리스트는 지침의 하위 유형, 전용 폴더 없음) |
| `[이력]` | `이력 및 결과/` 또는 해당 작업 폴더 내부 `이력 및 결과.md` |
| `[로그]` | 해당 작업 폴더 내부에 원 파일명 유지 (e.g., `터치 초기화 실패.txt`) |
| `[메모]` | `메모/` 또는 임시 `scratch/` 활용 |

기존 프로젝트(Sound1 등)의 migration은 후속 작업으로 진행한다 (`tasks/작업 목록.md` 참조).
