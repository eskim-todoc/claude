# 양식 — 요구사항.md

**TL;DR**: 4단계 2게이트 ① 인터뷰·요구사항 산출물 표준 양식. 사용자 요청 원문·**인터뷰 기록**·목표·수용 기준·작업 범위 외·위임 범위·관련 산출물 7개 섹션. **§2 인터뷰 기록이 요구사항 검증을 대신한다** — 별도 검증 문서를 만들지 않는다. 양식 본문을 작업 폴더의 `요구사항.md`로 복사한 뒤 `<...>` placeholder를 채워 사용.

## 사용법

1. 새 작업 폴더(`docs/tasks/<모듈>/YYYYMMDD_HHmm_<slug>/`) 생성 — `HHmm`은 24시간제 00~23시·분
2. **문서를 먼저 쓰지 않는다.** 모호점이 없어질 때까지 사용자에게 질문한다 ([`작업-프로세스.md §1.5`](../../일반/작업/작업-프로세스.md))
3. 본 파일의 §양식 본문을 복사해서 작업 폴더의 `요구사항.md`로 저장
4. `<...>` placeholder를 실제 내용으로 채움 — **§2에 실제 질문과 답변을 표로 남긴다**
5. **본문 섹션은 양식 §순서·헤더 그대로 사용** — 해당 없는 섹션도 헤더 유지 + 본문에 "해당 없음" 한 줄 표기 (섹션 삭제 금지)
6. 작성 직후 셀프 체크: frontmatter·TL;DR·의미 한글 라벨 ([`../../문서/메타-frontmatter.md`](../../문서/메타-frontmatter.md))
7. `이력 및 결과.md`를 **이 단계 시작과 동시에** 생성한다

> [!IMPORTANT]
> **인터뷰 종료 조건은 «모호점 0 + 수용 기준을 쓸 수 있는 상태»다.** §3 수용 기준을 스스로 작성할 수 없다면 아직 덜 물은 것이다. 사용자가 *"바로 해"*·*"알아서 해"*라고 명시하면 인터뷰를 생략하되 그 사실을 §2에 적는다.

> [!NOTE]
> 양식은 **포괄적 골격** — 모든 작업의 인지 경로 통일이 목적. §섹션 헤더는 순서·명명 그대로 유지, 해당 없는 섹션은 "해당 없음"으로 명시.
