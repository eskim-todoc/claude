# 양식 — 검증리스트.md

**TL;DR**: 4단계 2게이트 ③ 산출물 표준 양식. **게이트 1 통과 직후** 체크된 Step에서 역산해 만들고, ④ 구현·자체 선테스트를 마친 뒤 **§1을 스스로 채운 다음** 사용자에게 §2 체크를 받는다(게이트 2). 항목은 **반드시 리스트(`- [ ]`)로** 쓴다 — 표 셀 안의 `[ ]`는 클릭되지 않는다. §1은 Claude가 기계적으로 확인 가능한 것, §2는 사용자가 실제로 써 보거나 읽어야 아는 것만. 미통과 항목은 사유에 따라 «구현 실수 → 수정 후 재체크» / «계획 결함 → 이슈보고서»로 나뉜다.

## 사용법

1. **게이트 1 통과 직후** 본 양식을 복사해 작업 폴더의 `검증리스트.md`로 저장 — 무엇을 확인할지가 곧 구현 목표가 되므로 구현 전에 만든다
2. `계획.md` §4에서 **체크된 Step**과 `요구사항.md` §4 **수용 기준**에서 역산해 항목을 채운다. 체크 해제된 Step의 검증 항목은 넣지 않는다
3. §0에 게이트 1의 확정 사항(선택된 Step·결정)을 옮겨 적는다 — 나중에 «왜 이 범위였나»를 되짚는 근거가 된다
4. ④ 구현·자체 선테스트 후 **§1을 채운다.** 실패한 항목은 사용자에게 넘기기 전에 스스로 고치고, 고친 내용을 §1.1에 남긴다
5. 사용자에게 **게이트 2** 체크를 요청한다

> [!CAUTION]
> **체크 항목은 표가 아니라 리스트로 쓴다.** GFM은 **리스트 항목의 `- [ ]`만** 체크박스로 렌더링한다. 표 셀에 넣은 `[ ]`는 그냥 글자라서 **클릭할 수 없다.** 근거·방법은 항목 뒤에 `—`로 이어 붙이고, 서술이 길면 별도 절(§1.1 등)에 표로 정리한다.
>
> 같은 이유로 `계획.md`의 §실행 계획·§핵심 결정도 리스트다. **게이트가 걸리는 곳은 전부 리스트여야 한다.**

> [!IMPORTANT]
> **§2에는 Claude가 확인할 수 없는 것만 남긴다.** 제가 돌릴 수 있는 검사(빌드·grep·링크체크)를 사용자에게 넘기지 않는다. §2가 비대해지면 게이트가 부담이 되어 형식으로 퇴화한다.

> [!TIP]
> §1의 상시 후보 — 빌드·테스트 통과 · 잔존 표현 `grep` 0 · [`tools/check-links.ps1`](../../../tools/check-links.ps1) broken 0 · 신규 문서 frontmatter·TL;DR · 문자 손상(`U+FFFD`) 0 · `git diff --stat`로 의도 밖 변경 0 · 커밋 분할이 계획대로인지.
