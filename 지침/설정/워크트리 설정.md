# 워크트리 설정 (배경 세션 자동 격리 해제)

**TL;DR**: Claude Code 배경 세션은 **기본적으로 git 워크트리로 격리** 편집한다 — "작업 지시 시 자동 워크트리"의 원인. `worktree.bgIsolation:"none"`이 이를 꺼 메인 체크아웃을 **직접 편집**하게 한다. 모든 프로젝트 공통이면 **전역**(`~/.claude/settings.json`, git 밖), 프로젝트별이면 각 repo **Project scope**에 둔다. "원할 때만 워크트리"는 명시 요청 시에만.

## 1. 무엇을 제어하나

- **배경 세션 기본 동작**: 백그라운드/async로 실행되는 세션은 기본적으로 새 git 워크트리를 만들어 그 안에서 격리 편집한다. → 은수님이 겪은 "특정 프로젝트에서 작업 지시하면 자체적으로 워크트리로 진행"이 이것.
- **`worktree.bgIsolation:"none"`**: 배경 세션 워크트리 격리를 **끈다**. 세션이 메인 체크아웃(현재 브랜치)을 직접 편집한다. (Eclipse 워크스페이스 `src/` import 정합처럼 in-place 편집이 필요한 상황에도 부합.)
- **`worktree.baseRef`와 구분**: `baseRef`(`fresh`/`head`)는 워크트리를 *만들 때* 어느 ref에서 분기할지만 정한다 — **격리 여부(자동 진입)와 무관**. 자동 진입 자체를 끄는 키는 `bgIsolation`이다.

> [!NOTE]
> `bgIsolation`은 Claude Code 공식 문서에 명세가 얇은 키다. `"none"`=격리 해제는 **실증**으로 확인됐다(rules·sound1-fw-e8300 repo, 그리고 이 설정을 상속한 배경 세션이 "워크트리 격리 대신 in-place로 설정됨"으로 동작). 격리를 *켜는* 값은 별도 명시하지 않아도 **미설정=기본 격리**이므로, 특정 프로젝트만 워크트리를 원하면 그 repo에서 키를 빼면(전역과 다르게) 된다.

## 2. 스코프별 위치 (우선순위 높→낮)

| 스코프 | 위치 | 성격 |
|---|---|---|
| 프로젝트 로컬 | `<repo>/.claude/settings.local.json` | gitignored, 개인 오버라이드 |
| 프로젝트 공유 | `<repo>/.claude/settings.json` | git tracked, 그 repo 한정 |
| **전역 (User scope)** | `~/.claude/settings.json` (`C:\Users\<사용자>\.claude\`) | **git 밖**, 모든 프로젝트 공통 기본값 — rules는 값만 캡처 |

## 3. 설정 값

### 3.1 전역 기본 OFF (2026-07-14 적용, 권장)

모든 프로젝트에서 배경 세션 자동 워크트리를 끄려면 전역에 둔다:

```jsonc
// ~/.claude/settings.json  (User scope, git 밖)
{
  "worktree": {
    "baseRef": "fresh",     // 워크트리 생성 시 분기 base (격리 여부와 무관, 기존 유지)
    "bgIsolation": "none"   // ← 배경 세션 자동 워크트리 격리 OFF
  }
}
```

### 3.2 프로젝트별 설정

특정 프로젝트만 별도 정책을 원하면 그 repo의 `.claude/settings.json`에서 `worktree` 키를 병합해 오버라이드한다(전역보다 우선). 신규 프로젝트 표준 세팅에서의 배선은 [`../일반/프로젝트 초기 세팅.md §2.3`](../일반/프로젝트%20초기%20세팅.md) 참조.

## 4. 왜 전역에 두나 (2026-07-14)

- 원래는 **프로젝트별**(`.claude/settings.json`)로만 두는 방식이었다([`프로젝트 초기 세팅.md`](../일반/프로젝트%20초기%20세팅.md)) → repo마다 반복해야 해서 **설정 누락 시 그 프로젝트에서 자동 워크트리가 되살아나는** 문제.
- **전역**(`~/.claude/settings.json`)에 한 번 두면 모든 프로젝트가 기본 OFF를 상속 → 누락 방지. 프로젝트별 override는 그대로 유효.

## 5. "원할 때만 워크트리" 켜기

- **명시 요청**: 은수님이 "이 작업은 워크트리로 해줘"라고 지시하면 그때만 `EnterWorktree`로 진행.
- **특정 프로젝트 상시 워크트리**: 그 repo `.claude/settings.json`에서 `bgIsolation` 키를 빼면(또는 전역과 다르게 두면) 그 프로젝트만 기본값(격리)으로 되돌아간다.

## 6. 새 환경 재현

- 새 PC/새 Claude Code 설치 시 `~/.claude/settings.json`의 `worktree` 블록에 `baseRef`·`bgIsolation` 두 키를 넣는다(§3.1 값 그대로).
- **자기설정 수정 가드**: Claude가 `~/.claude/settings.json`을 직접 `Edit`하는 것은 원칙적으로 보안 정책으로 제한되며, `/update-config` 명시 호출 또는 은수님 직접 반영이 정석이다([`프로젝트 초기 세팅.md §9.3`](../일반/프로젝트%20초기%20세팅.md)). (배경·auto 권한 모드에서는 승인 하에 Edit이 통과되기도 함 — 환경 의존이므로 새 환경에선 `/update-config`를 기준으로 삼는다.)
