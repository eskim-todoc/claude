# 작업 완료 처리

**TL;DR**: 사용자 "작업 끝났어" 시그널 수신 시 (1) `이력 및 결과.md` 완료 요약 추가, (2) 해당 모듈 `작업 목록.md` 상태 컬럼을 `완료`로 + 완료일 기록, (3) `모듈 현황.md` 모듈 행 갱신(최종 업데이트·최근 작업·작업 수), (4) 커밋 → 사용자 승인 → `--no-ff` 병합. archive 폴더 폐지(2026-05-15~) — 작업 폴더 위치 영구 유지.

## 1. 절차

1. **`이력 및 결과.md` 완료 요약 섹션 추가** — 시계열 로그는 진행 중 누적되어 이미 존재. 형식은 [`../문서/폴더-구조.md §4.2`](../../문서/폴더-구조.md)
2. **`tasks/<모듈>/작업 목록.md` 갱신** — 해당 행의 `상태` 컬럼을 `완료`로 변경 + `완료일` 기록
3. **`tasks/모듈 현황.md` 갱신** — 해당 모듈 행의 `최종 업데이트`(완료일)·`최근 작업`(본 작업 폴더 링크)·`작업 수`(+1) 갱신. 신규 모듈이면 행 추가. 정렬 재조정(최종 업데이트 내림차순 → 작업 수 내림차순 → 모듈명 사전순). 본 파일이 없으면 새로 생성. 본 인덱스는 모듈 단위 헬스 스냅샷.
4. **커밋 → 사용자 승인 → `--no-ff` 병합**

> [!NOTE]
> 2026-05-15 Task α부터 **작업 폴더는 완료 후에도 `tasks/<모듈>/<작업>/` 그대로 유지** (`_archive/` 폴더 폐지). 외부 링크 안정성 + 폴더 이동 비용 0. 활성/완료 식별은 각 모듈 `작업 목록.md`의 `상태` 컬럼으로.

## 2. 트리거

- 사용자 *"작업 끝났어. 마무리해"* 류 시그널
- 또는 사용자가 검수 후 명시 승인

## 4. deprecation 리플 규칙

지침 파일을 폐지(deprecated 전환 또는 삭제)하는 커밋은, 그 파일을 인용하는 **모든 역링크를 같은 커밋에서 함께 정리**(제거 또는 "(비활성)" 표기)해야 완료로 인정한다.

- 폐지 직전 `Grep`으로 인용처를 **전수 재확인**한다 — 문서에 적힌 고정 개수를 신뢰하지 말고 그 시점의 fresh grep 결과를 유일한 근거로 삼는다.
- 폐지 후 `tools/check-links.ps1`로 잔존 깨진 링크 0을 확인한다.

**Why:** 폐지된 지침을 현재형으로 인용하는 역링크가 남으면 온디맨드 탐색자가 사문화된 절차를 유효한 것으로 오인한다(계획 모드 자동 진입.md가 그 실례 — deprecated 상태로 5+곳에서 현재형 인용됨).
