# 작업 진행 규칙 (인덱스)

**TL;DR**: 모든 작업은 ① 인터뷰·요구사항 → ② 분석·계획 → **[게이트 1]** → ③ 검증리스트 → ④ 구현·자체 선테스트 → **[게이트 2]**. 상시 산출물 4종(요구사항·계획·검증리스트·이력 및 결과), **검증은 은수님 체크박스**이며 게이트는 2회뿐이다. 계획 결함 발견 시 중단하고 `이슈보고서_N_<주제>.md`를 낸다. 완료 시 모듈별 작업 목록.md·모듈 현황.md 갱신. 명백한 단순 수정은 면제. 별도로 **검수(§5)** 는 각 프로젝트 `docs/검수/` 리스트를 실행하는 활동으로 본 프로세스와 구분한다. 본 파일은 진입점 — 상세는 하위 파일.

## 1. 적용 범위

| 적용 | 비적용(면제) |
|---|---|
| 코드 작성·수정 | 명백한 오타 수정 |
| 문서 작성·구조 변경 | 단일 설정값 변경 |
| 지침·정책 변경 | 한 단어·한 줄의 자명한 교정 |
| 분석·조사 작업 (보고서가 산출물) | 사용자가 "바로 해" 류로 명시한 trivial 작업 |
| 도구·자동화 스크립트 추가·수정 | |
| 외부 시스템 연동·환경 설정 | |

> [!IMPORTANT]
> 적용 여부가 모호하면 **적용한다.** 작업 프로세스 면제는 명백한 단순 작업에 한정. 모호하면 [`명령 해석 규칙.md`](명령%20해석%20규칙.md)에 따라 사용자에게 질문.

## 3. 서브에이전트 활용 (병렬·효율)

각 단계 산출 시 **광범위 탐색·다중 가설 분석·독립 작업 동시 실행** 등 서브에이전트로 병렬·효율화 가능한 부분이 있으면 **되도록 가능한 최대로 활용**한다 (default가 활용). 단계별 활용 매핑·종류별 선택·병렬 호출 방법·안티패턴은 [`서브에이전트 활용.md`](../서브에이전트/활용.md) 참조.

> [!TIP]
> 단계 ②(분석·계획)는 코드베이스 탐색·영향 범위 식별 같이 서브에이전트가 가장 큰 가치를 내는 단계다. 다만 **게이트 1 전이므로 read-only fan-out만** 허용된다 — 쓰기 fan-out은 게이트 1 통과 후 ④에서만 ([`작업/작업-프로세스.md §6`](작업/작업-프로세스.md)).

## 4. 단순 수정 예외

> 다음에 해당하면 작업 프로세스 면제하고 바로 처리. 단 변경이 광범위하거나 부작용 가능성이 있으면 적용.
> - 오타 수정 (단어·문장 교정)

> - 한 줄·한 단어의 자명한 교정

## 5. 검수 (제품 차원 QA)

사용자가 **검수**를 명령하면, 작업 중인 프로젝트의 **`docs/검수/`** 를 먼저 확인한다.
검수 리스트가 있으면 사용자가 지정한 **목적·범위에 가장 부합하는 리스트를 골라** 그 항목들을 수행한다.

- **검수 실행은 프로세스 적용 작업이 아니다.** 리스트 항목 수행 → **결과 보고** → 리스트의 **상태 칸 갱신**.
  근거(스크립트·로그·시뮬레이션 결과·실기 로그)는 관련 **작업 폴더**에 남기고 리스트에서 링크한다.
- **검수 리스트 자체의 작성·갱신은 일반 프로세스 작업**으로 다룬다 — 리스트가 곧 산출물이다.
- `docs/검수/` 아래는 **카테고리(도메인) 폴더**로 나누고(예: `stimulation/`), 각 폴더에 **뭉텅이 실행 단위의 리스트 파일**을 둔다.
  별도 인덱스는 두지 않는다 — 파일 자체가 리스트다. 프로젝트가 `docs/검수/`를 쓰려면 프로젝트 CLAUDE.md의 docs 구조에 등재한다.

> [!NOTE]
> "stimulation 검수해줘" 같은 지시는 §1~§4의 4단계 2게이트 프로세스가 아니라 **여기(§5) 절차**를 따른다. 반대로 "검수 리스트에 항목 추가해줘"·"검수 체계 만들어줘"는 프로세스 적용 작업이다.

### 5.1 검수 상태 정의 (전 프로젝트 공용)

| 상태 | 의미 |
|---|---|
| `미검증` | 아직 검증하지 않음 |
| `시뮬레이션` | 로직·시뮬레이션으로만 통과. 실기 미확인 |
| `실기확인` | 실기에서 통과 |
| `설계상` | 의도된 동작·미지원. 검증 대상 아님 |

### 5.2 검수 항목 양식

각 리스트 파일은 frontmatter + TL;DR 뒤에 **항목 표**를 둔다.

| 열 | 내용 |
|---|---|
| ID | 리스트 내 고유 번호 |
| 대상 | 기능·모듈·파일 |
| 조건 | 입력·상태 (예: 프레임 3~13 × 밴드 1~32) |
| 방법 | 시뮬레이션 / 실기 / 무회귀 대조 / 분석 |
| 기대 | 불변식·수용 기준 |
| 상태 | §5.1 값 |
| 근거 | 작업 폴더·스크립트·결과 링크 |
