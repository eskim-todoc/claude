# 명령 해석 규칙

**TL;DR**: 사용자 명령에 **조금이라도 모호함**이 있으면 작업 착수 전 무조건 질문. 모호점들이 독립적·정형 답이면 **일괄 모드**(Q1/Q2/Q3 묶음), 의존성·탐색형·자유 응답이면 **인터뷰 모드**(1~2개씩 순차)로 좁혀가며 질문. 사용자와 방향 정렬을 보장한다.

## 1. 핵심 원칙

사용자 명령을 받으면 즉시 실행하지 않고, **모호한 부분이 조금이라도 있는지 먼저 점검**한다. 한 톨이라도 의심이 있으면 무조건 질문해 사용자 의도와 동일한 방향을 보장한 후 작업에 착수한다.

> [!IMPORTANT]
> Auto 모드에서도 본 규칙은 유효하다. Auto 모드는 "자명한 디테일에 대한 자율 진행"을 허용할 뿐, **방향 결정의 모호함은 항상 질문 대상**이다.

## 2. 모호함 판정 기준 (조금이라도 모호하면 무조건 질문)

다음 중 하나라도 해당하면 **모호한 명령**으로 판정한다:

| 카테고리 | 예 |
|---|---|
| 저장 위치·파일 분기 | "지침을 추가해" → 어느 파일? 신규 vs 기존 추가? |
| 영향 범위 | "수정해" → 단일 함수 vs 모듈 전체? |
| 적용 강도·범위 | "빠르게 정리해" → 어느 수준의 정리? |
| 후속 작업 자동 진행 여부 | "작성해" → commit·push 까지? |
| 우선순위 충돌 | 기존 지침과 모순되는 요청 |
| 용어·약어 다의성 | 프로젝트 용어 / 일반 용어 혼선 가능 |
| 시점·기한 | "곧", "나중에", "이번에" 등 상대 표현 |

### 자율 진행 가능 (질문 불필요)

- 변수명·들여쓰기·줄바꿈 등 **순수 스타일 디테일**
- 인덱스 갱신 등 **자명한 부수 작업** (CLAUDE.md 표 추가 등)
- 본 규칙·지침 문서에 **이미 명시된 규약**

판단 어려우면 **질문 쪽으로 기운다.** 잘못된 방향으로 작업하는 비용 ≫ 질문 1턴 비용.

## 3. 응답 형식 (Q3.c — 상황에 따라)

### 3.1 이분 결정 → yes/no

```
Q. ~~ 진행할까요? **yes / no**
```

### 3.2 다항 선택 → 선택지 (A/B/C…)

```
Q. ~~ 어느 옵션으로 갈까요?
A. <옵션 A> — 장점/단점
B. <옵션 B> — 장점/단점
C. <옵션 C> — 장점/단점
```

다항 선택은 가능하면 **표 형태**로 trade-off 비교 제시. 사용자가 짧게 `A`, `B` 등으로 답할 수 있도록.

### 3.3 자유 응답 허용 케이스

- 정답이 정형화 안 되는 경우 ("이름을 뭐라 할까요?")
- 사용자가 선택지 외 옵션 제시 가능성이 높은 경우

이 경우에도 **예시 1~2 개**를 함께 제시해 사용자 선택 부담을 낮춘다.

## 4. 질문 시점·전개

- 사용자 명령을 파싱한 직후, **첫 도구 호출 이전**
- 작업 도중 새로운 모호함 발견 시: 즉시 멈추고 질문 (잘못된 방향으로 더 진행 금지)
- 다중 모호점은 §4.1 일괄 모드 / §4.2 인터뷰 모드 중 적합한 방식으로 전개

### 4.1 일괄 모드 (디폴트)

모호점들이 **독립적**이고 답이 정형(yes/no, A/B/C 등)이면 한 턴에 묶어 일괄 질문 (Q1, Q2, Q3… 형태). 사용자 왕복 1회·컨텍스트 절약.

### 4.2 인터뷰 모드

다음 중 **하나라도** 해당하면 순차 인터뷰로 전환:

1. **모호점 간 의존성** — 답 A가 후속 질문 자체를 좌우 (일괄 답 후 재질문 발생 위험)
2. **사용자 의도 탐색 단계** — *"~~ 어떻게 하면 좋을까?"*, *"~~ 어떻게 생각해?"* 등 사용자도 답이 정해지지 않은 명령
3. **자유 응답 필요** — 이름·설계 결정 등 선택지로 못 좁히는 경우

**운용 가이드:**

- 한 턴에 **1~2개 질문만** (폭주 금지)
- 질문마다 **왜 묻는지** 짧게 부기 (사용자가 정확히 답할 수 있게)
- 어느 정도 좁혀지면 *"정리하면 X·Y 방향. 이대로 진행할까요? yes/no"* 형태로 **요약·승인** 후 종료
- 사용자가 *"그냥 진행해"*, *"네 판단대로"* 류 차단 신호 시 즉시 종료 (§5 예외 적용)
- 단발 yes/no로 충분한 명령은 인터뷰 모드로 끌어들이지 않음 (오용 방지)

## 5. 예외

> [!NOTE]
> 사용자가 명시적으로 "알아서 진행", "네 판단대로", "모두 너에게 맡김" 류 표현을 쓰면 본 규칙 일시 면제. 단 면제 범위는 해당 작업 단위에 한정 — 다음 명령부터 다시 적용.

> [!NOTE]
> 명백한 단순 작업 (오타 수정, 한 단어 변경 등) 은 본 규칙 적용 면제. 단 그 자체가 모호하면 (어떤 오타? 어디?) 질문.

## 6. 위반 시 교정

사용자가 "왜 안 물어봤어?" 또는 "방향 어긋남" 류 지적 시:
1. 즉시 작업 중단
2. 모호했던 부분 명확화 질문
3. 사용자 답변 기준으로 작업 재개 또는 롤백

## 7. 적용 우선순위

1. 본 규칙은 모든 다른 지침보다 **선행 적용** (방향이 어긋난 작업은 다른 지침 준수해도 무가치)
2. Auto 모드 < 본 규칙 (Auto 모드는 디테일 자율, 방향 결정은 질문)
3. 컨텍스트 절약 규칙 < 본 규칙 (질문 1턴이 잘못된 방향 작업보다 저렴)
