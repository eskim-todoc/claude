# 커밋 메시지 컨벤션

**TL;DR**: 커밋 메시지 제목은 `<Prefix>[(<scope>)]: <요약>` 형식. Prefix는 §2의 19종 중 변경 성격에 가장 가까운 **1~2개** (영향 큰 순, 2개 초과 금지). 제목 50자 내 권장·명령형·마침표 생략. 본문은 무엇·왜·어떻게를 한 단락 또는 bullet으로. `BREAKING CHANGE`·`HOTFIX`는 단독 사용 권장. 기존 소문자 prefix(`docs(...)` 등) 커밋과 양립 가능 — 신규 commit부터 본 컨벤션 적용.

## 1. 형식

```
<Prefix>[(<scope>)]: <짧은 요약>

<상세 본문 — 무엇·왜·어떻게>
```

- **Prefix**: §2 표에서 변경 성격에 가장 가까운 항목 1~2개. **첫 글자 대문자** 권장
- **scope** (선택): 변경 영역 — `tasks/<모듈>` 명명과 일치 권장 (예: `meta`·`지침`·`LED`·`mermaid-study`)
- **요약**: 50자 내 권장. **명령형** ("추가했다" X → "추가" O). 마침표 생략
- **본문**: 제목 다음 빈 줄 후 작성. 줄당 72자 내 권장

## 2. Prefix 목록 (19종)

| Prefix | 의미 |
|---|---|
| `Feat` | 새 기능 추가 |
| `Update` | 정상 동작하나 보완이 필요한 경우 |
| `Fix` | 버그 수정 |
| `Correct` | 타입 변경·이름 변경 등 |
| `Docs` | 문서 수정 |
| `Comment` | 주석 추가/변경 |
| `Style` | 코드 포매팅·세미콜론 누락 등 코드 변경 없이 스타일 |
| `Refactor` | 코드 리팩토링 |
| `Test` | 테스트 코드 추가 |
| `Design` | 사용자 UI 디자인 변경 |
| `Rename` | 파일·폴더명 수정 또는 이동만 |
| `Remove` | 파일 삭제만 |
| `BREAKING CHANGE` | 큰 API 변경 (단독 사용 권장) |
| `HOTFIX` | 급한 치명적 버그 수정 (단독 사용 권장) |
| `Prevent` | 특정 기능 차단 |
| `Avoid` | 특정 현상 회피 |
| `Perf` | 성능 향상 |
| `Chore` | 빌드·패키지 매니저 수정 (예: `.gitignore` 등) |

## 3. 적용 규칙

### 3.1 Prefix 1~2개 (2개 초과 금지)

영향이 큰 순서로 `·` 또는 `,` 구분. 예: `Fix·Refactor(지침): ...`

> [!TIP]
> 1개로 충분하면 1개. **2개 초과는 변경이 너무 광범위** — atomic commit 분할 고려 ([`워크플로우.md §2`](워크플로우.md)).

### 3.2 BREAKING CHANGE · HOTFIX

- **단독 prefix** 사용 (다른 prefix와 묶지 않음)
- 본문 첫 줄에 영향 범위·복구 방법 명시 권장

### 3.3 본문 — 무엇·왜·어떻게

| 축 | 내용 |
|---|---|
| 무엇 | 변경된 객관적 사실 (파일·심볼·표·다이어그램 등) |
| 왜 | 변경 이유 (사용자 요청·버그 원인·정책 신설 등) |
| 어떻게 | 적용 방법·핵심 결정 (대안 대비 선택 이유 1~3개) |

본문이 한 줄로 자명하면 생략 가능. 작업 task 폴더가 있으면 본문에 anchor 권장 (예: `task: [meta/20260519_...]`).

## 4. 예시

### 4.1 단일 prefix

```
Docs(meta): 산출물 4종 신규 — 20260519_mermaid-스타일-정책-신설

mermaid flowchart 표준 정책 8요소 신설 task 산출물 4종:
- 요구사항.md: 8요소·수용 기준 5건
- 분석.md: 영향 범위·5 핵심 결정·자기 적용 시연 mermaid
- 계획.md: 7 Step·atomic 3 commit
- 이력 및 결과.md: 시계열 로그·완료 요약
```

### 4.2 복수 prefix (2개)

```
Fix·Docs(지침): §4.4 stateDiagram-v2 점선 전이 미지원 정정

stateDiagram-v2는 -.-> 점선 전이 미지원 (parser INVALID).
§4.4 매트릭스 ④ state 행 표기·예시 본문 정정 + NOTE 추가.
```

### 4.3 BREAKING CHANGE 단독

```
BREAKING CHANGE: tdc_led_pwm API 인자 순서 변경 (color, duty → duty, color)

기존 호출부 47곳 일괄 변경 완료. 외부 사용처 없음.
복구: git revert <SHA> 후 재호출부 변경 롤백 필요.
```

## 5. 기존 커밋과의 양립

본 컨벤션 적용 이전 commit (예: 소문자 `docs(meta): ...`·`fix(지침): ...` 등 conventional commits 스타일) 은 **그대로 보존**. 신규 commit부터 본 컨벤션 적용. 자동 lint 도구가 없으므로 표기 차이는 무해. 양식 통일이 필요해지면 별도 마이그레이션 task 검토.
