# 작업 규칙 체크리스트

**TL;DR**: 존댓말 사용, 문서는 GFM(.md), **모든 작업은 4단계 2게이트(인터뷰→계획→[게이트1]→검증리스트→구현→[게이트2]) + 산출물·이력 의무**, 코드는 게이트 1 통과 전 작성 금지, `claude_` 브랜치 + `--no-ff`, 작업 스코프(세션 cwd = 작업 대상 repo, 형제 독립 repo), **서브에이전트는 트리거 기반**(트리거어 시 위임, 그 외 판단 — 간단하면 직접·실익 시 위임; Sonnet·effort 미지정), AI 표시 금지.

> [!IMPORTANT]
> 모든 작업을 시작하기 전에 아래 규칙을 확인할 것.

---

## 1. 커뮤니케이션

- [ ] 사용자 대상 메시지는 **존댓말**로 작성 (반말 금지)
- [ ] 사용자 명령에 **조금이라도 모호함**이 있으면 작업 착수 전 무조건 질문 (이분→yes/no, 다항→선택지)

> [!NOTE]
> 상세: [`일반/커뮤니케이션 규칙.md`](일반/커뮤니케이션%20규칙.md) · [`일반/명령 해석 규칙.md`](일반/명령%20해석%20규칙.md)

---

## 2. 문서 작성

- [ ] 문서는 사용자가 다른 포멧을 명시하지 않는 한 **GFM Markdown(`.md`)** 으로 작성
- [ ] 문서는 유형별 폴더(`지침/`, `사용방법/`, `tasks/` 등) 아래 배치 (상세: [`문서/작성 규칙.md`](문서/작성%20규칙.md))
- [ ] 다이어그램은 **Mermaid**로 작성 (ASCII art 지양)
- [ ] 강조·경고는 **GitHub Alert 블록** (`> [!NOTE]`, `> [!WARNING]` 등) 활용
- [ ] 항목 식별자는 **알파벳 약어(`Q1`/`H1`/`R1`/`P1`) 금지** — 의미 한글 라벨 + `_번호` (`질문_1`/`가설_1`/`위험_1`/`요구사항_1`)
- [ ] '~하고 정리해' 요청 시, 작업 위치의 `docs/`에 `.md`로 정리

> [!NOTE]
> 상세: [`문서/작성 규칙.md`](문서/작성%20규칙.md)

## 3. 작업 진행 — 4단계 2게이트 프로세스 (모든 작업)

- [ ] 작업 지시 수신 시 `tasks/작업 목록.md`(루트 인덱스) → 해당 모듈 `tasks/<모듈>/작업 목록.md` 조회 → 기존 폴더 이어가기 또는 신규 생성 (사용자 확인)
- [ ] 산출물 작성: **① 인터뷰·`요구사항.md` → ② 분석·`계획.md` → [게이트 1] → ③ `검증리스트.md` → ④ 구현·자체 선테스트 → [게이트 2]**
- [ ] **① 인터뷰 먼저, 문서는 그 다음** — 모호점 0 + 수용 기준을 쓸 수 있을 때까지 질문하고 그 문답을 `요구사항.md` §인터뷰 기록에 남긴다 (이것이 요구사항 검증을 대신함)
- [ ] **② 계획서가 분석을 흡수** — 사실 주장엔 `파일:라인` 근거(추측 금지·미확인은 `(미확인)`), **실패 시나리오 ≥1 필수**, 전수 영향 조사는 **명칭·산출물 파일명·단계 번호·양식 링크 4축**
- [ ] **게이트 1** — 계획서 §실행 계획(Step `[필수]`/`[선택]`)·§핵심 결정(권장안+근거)에 은수님이 체크. 체크가 권장안과 달라도 **그대로 따른다**
- [ ] **③ 검증리스트는 게이트 1 직후 산출** — 체크된 Step에서 역산. **Claude 열/은수님 열 2열**, 은수님 열엔 써 봐야 아는 것만
- [ ] **④ 구현 후 자체 선테스트** — Claude 열을 스스로 채우고, 실패는 은수님께 넘기기 전에 고친다
- [ ] **게이트 2** — 은수님 검증리스트 체크. 미통과는 사유 분기: **구현 실수 → 수정 후 재체크** / **계획 결함 → `이슈보고서_N_<주제>.md` 발행 후 중단**
- [ ] `이력 및 결과.md`를 단계 ① 시작과 동시에 생성하고 단계 전이·게이트 통과·결정·이슈·**정정**마다 시계열 로그 갱신
- [ ] 작업 종료 시 `이력 및 결과.md` 완료 요약 추가 + 해당 모듈 `작업 목록.md` 상태 변경(완료) + `모듈 현황.md` 갱신
- [ ] 단순 수정(오타·설정값·자명한 한 줄)은 프로세스 면제. *"알아서 해"*는 **인터뷰 면제일 뿐 게이트 면제가 아니다**
- [ ] **검수 실행**("~ 검수해줘")은 본 프로세스가 아니라 프로젝트 `docs/검수/`의 리스트를 수행·결과 보고·상태 갱신 ([`일반/작업 진행 규칙.md`](일반/작업%20진행%20규칙.md) §5). 리스트 **작성·갱신**은 프로세스 적용 작업
- [ ] **오케스트레이션은 트리거 기반** — 은수님이 "오케스트레이션·여러 페르소나·서브에이전트들로·병렬로" 등 트리거어를 쓰면 dynamic workflow, 그 외엔 판단(간단하면 직접, 실익 명확할 때만 위임). 서브에이전트는 `model: sonnet`·**effort 미지정(세션 상속, Sonnet adaptive)**. 확정 스펙 대형 저술은 직접, **fan-out은 감시**(fire-and-forget 금지) — 폭주 방지. **2노드+ fan-out 시 `에이전트-로그/` 필수**([`서브에이전트/로그 구조.md`](서브에이전트/로그%20구조.md))
- [ ] **fan-out 경계는 게이트 1** — 게이트 1 **전(①②)은 read-only fan-out만**(조사·영향 범위·가설 병렬 검증), **쓰기 fan-out은 게이트 1 통과 후(④)에만**. 구현 fan-out 직후 자체 검증을 거쳐 검증리스트에 반영
- [ ] 신규 프로젝트 폴더 트리거(예: "기본 세팅 해줘") 수신 시 [`일반/프로젝트 초기 세팅.md`](일반/프로젝트%20초기%20세팅.md) 정형 절차 적용 (프로세스 면제)

> [!NOTE]
> 상세: [`일반/작업 진행 규칙.md`](일반/작업%20진행%20규칙.md) · [`서브에이전트/활용.md`](서브에이전트/활용.md) · [`서브에이전트/오케스트레이션.md`](서브에이전트/오케스트레이션.md) · [`일반/프로젝트 초기 세팅.md`](일반/프로젝트%20초기%20세팅.md)

## 4. 프로그래밍 작업 (단계 ④ 코드 작성 시 추가)

- [ ] 일반 작업 진행 규칙(§3)을 따른다 — 코드 작성은 단계 ④. 요구사항·계획 산출물과 **게이트 1 통과** 없이 코드 작성 금지
- [ ] 신규 심볼·모듈 분리 시 **`tdc_` 접두어 무조건 적용**, 기존 파일 리팩토링 시에도 손댄 심볼은 적용 우선
- [ ] 영속 참고성 지식(사용방법·시험방법 등)은 별도 wiki repo로 넘긴다 (은수님이 수동 반영 — rules는 wiki 운영에 관여 안 함)

## 5. 코드 분석·디버깅 (회귀 fix 시 필수)

- [ ] 함수 호출 경로 / 변수 사용처는 **추정 금지** — 반드시 `Grep` 으로 전수 확인
- [ ] root cause 가설은 **최소 3 개 수립 후 cross-check** (1 개로 만족 금지)
- [ ] **사용자가 직접 수정한 변경 (system-reminder)** 은 그 자체가 단서 — 의도 깊이 분석
- [ ] IRQ / 전원 / 클럭 / GPIO 등 **시스템 상태 변화 시점** 을 명시 추적
- [ ] fix 적용 전 self-check Q1~Q5 답변 (root cause 인가, 다른 가설 배제됐나, 회귀 위험은, 부작용은, 진단 요청이 우선 아닌가)
- [ ] 사용자가 "철저히" / "확실히" 표현 쓰면 검증 단계 강화

> [!NOTE]
> 상세: [`코딩/분석·디버깅 규칙.md`](코딩/분석·디버깅%20규칙.md) — 실제 회귀 사례 (Sound1 LED 잔상색 2026-04-23) 포함

## 6. Git

- [ ] 작업이 속한 **스코프(루트/프로젝트)의 repo**에 커밋 — 작업이 일어난 디렉토리가 아닌 **변경 파일 경로 기준**
- [ ] `claude_` 접두사 브랜치에서만 작업 (`main` 직접 커밋 금지)
- [ ] 파일 수정 전 feature 브랜치 생성 후 체크아웃
- [ ] 모든 병합은 `--no-ff`로 수행
- [ ] 커밋 완료 후, 병합 전 **사용자 확인** 필수
- [ ] Author / Committer: `김은수 <eunsu.kim@to-doc.com>` — AI 표시 절대 금지
- [ ] 커밋 메시지에 `Co-Authored-By` 등 AI 관련 라인 금지
- [ ] 머지·푸시 완료 후 `claude_develop` 복귀 — 모든 repo (루트 + 프로젝트) 동일, `claude_main` 체류 금지

> [!CAUTION]
> `main` 직접 커밋·푸시는 **절대 금지.** 릴리즈는 사용자 고유 권한.

## 7. 응답·컨텍스트 효율

- [ ] 파일 내용·툴 출력을 응답에 그대로 인용 금지 (Edit diff·1줄 요약)
- [ ] 인사·사전 설명("이제 ~하겠습니다")·사후 부연 금지 → 결과만
- [ ] 작업 종료 보고는 `변경/검증/다음` 3줄 (회고 명사구 한 줄 요약은 그 다음에 추가)
- [ ] `Read`는 `offset`/`limit` 활용 (큰 파일 전체 읽기 금지)
- [ ] 대량 탐색·로그 분석은 서브에이전트(Agent 도구) 위임
- [ ] **세션 종료·compact 직전·"요약해줘" 시 프로젝트 `docs/세션_인수인계/` 에 요약 작성** — 구간은 **직전 요약 문서가 커밋된 지점부터 git 으로** 잡는다(컨텍스트 아님). 상세: [`일반/세션 인수인계 규칙.md`](일반/세션%20인수인계%20규칙.md)
